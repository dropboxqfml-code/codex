Keithley 6517A · NI GPIB-USB 시험용 프로그램 v0.5.0

1. GitHub Release의 6517A-USB-GPIB-Trial-0.5.0-Windows-x64.zip을 새 쓰기 가능한 폴더에 모두 풉니다. 포함 runtime/app/tools 폴더를 분리하지 않습니다. Python·uv는 따로 설치하지 않습니다.
2. Verify-Bundle.cmd -> Test-Simulation.cmd -> Start-GUI.cmd를 실행합니다. Verify는 START -> CHECK 처리 파일 수 -> PASS/FAIL을 표시하고 diagnostics/bundle-verification-*.json을 저장합니다.
3. GUI는 SIMULATION·0 V로 시작합니다. 실제 시험은 SIM 연결을 종료하고 'NI 실장비 연결 시험 시작'에서 NI MAX와 같은 주소를 선택해 IDN -> 보호 OFF를 확인합니다. 기존 NI-488.2·NI-VISA 64-bit 설치를 사용하고 NI MAX test panel은 닫습니다.
4. '4. 시료·시험 설정 입력'에서 사용자 관리 저전압 방식을 선택합니다. 이 방식은 source 100 V 범위에서 절대 10 V 이하로 제한됩니다. 연결·정격·외부 보호는 사용자가 관리하고 그 확인을 직접 선택합니다.
5. '1 GΩ·1 V 시험값' 버튼을 누르면 요청 1 V, software trip 10 nA, 명목 기준저항 1 GΩ가 입력됩니다. 버튼은 REAL/SIM·운용 방식·확인 체크·resistive-limit 정책을 승인하지 않습니다. 전압·시간·trip을 검토하고 잔류 전압 확인과 resistive-limit ON/OFF 정책을 선택합니다.
6. 설정 적용 -> 연결 -> ARM -> 별도 START 순서로 실행합니다. ARM은 설정·readback·오류 큐·저장을 검증합니다. 설정 적용이나 연결만으로 출력 ON하지 않습니다. 미완성 설정은 초안으로 적용할 수 있고 ARM 준비 여부는 별도로 표시됩니다.
7. 사용자 관리 방식은 정격 문서·fixture ID·과거 lid 전이 기록을 필수로 요구하지 않습니다. 물리적 인터록 설치가 확인된 것으로 기록하지도 않습니다. 실제 장비 interlock 조회 0/실패·상태 오류는 두 방식 모두 출력 ON을 차단합니다.
8. 기존 검증 fixture 방식은 정격·승인 기록과 현재 연결의 OFF 상태 lid 0 -> 1 확인을 유지합니다. 고전압 설정은 이 방식을 사용하며 사용자 관리 방식의 10 V 제한을 올릴 수 없습니다.
9. 결과는 run 폴더의 readings.csv, summary.csv, raw_io.jsonl, run_status.json에 저장됩니다. STOP으로 중지할 수 있습니다. OUTPUT OFF와 방전 완료는 별개이며 잔류 전압은 UNVERIFIED입니다.
10. NI-VISA를 생략하는 @py 방식은 Enable-NI-Only.cmd의 선택 확장이 필요하고 NI-488.2 driver는 계속 필요합니다. 기존 NI-VISA 경로가 동작하면 그대로 사용합니다.

1 GΩ의 1 V -> 1 nA는 명목 계산값입니다. 실제 판독·누설·settling·기준저항 허용차와 구분합니다. Software current trip은 장비의 programmable compliance나 하드웨어 emergency stop이 아닙니다.
상세 절차: app/docs/reference_1gohm_trial.md 및 app/docs/user_hardware_trial.md
검증 범위: app/docs/validation.md 및 Release의 Windows-software-tests.xml/build-report.json
실장비 native resistance 모드는 차단되며 실제 current와 V/I 경로를 사용합니다.
