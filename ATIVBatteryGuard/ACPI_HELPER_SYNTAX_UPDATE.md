# 보조 본문 확장 구문과 중단 원인 — Acpi-routing-v4

## v3에서 관측한 사실

사용자 v3 요약의 DSDT는 본문 읽기 Complete·namespace Partial·설명자/메서드 각 1개·인수 3개·후보 본문 Parsed입니다. 후보에서 알려진 호출 표현식 1개·직접 Arg2 인수 0개·Return 1개/UnresolvedName을 관측했습니다. 보조 정의 1개를 검사했으나 해석 0개·미지원 1개였고 연결 상태는 Partial입니다. 원문 사용자 TXT는 저장소나 배포물에 포함하지 않습니다.

이는 메서드 실행 실패가 아니라 **제한된 정적 파서가 보조 본문을 해석하지 못한 결과**입니다. 직접 Arg2 인수 0개는 이름 객체·버퍼 등을 통한 입력 전달을 배제하지 않습니다. UnresolvedName 반환도 잘못된 응답이라는 뜻이 아닙니다. 미해결 참조 3개는 성공한 후보 본문의 관측이며 실패한 보조 본문의 중간 표식은 폐기됐습니다.

v3에는 정확한 중단 종류가 없어 미지원 opcode·피연산자·잘못된 인코딩·모호한 이름 중 무엇인지 구분할 수 없습니다. 특정 Acquire 구문에서 멈췄다거나 한계/순환 때문에 중단됐다고 추정하지 않습니다. 첫 SSDT의 미관측도 전체 펌웨어나 배터리 기능의 부재가 아닙니다.

## 이번 구현

수집 API·대상·상한은 유지하고, [고정 ACPICA 피연산자 정의](https://github.com/acpica/acpica/blob/e85aa3bebaae81ed1e6d163511ac7e1eafe732cf/source/include/acopcode.h#L42)에 근거한 표준 확장 구문을 정적으로 읽습니다. 원문 파일 SHA-256은 `72410dd629b6e483ad80eab513e244d951a79587784de6b842c6dddbeac1e7b2`입니다. 이 근거는 문법이며 현재 노트북에서 해당 opcode가 사용된다는 증거는 아닙니다.

- Acquire는 참조 뒤의 timeout을 **raw WORDDATA 2바이트**로 소비합니다. 그 바이트를 FF 반환·Ones·명명 호출로 해석하지 않습니다.
- Release·Signal·Reset·Wait·Sleep·Stall, CondRefOf, BCD 변환, Revision·Timer·Debug 참조, 일반 CreateField와 Fatal의 지원 범위 구문을 읽습니다. SimpleName/SuperName/Target과 raw 고정 길이 피연산자를 구분하고 문맥에 맞지 않거나 불완전하면 중단합니다.
- 실제 대기·동기화·타이머 읽기·변환·필드 생성·Fatal 처리는 실행하지 않습니다. 메서드·AML·OEM 평가 기능을 추가한 것이 아닙니다.
- Load/LoadTable/Unload와 메서드 안의 동적 namespace 정의는 해석 불가로 닫습니다. 정의가 바뀔 수 있는 동작을 추정해 연결하지 않습니다.
- 중단 원인은 고정 실패 종류와 공개 표준 구문 이름으로만 표시합니다. 알 수 없는 opcode는 고정된 Unrecognized 종류이며 raw hex·위치·이름·경로·주소·피연산자·예외 원문은 내보내지 않습니다.

해석 실패·미실시·한계 초과를 정상 미관측과 구분합니다. 지원하지 않는 본문에서 중간에 읽은 호출·FF·반환·확장 구문 표식은 모두 폐기합니다. 기존 후보 본문과 전체 관측 연결의 FF 표식 의미는 유지합니다.

별도로 **구문 해석을 완료한 보조 본문 N개**의 반환 문 수·반환 형태·확장 구문·상수 FF 반환 구문을 집계합니다. N=0이면 미확정입니다. 연결이 Partial이어도 완전히 해석한 본문의 구문 사실만 표시하며, 그 범위에서 false/미관측은 나머지 정의나 실제 FF 응답의 부재를 뜻하지 않습니다. 실제 FF가 보조 밖에서 생겼다거나 배터리 명령이 미지원이라고 결론내리지 않습니다.

## 유지하는 경계

두 Windows 읽기 API·고정 ACPI 공급자·DSDT 직접 읽기/첫 SSDT만 사용합니다. 테이블당 4MiB·목록 4096바이트·부모/작업자 각 10초, 구문 노드 10만·깊이 32·메서드 4096개·이름 객체 8192개와 보조 깊이 2/정의 8개/전체 호출 표현식 32개 제한을 유지합니다.

원본 테이블은 메모리에서만 읽고 지웁니다. 원본 저장/제출·네트워크·레지스트리 캐시·새 WMI/OEM 요청·삼성 DLL·실험 예약·장치/드라이버/포트/물리 메모리 접근·보안 변경·펌웨어 쓰기는 없습니다. 기존 실제 요청·응답 디코더·예약·일반 앱의 하드웨어 경로·제어 정책과 이전 ZIP은 그대로입니다. 실제 충전 제어는 Unsupported이며 완료된 1회 OEM 실험은 재실행하지 않습니다.

## 새 요약 확인

1. [프로그램 ZIP](../downloads/ATIVBatteryGuard-ACPI-HELPER-SYNTAX.zip) **하나만** 새 폴더에 모두 압축 해제합니다. 소스 ZIP은 실행에 필요하지 않습니다.
2. `ATIVBatteryGuard.AcpiRoutingCheck.exe`를 **일반 권한**으로 실행합니다.
3. **Acpi-routing-v4** 표시가 있는 새 요약만 전달합니다. 이전 v3 반복이나 관리자 비교는 필요하지 않으며 기존 TXT/DLL/원본 ACPI도 다시 제출하지 않습니다.

이전 도구에서 빠졌던 보조 본문 해석 범위와 중단 원인을 확인하는 수정본입니다. 새 v4 분석의 실제 결과는 아직 미관측이고 자동 검증은 합성 AML·가짜 읽기 콜백으로 수행합니다. 정확한 검증 수치는 [VALIDATION](VALIDATION.md)에 기록합니다.
