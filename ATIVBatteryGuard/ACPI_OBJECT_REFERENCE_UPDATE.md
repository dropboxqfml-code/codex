# 이름 정의와 참조 관계의 정적 요약 — Acpi-routing-v5

## v4 관측에 따른 이번 범위

v4에서 보조 본문 1개 해석·미지원 0·실패 None·Acquire/Release를 관측했습니다. 후보와 보조 본문에 남은 미확정 이름 참조 6회는 고유 객체 수가 아니며 실제 데이터 전달 실패도 아닙니다. [직전 결과·계획](ACPI_V4_RESULT_AND_NEXT_PLAN.md)에 따라, 이번에는 같은 테이블에서 관측한 이름 정의의 종류와 저장·반환 참조 관계를 분류합니다.

## 새로 보고하는 내용

- 후보와 완전히 구문 해석한 보조 본문의 이름 참조 횟수·분류된 횟수·관측 선언 종류를 보고합니다. Buffer·Integer·String·Package·Mutex·Event·OperationRegion·Field 등의 종류이며 실제 실행 중 객체의 값이나 형식 확인이 아닙니다.
- 직접 `Store(Arg2, Name)`의 대상과 직접 `Return(Name)`이 같은 관측 정의를 참조하는지, 해석된 보조 본문에도 그 정의 참조가 있는지 구문 관계만 요약합니다. 별칭·지역 변수·계산식의 값 전파, 실행 순서, 실제 데이터 동일성은 추론하지 않습니다.
- 보조 본문에서 Store 대상으로 쓰인 선언 종류와, 지원 가능한 Field가 연결된 OperationRegion의 선언된 주소 공간 종류만 보고합니다. SystemIO/SystemMemory/EmbeddedControl 등의 종류가 관측돼도 실제 영역을 읽거나 쓰지 않습니다.
- 이름·경로·필드명·원본 바이트·주소·오프셋·길이·OEM 값·안정적인 객체 식별자는 출력하지 않습니다. 임시 이름 해소 자료는 판독 중 메모리에서만 사용합니다.

## 보수적으로 남기는 부분

같은 경로의 중복 정의, 메서드/객체 충돌, Alias·External, 미분류 초기화식과 동적 생성의 가림은 임의로 첫/마지막 종류를 선택하지 않습니다. 완전히 해석한 후보/보조 본문의 Create*Field 이름이 정적 정의를 가릴 수 있으면 새 관계 분석에서 불확정으로 남깁니다. 미해석 보조 본문의 중간 사실도 집계하지 않습니다.

단순 FieldList의 NamedField·ReservedField·AccessField·ExtendedAccessField만 지원 범위로 둡니다. 필드의 encoded bit length는 바이트 패키지 경계와 구분해 읽고 값은 저장하거나 출력하지 않습니다. ConnectField·BankField·IndexField 등 복잡한 범위는 해석 완료로 승격하지 않습니다. FieldList 전체가 지원 범위 안에서 읽혔을 때만 그 필드들을 분류하며, 실패한 목록의 prefix를 typed Field 근거로 쓰지 않습니다. byte 단위 재검색도 하지 않습니다.

각 본문의 고유 이름 참조·역할 추적은 64개로 제한합니다. 반복 참조의 횟수와 고유 추적 이름 수는 다릅니다. 새 관계 상한을 넘으면 새 객체 보고서가 LimitExceeded/미확정이 되며 기존 후보 구문 해석·직접 비교/FF 표식을 폐기하거나 실제 미지원으로 바꾸지 않습니다.

관계의 true는 **같은 관측 정의를 참조하는 구문이 존재한다**는 뜻입니다. 실제 공유 버퍼의 값, 입력 그대로 반환, 호출의 실행 또는 보조 본문의 변경 효과를 증명하지 않습니다. 미분류·부분 방문·동적 가림에서는 관계 부재를 false로 단정하지 않습니다.

기존 연결 검사와 FF 표식 의미는 유지합니다. 새 선언 종류 분류가 이루어져도 전체 namespace의 Partial이나 실행 중 값·별칭·동일성은 해결된 것이 아닙니다. 실제 충전 제어는 계속 Unsupported이고 FF의 실제 의미도 미확정입니다.

## 실행·검증 경계

수집은 기존 두 Windows 읽기 API·고정 ACPI 공급자·DSDT 직접 읽기/첫 SSDT 그대로입니다. 레지스트리·추가 SSDT·장치/드라이버/포트/물리 메모리·영역 읽기/쓰기·OEM/삼성 DLL/AML 실행·값/분기 평가·실제 동기화/대기·실험 예약 접근·보안 변경·네트워크는 추가하지 않습니다. 원본 테이블을 저장하거나 제출하지 않습니다.

기존 4MiB/4096바이트/각 10초·구문 노드/깊이·메서드/객체·보조 깊이/정의/호출 표현식 상한과 일반 앱·OEM 요청/응답/예약/제어 정책을 유지합니다. 이전 배포 ZIP도 그대로 보존합니다.

1. [프로그램 ZIP](../downloads/ATIVBatteryGuard-ACPI-OBJECT-REFERENCES.zip) **하나만** 새 폴더에 모두 압축 해제합니다. 소스 ZIP은 실행에 필요하지 않습니다.
2. `ATIVBatteryGuard.AcpiRoutingCheck.exe`를 **일반 권한**으로 실행합니다.
3. **Acpi-routing-v5** 표시가 있는 새 요약만 전달합니다. v4 반복·관리자 비교·기존 TXT/DLL/원본 ACPI 재제출은 필요하지 않습니다.

새 v5 객체·참조 분석의 실제 노트북 결과는 아직 미관측입니다. 자동 검증 수치와 범위는 [VALIDATION](VALIDATION.md)에 기록합니다. 완료된 1회 OEM 실험을 재실행하거나 예약 표식을 삭제하지 않습니다.
