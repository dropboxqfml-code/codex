# ACPI 정적 점검 실기 결과 — Acpi-routing-v1

## 확인한 내용

사용자가 전달한 `Acpi-routing-v1` 실행 요약을 분석했습니다. 원문 TXT는 저장소와 배포물에 포함하지 않습니다. 아래는 전달된 텍스트의 관측이며 텍스트의 진위나 현재 장치 일치를 별도로 검증한 것은 아닙니다.

| 항목 | 전달된 결과 | 확인 범위 |
| --- | --- | --- |
| 테이블 목록 조회 | Complete | 목록의 크기 제한과 재조회 길이 검사를 통과한 경로입니다. 전체 AML 분석 완료를 뜻하지 않습니다. |
| DSDT 목록 항목 | 0 / 목록에서 미관측 | 이 구현은 목록에 없으면 GetSystemFirmwareTable을 호출하지 않습니다. DSDT 본문은 읽지 않았고 직접 조회의 성공/실패도 시험하지 않았습니다. |
| SSDT 목록 항목 | 4 | 같은 서명의 목록 항목 수입니다. 네 본문을 모두 읽었다는 뜻이 아닙니다. |
| 첫 SSDT 구문 탐색 | Partial | 첫 테이블의 서명·길이·체크섬 검사 후 제한된 구문 탐색에서 일부 해석으로 끝난 경로입니다. 권한 거부·시간 초과·InvalidTable 출력과 다릅니다. |
| 알려진 SABI 설명자 / 대응 메서드 | 0 / 0 | 해석한 범위에서 미관측입니다. 전체 테이블이나 전체 펌웨어에 정의가 없다는 결론은 아닙니다. |
| 후보 인수 / 본문 | 미확정 / NotObserved | 대응 후보를 확보하지 못해 본문을 분석하지 않았습니다. |
| Arg1·SizeOf(Arg2) 비교 / 상수 FF 반환 | 해석 불가 또는 미실시 | false나 정상/오류 응답의 의미로 바꾸지 않습니다. |

수집 API와 제한된 파서의 실기 경로는 위 범위에서 관측됐습니다. 실행 계정의 상승 여부는 이 요약에서 보고하지 않으므로 일반 권한 또는 관리자 권한이었다고 추가로 단정하지 않습니다. DSDT 조회 성공, 전체 SSDT 접근, 완전한 AML 해석은 확인되지 않았습니다.

## 무엇이 남았는가

이번 결과는 Windows 테이블 목록 조회가 완료됐지만 **분석에 필요한 현재 모델의 WMI 정의를 확보하지 못했다**는 결과입니다. DSDT가 목록에 없는 이유와 첫 SSDT의 Partial을 유발한 정확한 구문은 현재 출력에 없습니다. 이를 특정 펌웨어 결함·드라이버 누락·권한 문제로 추정하지 않습니다.

Microsoft의 [GetSystemFirmwareTable 공식 문서](https://github.com/MicrosoftDocs/sdk-api/blob/656e9656bfaef34dd29cd7ee9e1146aec17e924c/sdk-api-src/content/sysinfoapi/nf-sysinfoapi-getsystemfirmwaretable.md)는 같은 이름의 ACPI 테이블 중 첫 것만 반환한다고 명시합니다. SSDT 항목 수만큼 같은 조회를 반복해 나머지를 읽을 수 없습니다. 관리자 실행이나 동일 도구 재실행으로 이 API 제한이 해소된다는 근거도 없습니다.

따라서 먼저 개선할 대상은 **정적 정의를 얻는 범위**입니다. 알려진 DSDT ID를 직접 조회하면 성공할지, 다른 읽기 전용 Windows 자료가 필요한 범위를 실제로 제공하는지는 별도 근거가 필요합니다. 현재 결과만으로 새 수집 경로를 구현해 재실행을 요구하지 않습니다. 원본 AML을 갖고 있지 않으므로 이번 결과만으로 특정 미지원 opcode를 골라 파서를 고치거나 byte 재검색을 추가할 수도 없습니다.

기존 WMI 실험의 ResponseReceived·ValidFrame·첫 payload FF 관측은 그대로입니다. 이번 요약은 그 응답의 발생 위치나 배터리 의미를 좁힐 새 정의를 제공하지 못했습니다. FF를 보호 OFF/ON·하드웨어 미지원으로 변환하거나 요청 바이트·명령을 바꾸지 않습니다.

## 이번 반영과 다음 경계

- 이번에는 실기 관측과 수집 한계를 문서에 반영했습니다. 실행 코드·기존 OEM 요청·디코더·예약·제어 정책은 변경하지 않았습니다.
- 현재 ACPI 점검은 완료된 기록으로 전환합니다. 같은 도구 재실행, 관리자 비교, 기존 TXT/DLL/EXE 또는 원본 ACPI의 재제출은 요청하지 않습니다. 새 EXE도 배포하지 않습니다.
- 다음 구현에 앞서 현재 모델의 정적 정의를 얻을 수 있는 Windows 읽기 전용 자료의 제공 범위·문서 근거·개인정보 경계를 검토해야 합니다. 같은 서명 반복 조회나 다른 모델 정의 대입은 대안이 아닙니다.
- AML/OEM/삼성 DLL 실행, 물리 메모리·포트·드라이버 접근, 드라이버/서비스/보안 변경이나 펌웨어 쓰기로 수집 한계를 우회하지 않습니다. 완료된 1회 실험은 재실행하지 않고 원래 예약 표식을 유지합니다.

실제 충전 제어는 계속 Unsupported입니다. 문서만 변경했으므로 빌드·테스트를 다시 실행하지 않았습니다. 353개 테스트·Python 22개·7개 프로젝트 빌드 경고/오류 0개는 직전 코드의 검증 기록입니다. 기존 다운로드 ZIP과 그 ZIP에 결합된 소스·체크섬은 변경하지 않습니다.
