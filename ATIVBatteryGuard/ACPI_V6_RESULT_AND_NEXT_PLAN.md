# v6 실기 결과와 다음 개발 계획 — 2026-11-05 한국 시간

## 의도한 결과의 확인

**v6의 목표인 후보 Field의 선언 공간·21바이트 대비 폭·직접 Store 원천·보조 Store와의 Region 선언 관계 요약은 달성됐습니다.** 사용자 출력의 수정판은 Acpi-routing-v6이며 DSDT 직접 읽기 Complete, 후보 Parsed, 보조 해석 1개·미지원 0·실패 None입니다. 원문 TXT는 저장소·배포물에 넣지 않습니다.

| 항목 | 실제 출력 | 확인한 범위 |
| --- | --- | --- |
| 직접 Arg2 저장 대상 Field | SystemMemory / Matches21ByteFrame | 관측한 대상 Field의 선언 공간이 메모리이며 폭은 고정21바이트와 일치합니다. 실제 메모리를 읽거나 쓴 결과가 아닙니다. |
| 직접 반환 대상 Field | SystemMemory / Matches21ByteFrame | 반환 Field에도 같은 선언 형태를 관측했습니다. 입력 저장/반환이 같은 관측 Field 정의를 참조한다는 v5 관계도 유지됐습니다. |
| 후보 Field Store 구문 | 총2회 / 직접 Arg2 원천1회 / Arg2, Literal | 나머지1회는 literal 원천입니다. 실행 횟수나 서로 다른 Field2개라는 뜻은 아닙니다. |
| 해석된 보조 본문의 Field Store | SystemIo | I/O 공간으로 선언된 Field를 대상으로 하는 Store 구문입니다. 실제 포트 접근·SMI·펌웨어 처리 성공을 확인하지 않았습니다. |
| 후보 Arg2 Field / 보조 Store Field의 Region 관계 | DifferentObservedDefinitions | 관측된 Region 정의가 서로 다릅니다. 실제 물리 주소의 동일·겹침·분리는 판단하지 않습니다. |
| 후보 반환 Field / 보조 Store Field의 Region 관계 | DifferentObservedDefinitions | 반환 역할에서도 같은 선언 비교 결과입니다. 새로운 하드웨어 실행을 뜻하지 않습니다. |

이 결과는 메모리 공간의 프레임 저장/반환 Field와 보조 본문의 I/O 공간 Store 선언을 구분한 정적 근거입니다. 기존 서비스 wsabi의21바이트 전송 형식과 선언 폭이 부합하지만, 정확한 배치·변환·입력 보존·실제 경로 실행·모델별 배터리 명령의 의미까지 입증하지 않습니다.

## Partial과 남은 미확정

전체 namespace·기존 연결·객체·Field 통로 보고서는 Partial입니다. 전체 정의 탐색의 Partial은 새 Field 보고서에도 반영되므로, 선언 폭과 Region 관계가 관측됐어도 전체 상태가 Complete로 바뀌지 않는 것이 현재 설계에 맞습니다. 추가 literal Store 대상의 Region까지 완전히 해소됐는지는 현재 출력에 없습니다.

기존 연결 검사의 미확정 이름 참조6회와 후보/보조의 선언 종류3/3회+3/3회 분류는 별도 지표입니다. 고유 객체6개나 새로운 실행 오류를 뜻하지 않습니다. 후보·보조의 구문 실패 None은 유지됐습니다.

이번 literal 원천은 정수만 뜻하지 않습니다. 구현은 직접 정수·문자열·Buffer·Package 구문을 Literal로 합칩니다. 그 값·대상·분기·순서를 보고하지 않았으므로 이를 FF 초기화, 상태 초기화, 명령 selector 또는 I/O 트리거라고 단정할 수 없습니다. Arg0/Arg1이 Field Store의 직접 원천으로 보고되지 않았다는 사실도 그 인수가 모든 구문에서 무시된다는 뜻은 아닙니다.

보조 본문의 Acquire/Release, 명시적 Return0, scoped literal FF 반환 미관측은 기존 지원 구문 범위의 관측입니다. 실제 동기화 성공·효과 없음·모든 FF 생성 부재를 뜻하지 않습니다. 첫 SSDT는 Partial·후보 미관측·새 분석 NotInspected이며, 전체 SSDT나 기능 부재 판단으로 확대하지 않습니다.

기존1회 WMI 실험의 ValidFrame/응답 첫 payload FF와 이번 정적 선언은 서로 다른 증거입니다. FF가 어디서 만들어졌는지, 현재 모델의 명령이 무엇인지, 배터리 보호 ON/OFF는 아직 미확정이며 실제 충전 제어는 **Unsupported**입니다.

## 다음 개발의 우선순위와 수용 조건

1. **추가 literal Store의 대상 역할을 구분합니다.** 후보의 비Arg2 Store 대상이 입력/반환 Field와 같은 관측 정의인지, 보조 Store Field 또는 같은 Region 선언을 참조하는지 분류합니다. 주소 공간과 고정 프레임 대비 폭 범주만 표시하고, 미분류·다중 대상·가림을 단일 관계로 줄이지 않습니다. literal은 직접 구문 종류로만 세분화하고 원문 상수·주소·이름·버퍼를 내보내지 않습니다.
2. **필요한 경우 제한된 구문 위치 관계를 추가합니다.** 후보의 Store·알려진 보조 호출·Return이 같은 직접 구문 목록에서 앞뒤에 나타나는지만 비교합니다. 분기·반복·중첩 표현식·미해석 본문이 섞이면 별도 미확정으로 닫습니다. 소스에 나타난 순서를 실제 실행 순서·값 전파·초기화 또는 트리거 효과로 설명하지 않습니다. 보조 인수 값을 원래 WMI 입력으로 대입하지 않습니다.
3. **저장된 Windows/SABI 분석과 대조합니다.** 위 역할 정보를 기존 서비스 wsabi21바이트 계약, 실제1회 응답 검증 범위와 구분해 정리합니다. FF 생성 위치를 입증하지 못하면 원인을 미확정으로 유지합니다. Linux 명령이나 다른 모델의 ABI를 그대로 적용하거나 요청을 자동 수정하지 않습니다.
4. **같은 안전 경계 안에서 구현·검증합니다.** 기존 두 읽기 API·DSDT/첫 SSDT·크기/노드/시간/관계 상한을 유지합니다. 동일/다른 선언·복수/미해소·literal 여러 종류·분기/중첩의 거짓 순서·실패한 본문 폐기·개인정보 회귀를 합성 입력으로 검사합니다. OEM/AML/DLL 실행·실제 영역 접근·드라이버/서비스/보안/레지스트리 변경·실험 예약 접근은 추가하지 않습니다.

이번 결과 확인에는 v6 반복 실행·관리자 비교·기존 TXT/DLL/EXE·원본 ACPI 재제출이 필요하지 않습니다. 새 구현이 위 빈 정보를 실제로 추가할 때에만 새 요약의 필요성을 판단합니다. 선언 요약만으로 모델별 명령 의미가 풀리지 않으면 그 한계를 명시하고 같은 진단을 반복하지 않습니다.
