# v7 실기 결과와 다음 개발 계획 — 2026-11-05 한국 시간

## 의도한 결과의 확인

**v7의 직접 목표인 Literal Store 원천 종류·대상 선언 관계·직접 구문 배치 요약은 달성됐습니다.** 사용자 출력은 Acpi-routing-v7이며 DSDT 본문 읽기 Complete, 후보 Parsed, 보조 해석1개·미지원0·실패 None입니다. 원문 TXT는 저장소·배포물에 넣지 않습니다.

| 항목 | 실제 출력 | 확인한 범위 |
| --- | --- | --- |
| Literal Store | 1회 / Integer | 직접 정수 원천 구문입니다. 정수 값 자체는 보고되지 않았습니다. |
| Literal 대상 Field | SystemMemory / Matches21ByteFrame | 관측된 단일 Field의 선언 폭이 고정21바이트와 일치합니다. |
| Literal / Arg2 저장 대상 관계 | Field·Region 모두 SameObservedDefinition | 같은 관측 Field 및 Region 정의를 참조합니다. |
| Literal / 직접 반환 대상 관계 | Field·Region 모두 SameObservedDefinition | 반환도 같은 관측 선언을 참조합니다. |
| Literal / 보조 Store 대상 관계 | Field·Region 모두 DifferentObservedDefinitions | 관측 정의가 서로 다릅니다. 실제 물리 주소의 분리·겹침은 판단하지 않습니다. |
| 직접 구문 목록 | SingleDirectList | 각 역할 하나씩이 같은 직접 구문 목록에 나타났고 앞뒤 관계를 분류했습니다. |

실제 앞뒤 출력은 Arg2/literal=AfterInSameList, Arg2/보조 호출=BeforeInSameList, literal/보조 호출=BeforeInSameList, 보조 호출/Return=BeforeInSameList입니다. 이를 합친 **소스 배치**는 다음과 같습니다.

```text
정수 Literal Store → Arg2 Store → 보조 호출 → 같은 Field를 참조하는 Return
```

이는 소스에 적힌 구문 관계입니다. 실제 초기화·형 변환·덮어쓰기·입력 보존·실행 경로·SMI 성공·FF 생성 원인을 확인한 결과가 아닙니다. 특히 정수 Store가 먼저 있다는 사실만으로 기존 WMI 응답의 FF가 그 정수에서 생겼다고 결론내릴 수 없습니다.

## 유지된 관측과 남은 미확정

입력/반환 Field의 SystemMemory·21바이트 선언 폭과 보조 Store의 SystemIo는 v6 관측과 일치합니다. 후보/보조의 이름 참조3/3회+3/3회 분류, Acquire/Release, 후보 호출1회·직접 Arg2 인수0개·Return1회, 보조 명시적 Return0개도 유지됐습니다. 참조·호출 수는 정적 발생 횟수이며 고유 객체 수나 실행 횟수가 아닙니다.

전체 namespace와 기존 연결·객체·Field·Store 역할 보고서는 Partial입니다. 전체 정의 탐색이 불완전한 상태를 반영하면서 범위가 명확한 관측은 보존하는 설계입니다. 후보·보조의 구문 실패 None과 모순되지 않으며 기존 연결 검사의 미확정 이름 참조6회도 별도 보수적 지표입니다. 첫 SSDT는 Partial·후보 미관측·새 분석 NotInspected이고 전체 SSDT나 기능 부재를 판단할 근거가 아닙니다.

기존 승인1회 실험은 실제 WMI 응답과 구조 검증 ValidFrame, 첫 payload 바이트FF를 확인했습니다. 전체 payload·명령 echo·현재 모델의 명령 의미는 확인되지 않았습니다. v7 정적 구조가 추가돼도 FF를 보호 OFF/ON·명령 미지원·하드웨어 기능 부재로 변환하지 않습니다. 실제 충전 제어는 **Unsupported**입니다.

## 다음 개발의 우선순위

전달 구조의 핵심 빈 부분은 이번에 구체화됐습니다. 다음 우선순위는 같은 wrapper 구문을 더 세분화하는 새 진단보다 **현재 모델·BIOS의 Windows 배터리 명령·응답 계약을 입증하는 출처 확보**입니다.

1. **확인된 전달 규약과 미확정 명령을 분리해 정리합니다.** [서비스 wsabi 분석](SABI_LINK_RESULT_AND_WMI_REVIEW.md)의21바이트 WMI 프레임/payload16, [Sabi3 x64 ABI](SABI3_NATIVE_ABI_REVIEW.md)의 호출자11바이트·별도 장치 전송, 실제1회 응답, 이번 ACPI 선언/배치를 구분합니다. 같은 크기나 함수 이름만으로 서로 다른 전송의 의미를 합치지 않습니다.
2. **배터리 호출자가 명령을 선택하는 정적 근거를 우선 추적합니다.** 보유 분석 기록과 적합한 공개 정적 자료에서 실제 배터리 조회/설정 문맥의 명령·selector·입력 준비·응답 분기를 찾습니다. 서비스 wsabi 자체는 호출자가 준 명령을 포장하는 일반 중계 DLL입니다. 저장된 SamsungConfigurationMonitor의 확인 문맥은 팬·정숙 모드이므로 배터리 계약으로 재사용하지 않습니다. 동일 파일·동일 분석의 반복을 새 근거로 세지 않습니다.
3. **적용 모델·BIOS·전송 경로와 응답 의미를 함께 확인합니다.** 현재 저장 기록에는 이 모델의 Windows 배터리 명령 매핑이 없습니다. [기존 조사](WMI_MODEL_CONTRACT_FOLLOWUP.md)의 Linux/hotkeys 후보나 신형 Galaxy Book 명령을 그대로 대입하지 않습니다. FF를 구분하는 응답 조건, 명령 echo·길이·상태 코드의 규약이 있는지 출처를 확인하고, 없는 항목은 미확정으로 표시합니다.
4. **근거가 확보된 부분부터 순수 코드 명세와 검증으로 고정합니다.** 적용 조건·조회 명령·입력·응답 수락 조건·보호 상태와 오류의 구분을 재현 가능한 명세로 정리한 뒤, 장치 호출 없는 합성 입력으로 검증합니다. 실제 응답에서 관측하지 않은 전체 payload나 echo를 복원했다고 주장하지 않습니다. 추가 계약 근거 없이 기존 요청/디코더 의미를 바꾸거나 비어 있는 제어 어댑터·반복 진단 UI를 만들지 않습니다.

다음 단계의 완료 기준은 출처가 있는 모델/전송/명령/입출력/상태 의미의 대조표와 실제 구현 가능한 항목·부족한 항목의 구분입니다. 출처에 기반한 의미가 확보되기 전에는 실제 제어를 활성화하지 않습니다. 근거를 찾지 못해도 장치 기능 부재로 결론내리지 않고 조사 범위와 남은 빈 부분을 기록합니다.

## 안전 경계와 이번 작업 범위

이번에는 결과 분석과 후속 계획만 기록했습니다. 실행 코드·배포 ZIP·요청/응답/예약/제어 정책은 변경하지 않았고 빌드/테스트도 반복하지 않았습니다. 429개 테스트·Python27개·빌드 경고/오류0개는 v7 배포 당시의 검증 기록입니다.

v7 반복 실행·관리자 비교·기존 TXT/DLL/EXE·원본 ACPI 재제출은 필요하지 않습니다. 새 OEM 시험·삼성 DLL 초기화/실행·AML 평가·Field/포트/물리 메모리 접근·0x66 쓰기·드라이버/서비스/보안 변경은 계획에 포함하지 않습니다. 완료된1회 실험과 예약 표식을 유지합니다. 이번 계획은 추가 하드웨어 실험 승인을 요청하거나 가정하지 않습니다.
