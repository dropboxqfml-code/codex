# Amor3 공식 원본 확보·오프라인 검사 추가 — 2026-11-07 한국 시간

**현재 모델 계열의 제조사 목록에서 아직 받지 않았던 SamsungSystemConfiguration for Amor3 1.0.0.7을 확보했습니다.** 새 원본의 관측 크기·해시를 개발용 오프라인 검사기에 추가했고 Python 테스트 88개가 통과했습니다. 선택한 Monitor 호출은 팬 제어로 연결됐으며 새 보호 상태 조회 계약은 아직 확보하지 못했습니다. Windows 앱과 실제 제어는 기존 Unsupported 상태입니다.

[외부·간접 후보 검토](EXTERNAL_INDIRECT_CONTRACT_BOUNDARIES.md) 이후 같은 펌웨어 후보를 반복 분류하는 대신 제조사 배포 목록과 미검토 구성요소를 확인했습니다. 원본 프로그램·DLL·설치 스크립트는 실행하거나 로드하지 않았습니다.

## 새 원본의 모델 연결과 실제 바이트

저장된 정확한 Model940X3G 목록 6개를 대조했습니다. WB 목록 두 개가 같은 패키지를 가리키며, 이를 독립 패키지 두 개로 세지 않았습니다. 공개 목록의 locator에서 정상 제조사 리다이렉트를 따라 [BASW-A0141A02.ZIP](https://downloadcenter.samsung.com/content/SW/201405/20140527113613244/BASW-A0141A02.ZIP)을 HTTP200으로 받았습니다. 이 링크는 분석 출처이며 사용자 프로그램 교체판이 아닙니다.

ZIP은 3,771,257바이트, SHA-256 `1681f1a5a10b3d758ce1b925efbe7ec4360d3ed33c7d3fb189a5bf69fff699c2`입니다. 파일 10개·비압축 합계 7,585,067바이트가 목록과 일치하며 CRC·안전 경로·중복/대소문자 충돌·심볼릭 링크 검사를 통과했습니다. 프록시·TLS 검증을 유지했고 환경 설정을 바꾸지 않았습니다. 사용자 시리얼·DMI·장치 식별자는 조회하거나 전송하지 않았습니다.

| 새 원본의 주요 구성 | 바이트 | 확인한 범위 |
| --- | ---: | --- |
| SamsungConfigurationMonitor.exe | 1,779,008 | 파일 버전 1.0.0.7, 동적 WSABI 준비와 선택한 팬 조회·설정 호출 |
| SamsungSystemConfiguration.exe | 23,872 | 서비스·Monitor 프로세스 실행 경로 |
| IdleStateFanCtrl.exe | 96,064 | Monitor 창에 전달하는 idle 관련 메시지 경로 |
| WSABI.dll | 22,920 | 과거 서비스 DLL 기록의 정확한 SHA-256과 일치 |

WSABI SHA-256은 `564b640d62db2a4e4b56c6331e0e526bad2ac1fcf438a41a9e5241551f457b6e`입니다. 새 제조사 원본과 과거 서비스 DLL 기록의 바이트 신원을 연결한 것입니다. 과거 Monitor 전체의 해시가 보존되지 않았으므로 Monitor까지 같은 파일이었다고 단정하지 않습니다. 배포 목록 연결은 현재 Windows10 설치·실제 DLL 선택·충전 지원의 증명이 아닙니다.

## 새 원본과 미검토 구성요소의 역할

Monitor의 선택한 loader는 실행파일 디렉터리를 구해 WSABI 경로를 구성한 뒤 함수 주소를 얻습니다. 실제 로드 경로나 현재 장치 준비 상태를 관측한 것은 아닙니다. 선택한 query·setter와 debug 문맥은 팬 제어로 연결됐으며 입력의 `80`을 배터리 80%로 해석하지 않습니다. 준비 함수의 API 결과·BIOS mode 처리도 보호 상태 검증이 아닙니다.

새 SSC 설치 설정은 Win8 분기에서 서비스·idle 작업 등록을 선언합니다. 서비스→Monitor 프로세스, idle worker→Monitor 창 메시지의 원본 연결을 확인했지만 어떤 설치·서비스·작업도 실행하지 않았습니다.

기존에 확보한 같은 모델 계열 패키지에서도 새 구성요소를 분류했습니다. W7의 `SettingsChargingOnlyMode.exe`는 실제 USB 태블릿 탐지·SABI 호출과 연결된 USB 충전 전용 기능이며 노트북 충전 상한 조회가 아닙니다. 후속 2.2.0.21의 추가 OSD 실행 파일·INI는 event handler의 알림 소비자로 연결됐습니다. 정확한 OS 버전 선택 조건과 현재 노트북의 선택은 미확인입니다. 해당 이름과 목록의 Win10 문맥만으로 전체 패키지의 현재 호환성이나 보호 기능을 판정하지 않습니다.

현재 2.2.0.18의 언어 리소스에 있는 80% BLE 도움말도 모델별 지원 허용 목록과 구분했습니다. 검토한 MSI component 선택 조건은 OS 분기이며 custom action에는 설치 상태 조건도 있습니다. 모델 정보 소비자는 메타데이터 초기화로 연결됐습니다. 보호 모드 처리자·모델별 허용 목록·신뢰할 상태 재조회는 이 범위에서 확보하지 못했습니다.

## 개발 코드와 검증

[오프라인 원본 검사기](scripts/inspect_command_research_artifact.py)에 고정 종류 `ssconfig-amor3`를 추가했습니다. ZIP 해석 전에 위 크기·SHA-256을 검사하고, 일치한 뒤 기존의 bounded ZIP 구조·CRC·경로 검사를 수행합니다. CLI에서 기대 크기·해시를 덮어쓸 수 없습니다. 이 도구는 다운로드·추출·OEM 실행 기능을 추가하지 않습니다.

일치 결과는 `ObservedSourcePayloadMatched`입니다. `sourcePayloadIntegrityVerified`는 관측 바이트와 ZIP의 일치만 뜻하며 Authenticode·현재 모델 호환성·배터리 계약·메서드 실행·하드웨어 쓰기 권한은 모두 false입니다. 실제 새 ZIP에서도 파일 10개·합계 7,585,067과 이 닫힌 권한 상태를 확인했습니다.

[테스트](scripts/test_command_research_artifact.py)에 pin 누락/불일치의 ZIP 해석 전 거부, 관측 일치 후에도 인증·권한 거부, CRC·잘림·위험 경로 거부의 신규 3개를 추가했습니다. 전체 Python **88개 통과**, 독립 코드 검토도 통과했습니다. C#/WPF 코드·실행 파일·기존 ZIP은 바꾸지 않아 C# 빌드·테스트는 재실행하지 않았습니다. C# 437개·빌드 경고/오류 0개는 이전 `5d77df5` 검증 기록입니다.

[검사 기록](reports/amor3-oem-source-audit.json)에 카탈로그 연결·새 원본·정적 선택 범위·실제 도구 결과를 저장했습니다. 원본 삼성 바이너리·카탈로그 원문·전체 디스어셈블리는 비공개 캐시에 보존하고 사용자 배포물에 포함하지 않습니다. 하드웨어/OEM 호출·기존 단발 예약 접근·드라이버/서비스/보안·펌웨어 변경은 없습니다.

다음 채택 조건은 계속 현재 모델의 보호 상태 생산자→고정 조회→실패 보존·새 요청 대응→Windows 반환의 연결입니다. 새 패키지를 받았다는 사실이나 팬·USB·OSD 기능을 충전 제한 구현으로 세지 않습니다. 기존 프로그램을 그대로 사용하며 추가 노트북 시험·동일 자료 재제출은 필요하지 않습니다.
