# 충전기 응답 조회 후보와 상태 스냅샷 — 2026-11-07 한국 시간

**후속:** [고정 조회의 생산자·소비자 대조](FIXED_QUERY_CONSUMER_REVIEW.md)에서 현재 OEM 전력 조회와 ACPI 대체 조회를 연결했습니다. 전류·전압 표시 경로와 오류 폐기 분기를 분리했으며 새 보호 조회 계약은 확보하지 못했습니다. 아래는 이전 분석 시점의 기록입니다.

**설정 echo와 별도로 버스에서 받은 두 바이트를 반환하는 EC 코드 후보를 찾았습니다.** 조건부 해석에서는 충전기 옵션·전류·전압 레지스터 계열을 읽는 표현이 가능합니다. 하지만 범용 버스 조회이며, 현재 모델의 고정 보호 조회 API나 안전한 Windows 호출 계약으로 확정한 것은 아닙니다. 실제 충전 제어는 미구현·Unsupported입니다.

[오류·신선도 경계 분석](EC_FRESHNESS_AND_ERROR_PATHS.md)의 후속입니다. 기존 P05ACJ 원본을 데이터로만 읽었으며 EC의 Intel 8051 호환 ISA·하위 48KiB 공통/상위 16KiB bank 모델을 전제로 합니다. 제조사 칩 정의·현재 이미지·실제 버스 관측은 아닙니다.

## 서로 구분한 세 가지 값

| 값의 출처 | 이번에 확인한 소스 연결 | 보호 적용을 판단할 때의 한계 |
| --- | --- | --- |
| 내부 보호 모드·임계값 | 앞서 확인한 80/75 정책의 저장값 | 충전기 쓰기의 성공이나 실제 충전 중단을 입증하지 않음 |
| 활동 상태 스냅샷 | 정책의 마지막 동작 비트→갱신 표시→상태 생산자→EC 페이지 읽기 | 여러 조건이 같은 값을 만들며 보호 모드의 직접 복사본이 아님 |
| 별도 버스 읽기 결과 | 내부 분배표→bank stub→word 읽기→수신값 반환 | 범용 조회·오류 축약·기존 중계 신선도 문제가 남음 |

## 정책이 상태 페이지에 반영되는 경로

충전 억제·복원 요청 이후의 소프트웨어 동작 비트가 갱신 표시와 갱신 처리자를 거쳐 상태 스냅샷에 영향을 주는 경로를 연결했습니다. 상태 생산자는 AC·배터리 조건과 활동 비트를 조합하고, 기존 EC 페이지 읽기 처리자는 그 스냅샷을 반환할 수 있습니다.

이는 보호 모드와 80/75 임계값의 직접 미러가 아닙니다. 앞선 충전기 쓰기 결과를 확인하지 않고 활동 비트를 갱신하며, 보호 외 조건도 같은 상태값을 만들 수 있습니다. 따라서 ‘충전 중 아님’이나 해당 스냅샷의 값으로 보호 설정 활성·적용 성공을 역산하지 않습니다. 확인된 오류 보존 Windows callback 네 개는 다른 고정 필드를 선택하므로, 이 연결만으로 새로운 Windows 보호 조회가 생긴 것도 아닙니다.

저장된 ACPI의 일반 배터리 상태 처리에서도 일부 활동값을 AC 전원 조건으로 정규화하는 코드를 별도로 대조했습니다. 이 비교를 근거로 host offset과 EC 내부 주소를 숫자만으로 대응시키지는 않았습니다. 겉보기 모드 주소 후보 하나는 실제 소비자가 코드 메모리를 읽는 별도 포인터로 판명했습니다. 선택한 생산자·복사 후보에서 직접 모드 미러는 찾지 못했지만, 모든 동적 복사·별칭·외부 코드를 배제한 것은 아닙니다.

## 별도 버스 응답을 읽는 후보

새 후보는 호출자가 지정한 장치와 레지스터를 내부 word 읽기 helper로 전달합니다. helper는 버스 상태가 성공인 경우에만 수신 word를 목적지에 복사합니다. 본문은 그 값의 낮은 바이트와 높은 바이트를 반환 메시지에 넣습니다. 분배표의 항목·bank 전환·입력 소비·결과 순서를 원본 바이트로 검산했습니다.

이 경로는 내부 희망 모드나 마지막 동작 기록을 다시 돌려주는 것과는 다른 **버스 응답 생산자**입니다. 기존 충전기 쓰기 경로에서 본 레지스터 계열을 선택할 수 있다는 소스상 후보이며, 실제 충전기 종류·현재 지원·전기적 충전 중단을 검증한 것은 아닙니다. 모든 버스 장치와 레지스터 읽기가 부작용 없다고 선언하지 않습니다. 구체적인 조회 요청이나 실행 코드는 만들지 않았습니다.

버스 오류가 나면 실패 원인 대신 모든 비트가 1인 word를 반환합니다. 정상 수신값이 모두 1인 경우와 같은 모양이며, 별도 상세 상태·요청 순번은 없습니다. 또한 EC 본문의 두 바이트 생산과 외부 중계의 전체 복사는 별개입니다. **이 본문을 찾았다고 기존 Windows 중계의 송신 오류 가림·오래된 응답 가능성이 해결되지는 않습니다.** 오류 보존 고정 조회 경로로 이 결과가 전달되는 연결은 아직 확보하지 못했습니다.

기존 고정 충전기 읽기도 대조했습니다. 확인한 직접 호출은 제조사 ID 조회였고, 해당 경로는 버스 상태를 검사하지 않은 채 scratch 값을 소비합니다. 옵션 상태의 독립 read-back이나 현재 부품 식별 근거로 승격하지 않습니다.
