# 미분류 영역과 EC 업데이트 경로의 연결 — 2026-11-07 한국 시간

**후속:** [조건부 EC 충전 보호 코드 후보](EC_CHARGE_PROTECTION_CANDIDATE.md)에서 명령어·bank 가정을 명시한 내부 해석으로 SBS 잔량과80/75 충전 요청 사슬을 연결했습니다. 아래의 당시 미복구 기록은 그 이전 단계입니다. 현재 장치·Windows 제어 계약과 실제 설정 재조회는 여전히 미검증입니다.

**보유 P05ACJ의 96KiB 분석 대상이 EC 업데이트 영역에 포함된다는 정적 근거를 확보했습니다.** 제조사 업데이터의 파일 선택, 하위 도구의 EC 분류 선택, 펌웨어의 같은 분류 생산, 실제 영역 복사·버전 비교를 연결했습니다.

이번 전체 목표인 **충전 보호 설정의 처리자·응답·신뢰할 재조회는 확보하지 못했습니다.** EC 업데이트 자료의 위치를 확인한 것과 충전 제한 명령을 구현할 수 있다는 것은 별개입니다. 실제 보호 조회·충전 제어는 미구현·Unsupported입니다.

## 실제로 연결한 경로

모든 분석은 이미 보유한 원본을 데이터로 읽어 수행했습니다. 새 제조사 파일을 다운로드하거나 실행하지 않았습니다.

| 근거 | 확인한 내용 |
| --- | --- |
| P05 제조사 wrapper | 단일 ROM/CAP 파일을 선택하고 전체 파일을 읽기 전용으로 매핑합니다. 저장된 기본 옵션과 전체 CAP 파일명을 하위 AMI 도구에 전달하는 경계를 복원했습니다. |
| 하위 AMI 도구 | 실제 등록된 EC 블록 옵션의 선택 callback이 동적 block-info의 type 3을 선택합니다. 인접한 다른 callback과 혼동하지 않았습니다. |
| 펌웨어 SMIFlash | 16바이트 헤더 뒤에 1,280개의 9바이트 block-info 레코드를 만듭니다. 그중 31개의 4KiB 페이지를 type 3으로 분류합니다. |
| 별도 ROM-layout 표 | 24바이트 레코드 16개 중 한 항목이 위 31페이지와 정확히 같은 124KiB 영역을 가리킵니다. 그 안에 분석 대상 96KiB가 들어 있습니다. |
| AMITSE의 소비 경로 | 같은 124KiB 영역을 버퍼에 복사하고, 현재 버전 getter의 6+3바이트를 저장된 `P05ACJ062`와 직접 비교합니다. 조건에 따라 갱신 경로를 호출합니다. |

9바이트 block-info와 24바이트 ROM-layout은 **별도의 생산자**입니다. 한 표를 다른 표로 변환한다고 가정하지 않았습니다. 두 표의 실제 영역 범위가 같고, 하위 도구가 해당 분류를 EC로 명명·선택한다는 점을 대조했습니다. 영역 표의 모든 주소·파일 오프셋 쌍도 같은 관계를 가지므로 임의의 주소 배치를 추측해 연결하지 않았습니다.

이는 분석한 소스의 업데이트 인터페이스에서 EC 영역을 분류하는 근거입니다. 실제 노트북에서 해당 모듈이 로드되거나 같은 block-info가 반환된 것을 관측하지 않았으며, 현재 설치 이미지와의 바이트 동일성도 검증하지 않았습니다.

## 갱신 코드를 보호 조회로 사용할 수 없는 이유

선택된 소비 함수는 원본 영역을 복사한 뒤 앞부분의 일부 바이트를 복사 버퍼 안의 다른 위치로 옮기고, 선택 범위를 조각으로 비교·처리합니다. I/O 쓰기와 갱신 동작을 포함합니다. **원본 96KiB 전체가 그대로 기록되는 이미지라고 가정하거나, 이 함수를 읽기 전용 조회로 실행하지 않습니다.**

6+3바이트 getter도 구성 요소의 버전 비교용입니다. 이 반환값은 배터리 보호 상태나 충전 상한이 아닙니다. 현재 EC 종류·칩·명령어 아키텍처·메모리 bank와 코드 주소 기준은 확정하지 못했습니다. ENE/SMSC 이름이나 8051과 비슷한 바이트 모양만으로 내부 명령어를 해석하지 않았습니다.

업데이트 도구의 다른 헤더 검사 함수는 실제 EC 옵션에 등록된 callback이 아니었습니다. 따라서 특정 헤더 문자열이 CAP에 없다는 사실만으로 EC 갱신 실패·건너뜀을 판정하지 않습니다. 전체 입력 버퍼의 모든 후속 변환·OEM 옵션·실행 시 선택도 미확정입니다.

## 검증과 개발 판단

원본 해시 확인 후 wrapper의 선택 경로 834행·22개 단언, 하위 도구의 선택 경로 364행과 별도 검토 261행, 일반 I/O 드라이버의 선택 경로 559행, AMITSE의 선택 함수 7개·368행을 보존했습니다. ROM-layout과 block-info 생산 코드도 별도로 대조했습니다. 통합 검산에서는 실제 EC 옵션 등록·type 3 선택, 16바이트 헤더·9바이트 레코드, 31페이지 범위, 원본 영역·버전 비교의 일치를 확인했습니다. 숫자는 선택한 코드 범위이며 전체 프로그램 분석 완료를 뜻하지 않습니다.

요약은 [정적 검사 기록](reports/ec-update-region-audit.json)에 저장했습니다. 원본·전체 디스어셈블리·포트·물리 주소·업데이트 실행 명령·비공개 패키지 정보는 공개하지 않습니다. 기존 프로그램과 개발 소스 ZIP도 그대로 보존합니다.

**현재 보유 자료와 확인된 안전 조건으로는 실제 충전 제어 구현이 막혀 있습니다.** 이번에는 영역의 용도까지 연결했지만, 배터리 보호 처리자와 Windows에서 사용할 검증된 조회·변경 계약을 얻지 못했습니다. 내부 분석을 더 진행하려면 컨트롤러·명령어 및 주소 기준을 먼저 입증해야 합니다. 그 근거 없이 추측한 EC 명령이나 펌웨어 갱신을 대체 수단으로 쓰지 않습니다. 이는 하드웨어의 영구적인 기능 부재 판정은 아닙니다.

앱·테스트 코드는 변경하지 않았고 새 EXE·소스 ZIP을 만들지 않았습니다. 이번에는 정적 검증만 수행해 빌드·단위 테스트를 반복하지 않았습니다. C# 437개 / Python 85개 통과와 전체 빌드 경고·오류 0개는 코드 커밋 `5d77df5`의 이전 검증 기록입니다. 추가 노트북 시험·자료 제출·OEM 재호출·예약 접근·드라이버/서비스/보안 변경·BIOS 갱신은 필요하지 않습니다.
