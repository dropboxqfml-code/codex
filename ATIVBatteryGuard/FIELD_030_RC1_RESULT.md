# 0.3.0 RC1 실사용 결과와 RC2 수정

2026-11-25 한국 시간. [사용자 JSON 원본과 평가](reports/field-030-rc1/assessment.json)를 보존했습니다. 첨부 파일은 검증 데이터로 읽었으며 실행 지시로 취급하지 않았습니다.

## 받은 결과

파일 검사는 실행 전후 모두 통과했고 소스 지문은 배포한 RC1과 일치합니다. 두 파일의 GUI 결과도 같습니다. 다만 GUI 자동 검사는 `RECENT_SELECTION_NOT_PRESERVED`로 실패했습니다. 바인딩 오류는 0개, 하드웨어 쓰기는 false이며, 네이티브 배터리/WMI 검사는 앞선 실패로 `not-run`입니다. 자동 검사를 통과한 것으로 처리하지 않습니다.

사용자는 안내 1·2·3을 수행했고 큰 이상이 없었다고 보고했습니다. 현재 사용 배율의 글씨와 테두리, 창 크기 변경 후 마우스 클릭이 정상이며 Defender에서 특이사항이 없었다고 확인했습니다. 이는 사용자 수동 보고로 기록합니다. 정확한 배율 숫자, IME 조합 중 처리, 취소·동시 수정 충돌, 장시간 사용까지 확인했다고 확대하지 않습니다.

검증 도구는 Defender와 수동 사용을 검사하지 않으므로 원본 JSON의 `DefenderScanExecuted`와 `ManualUserFlowsConfirmed`는 false인 채로 보존합니다. 별도 수동 보고를 이유로 원본 필드를 바꾸지 않습니다. 검사 시각·정의 버전·탐지 수 등의 기계 증거는 제공되지 않았습니다.

## 원인과 수정

최근 목록의 ItemsSource가 바뀌면 WPF의 양방향 SelectedItem 바인딩이 일시적으로 null을 전달할 수 있습니다. 이 값이 다시 찾아 둔 선택을 지웠습니다. 같은 콜백을 재현한 새 회귀는 수정 전 1251통과·1실패였고, 목록 갱신 중 선택 setter의 재진입을 막은 뒤 1252통과·0실패입니다. 명시적 선택 해제와 실제로 목록에서 사라진 항목의 선택 해제도 확인했습니다.

RC2의 앱/helper 구성은 RC1과 비교해 MainViewModel의 이 수정과 ApplicationRelease 버전만 다릅니다. XAML·충전 제어·설정/기록 형식은 유지합니다. 실제 Windows의 `RECENT_SELECTION_NOT_PRESERVED` 검사는 삭제하거나 완화하지 않았습니다. Linux 테스트는 Windows 통과 증거가 아니므로 새 후보에서 자동 검사를 다시 받아야 합니다.

## 첫 실행 경고

배포본에는 Authenticode 서명이 없고 사용자가 첫 실행 경고를 관찰했습니다. 미서명 게시자·다운로드 출처·SmartScreen 평판 경고와 관련될 수 있으나, 이 JSON으로 정확한 경고 종류를 특정하지는 못합니다. Defender 수동 검사에서 특이사항이 없었다는 보고와 별개의 결과입니다.

정식 배포 준비 항목으로 배포자 코드 서명 인증서와 타임스탬프 적용, 서명 후 파일 재검증을 유지합니다. 서명이 있어도 Windows 평판 경고가 즉시 모두 없어짐을 보장하지 않습니다. 이번 수정은 경고를 제거하거나 서명을 완료한 변경이 아닙니다. 보호 기능 해제·예외 추가·우회는 요청하지 않습니다.

## 다음 확인

새 RC2 검증 키트를 별도 로컬 폴더에 풀어 `검증시작.cmd`만 다시 실행하고 새 validation/gui JSON을 전달하면 됩니다. 이미 확인한 수동 흐름과 충전 시험을 반복할 필요는 없습니다. RC2의 Windows 자동 검사와 남은 실사용·서명 배포 근거가 확보되기 전에는 최종 0.3.0 완료로 표시하지 않습니다.
