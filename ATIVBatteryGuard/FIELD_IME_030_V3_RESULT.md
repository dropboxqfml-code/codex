## 해석과 한계

실제 조합 중 입력과 저장·재열기의 성공은 기록됐습니다. 단순히 조합 표시를 잘못 이해했거나 입력기 증거가 없어서 실패한 결과는 아닙니다. 그러나 IME 전체를 통과로 표시할 수는 없습니다.

오류 위치상 이전의 닫기 차단 결정·자동 취소 검사는 지나갔고, 이후 합쳐진 조건 검사에서 실패했습니다. 이 조건은 창 표시, 초안 수정 상태, ViewModel 문구 일치, TextBox 문구 일치, 기존 저장값 보존을 함께 검사합니다. 현재 JSON에는 각각의 결과나 전후 상태가 없으므로 어느 항목이 달랐는지, 실제 끝 글자 유실인지, 입력 문구/검사 타이밍 불일치인지 단정할 수 없습니다. 원문을 다시 제출할 필요는 없습니다.

코드 검토에서 확인 대화상자 진입 전후 메모 ViewModel이 Text/IsReadOnly 알림을 보내는 점과 닫기 시점의 미확정 UI 입력 전달을 다음 조사 대상으로 기록합니다. 이를 이번 사용자 기기 오류의 확정 원인으로 표시하지 않습니다.

## 다음 개발

닫기 취소 검사의 각 조건을 텍스트 원문 없이 불리언으로 분리하고, 조합 중 UI 입력이 확인 가드에 들어가기 전에 ViewModel로 전달되는 경로를 확인합니다. 원인이 확인되면 최소 범위로 수정하고 닫기 취소 사례에 집중합니다. 같은 v3로 반복 시험하거나 이미 통과한 빠른/20분/충전 시험을 다시 요청하지 않습니다.

이번에는 JSON 일관성/실패 조건과 소스 오류 위치를 확인하고 원본·현황만 갱신했습니다. 새 빌드/회귀·클라우드 Windows 실행은 하지 않았습니다. 기존1267회귀 성공을 이번 Windows 실패의 반증으로 사용하지 않습니다. 서명·보안/최종 출시는 여전히 미완료입니다.
