# 고정 조회의 생산자·소비자 대조 — 2026-11-07 한국 시간

**후속:** [외부·간접 조회 후보의 경계](EXTERNAL_INDIRECT_CONTRACT_BOUNDARIES.md)에서 공통 GUID 구간·게시 간접 호출·별도 EC 반환 경로를 대조했습니다. 새 보호 조회 계약은 확보하지 못했으며, 반환값이 있는 쓰기 경로를 제외하고 미연결 공급자를 보류했습니다. 아래는 이전 분석 시점의 기록입니다.

**이번 추적에서는 새 보호 상태 조회 계약을 확보하지 못했습니다.** 대신 현재 삼성 프로그램의 전력 데이터 조회와 ACPI 대체 배터리 조회를 생산자·소비자까지 연결했습니다. 전자는 전류·전압을 이용하는 전력 표시 경로이며, 후자는 하위 읽기 오류를 버리는 분기가 있어 보호 상태 조회로 채택하지 않습니다. 실제 제어는 미구현·Unsupported입니다.

[충전기 응답 조회 후보와 상태 스냅샷](CHARGER_READBACK_AND_PROJECTION.md)의 후속입니다. 기존 원본을 데이터로만 읽었습니다. EC 해석은 Intel 8051 호환 ISA·하위 48KiB 공통/상위 16KiB bank 모델을 전제로 하며 현재 장치·칩·실제 실행을 검증한 것은 아닙니다.

## 현재 OEM 전력 조회의 실제 소비자

Settings 2.2.0.18의 `CommandMNPowerManagement.dll`에서 `CmdGetCurrentPowerData`의 RTTI·vtable·import 호출을 연결했습니다. 이 명령은 `ModuleSABI.dll`의 `EcoMode_GetPowerData`를 호출하고 반환 버퍼를 숫자 계산·표시에 사용합니다. 고정 펌웨어 callback이 읽는 두 word는 기존 배터리 polling의 전류·전압 캐시로 연결됩니다. 나머지 한 바이트는 별도 생산 코드가 있으며 충전기 응답으로 식별하지 않았습니다.

이는 이름에 Power가 있다는 추측이 아니라 호출과 값의 생산 경로를 대조한 결과입니다. 그러나 보호 모드·80/75 임계값·충전기 옵션 상태의 조회는 아닙니다. 캐시를 읽는다는 사실도 최신 버스 응답임을 보장하지 않습니다.

`GetEcomodeSupport`의 선택 경로는 소프트웨어 gate 서명을 확인합니다. 물리적 배터리 기능 지원 판정으로 사용하지 않습니다. 전력 조회 wrapper는 API 결과의 낮은 바이트를 검사하고, 상위 숫자 소비자는 조회 반환값을 확인하지 않은 채 Windows 전원 상태와 반환 버퍼를 계산에 사용합니다. 현재 앱에 이 성공 판정 방식을 도입하지 않습니다. 실제 DLL 선택·호출 성공·화면 오류는 관측하지 않았습니다.

## ACPI 대체 조회와 별도 제공자

저장된 `_BST`의 `ECON==0` 분기에서 byte/word wrapper→공유 분배기→등록된 `SecEcDxe` callback→EC 상태 페이지 읽기를 연결했습니다. 기존 레거시 SABI의 비슷한 selector 번호를 같은 명령으로 취급하지 않았습니다. 상태 조회가 앞서 찾은 활동 스냅샷을 읽는 연결도 실제 helper의 주소 계산으로 확인했습니다.

하위 한 바이트 helper는 대기 실패를 보존하지만, 상위 byte callback은 그 반환을 검사하지 않고 초기값 또는 결과 byte를 복사한 뒤 정상 반환합니다. word callback은 같은 임시 byte를 사용해 두 번 읽고 양쪽 반환을 검사하지 않습니다. 두 번째 읽기 전에 임시값을 다시 지우지 않아, 소스상 실패 시 0이나 이전 byte가 결과에 섞일 수 있습니다. 두 읽기는 하나의 원자적 word 조회도 아닙니다.

따라서 상세 실패·일관된 최신 값을 보장하는 보호 조회 계약으로 채택하지 않습니다. 입력 범위나 출력 숫자의 유효 범위를 검사하는 파서만으로 이미 버린 오류 정보를 복구할 수는 없습니다. 이는 저장된 대체 분기의 소스 사실이며, 현재 노트북이 이 분기를 사용하거나 잘못된 배터리 값을 표시했다는 관측이 아닙니다. 현재 앱의 동작 중인 배터리 표시는 변경하지 않았습니다.

## 버스 읽기와 후보 판정

성공한 버스 word를 상태 캐시에 복사하는 다른 경로도 확인했습니다. 선택한 장치·채널은 앞서 충전 정책에서 확인한 대상과 다르고 부품 역할은 미확정입니다. 실패 시 기존 캐시를 유지하는 경로도 있습니다. 이를 충전기 옵션의 독립 read-back으로 연결하지 않습니다.

| 후보 | 이번 판정과 남은 조건 |
| --- | --- |
| 현재 OEM 전력 데이터 조회 | 생산자·숫자 소비자 연결 완료. 보호 조회 후보에서 분리 |
| ACPI 대체 byte/word 조회 | 하위 오류 폐기·분리된 byte 읽기 확인. 신뢰할 보호 조회로 채택하지 않음 |
| 다른 대상의 수신 word 캐시 | 복사 경로는 확인. 충전기 옵션 대상·의미 연결은 미확정 |
| 기존 범용 모드·버스 읽기 | 후보 보존. 고정 인터페이스·안전성·신선도 조건은 여전히 미확정 |

직접 word 읽기 호출자 대조는 실제 복사 대상 소스 범위로 한정했습니다. 계산된 호출·별칭·외부 코드 전체를 닫거나 하드웨어의 보호 기능 부재를 판정한 것은 아닙니다. 새 명령이나 기존 시험의 재실행 근거도 아닙니다.
