# A 권한 조건을 반영한 추가 1회 시험 — 승인 검토안

**결과 수신·추가1회 소모:** 승인된Access1은 [저장후보0·정리Complete](ACCESS1_STORED_ZERO_RESULT_AND_NEXT.md)를보고했습니다. 이미소모한추가예산은유지하며여기서새실행권한을부여하지않습니다. 실제설정변경·임계값조회·새전환시험은아직승인/구현되지않았습니다. 아래는승인·배포이력입니다.


**후속 승인·구현:** 사용자가 **“알겠어 진행해.”**로 위 추가 예산을 명시 승인했습니다. [Access1 구현·제공 안내](FIXED_READ_ACCESS1_IMPLEMENTATION.md)에 새 전용 예약과 수동 관리자 실행·START·최대1method·709현재회귀/전체빌드0/0·ZIP을 기록했습니다. 기존 소모분은 유지하고 handshake/재시도/설정쓰기/B는 승인하지 않았습니다. 아래는 승인 전 검토안 이력입니다.

**작성 당시 상태: 추가 시험 미승인·미구현·미배포.** 기존 A는 [준비 권한 거부](FIXED_READ_A_ACCESS_DENIED_RESULT.md)로 종료됐고 예약을 소모했습니다. 이 제안은 실패도 소모하기로 한 기존 한도를 그대로 보존한 채, 사용자가 명시적으로 승인할 경우에만 허용할 **추가 준비1회**입니다. 기존 시험을 다른 이름으로 계속하는 자동 재시도나 예산 복구가 아닙니다.

TXT에는 토큰 상태가 없으나 사용자가 추가 답변으로 **일반 실행**이었다고 확인했습니다. 이 답변을 실제 TokenElevation 측정으로 바꾸지는 않습니다. 저장된 상승 토큰의 준비 성공 조건을 적용하는 추가 시험안이며 현재 권한 거부의 내부 원인이나 추가 시험 성공이 확정됐다는 뜻은 아닙니다.

## 승인 대상으로 제시하는 정확한 범위

| 항목 | 추가 시험의 고정 범위 |
| --- | --- |
| 장치·동작 | 기존 940X3G/930X3G · P05ACJ.128.140819.dg profile와 동일한 저장 byte·읽기 분기만 사용 |
| 토큰 | 별도 도구를 같은 Windows 계정에서 사용자가 수동 관리자 실행. 자동 UAC/runas·상시 관리자 앱·다른 계정/암호 입력·권한 조정 없음. 현재 TokenElevation을 먼저 읽고 Elevated가 아니거나 불명이면 START/예약/WMI0 |
| 시작 | 도구의 명시적 START 후 추가 시험의 영속 예약을 먼저 소모. 그 뒤 준비 실패도 반복하지 않음 |
| 추가 한도 | 준비 최대1회, CallSabiFunction 최대1회, 고정 byte sample0~1회. 현재 로그의 method0을 무한 재시험 근거로 쓰지 않음 |
| 추가 동작 금지 | handshake·삼성DLL/OEM 초기화·재시도·다른 명령/주소·설정/임계값 쓰기·B fallback 각각0 |
| 새 예약 | 승인 뒤에만 `FixedModeReadA-Access1.attempt`라는 **승인된 추가1회 전용** marker를 구현. 기존 A/과거 Query65 예약은 조회·초기화·삭제·재사용하지 않음. 다른 실패에 세 번째 marker를 자동 생성하지 않음 |
| 검사·수명 | 기존 exact metadata/활성 단일 대상·fixed SDK binding·응답 거부·whole-exchange owner·2초획득/10초표시/actualclose join·CallCanceled/pending 유지 |
| 새 결과 | 토큰·준비 세부 단계·오류/정리 범주·응답 판정·저장 후보0/1만 기록. raw frame/비교값·경로·계정/고유 ID·예외 원문 출력0 |

기존 정상 초기화·inline 관련 처리·같은 비재진입 P05 stream/모델 대응의 명시적 전제는 그대로입니다. Elevated는 접근 성공·gate 열림·현재 reader 실행·현재 보호 설정·충전 제어 안전성을 새로 증명하지 않습니다. 통신 buffer와 EC mailbox 게시/응답 교환은 있으며 저장 byte를 바꾸는 경로는 선택하지 않습니다.

현재 저장된 일반/상승 비교와 Locator-v2 Ready 근거를 재사용합니다. 사용자에게 같은 권한 비교·무호출 진단·DLL/EXE를 다시 제출하도록 요구하지 않습니다. 추가 시험이 승인돼도 실제 설정 변경·충전 제어는 범위 밖이며 Unsupported를 유지합니다.

승인 후에는 위 추가1회 제한과 새 marker만 연결하고, 토큰 사전 차단·예약 경합·준비 실패 소모·정제 세부 오류·기존 수명/응답 회귀와 전체 빌드를 검증한 별도 ZIP을 제공합니다. 삼성 원본·firmware·과거 실험 EXE는 포함하지 않습니다. 실제 실행은 제공 후 사용자가 직접 이 추가 시험을 시작할 때만 가능합니다.

[AGENTS.md](AGENTS.md)의 **“커널/펌웨어 제어 코드 추가 작업은 사용자에게 별도의 명시적 승인을 받은 뒤 안전성과 모델 적합성이 입증된 범위에서만 진행한다.”**와 기존 A의 준비 실패 소모 합의 때문에 추가 호출용 구현에는 별도 승인이 필요합니다. 현재의 일반 개발 요청을 추가 단발 예산 승인으로 해석하지 않습니다.
