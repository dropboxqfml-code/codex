현재 상태(2026-11-25): [사용자 결과](FIELD_IME_030_V3_RESULT.md)에서 실제 입력기 이벤트와 저장·재열기는 확인했지만 닫기 취소 후 복합 조건이 IME_CANCEL_DRAFT_MISMATCH로 실패했습니다. 정확한 불일치 항목은 미확인입니다. 새 모드 미실행 상태는 아래 개발 시점의 이력이며, 같은 v3 시험을 반복하지 않고 조건 세분화와 닫기 입력 전달부터 조사합니다.

## 동작과 증거

도구가 한글 문자열을 TextBox에 주입하지 않습니다. 사용자가 ‘한글 입력 확인’을 실제 입력기로 입력하고 메모 저장을 누르면 제품의 실제 저장소·메모 재열기 결과를 비교합니다. 이후 ‘종료 취소 확인’으로 바꾸고 X를 누르면 제품의 TryPrepareToClose와 실제 MessageBox 자동 취소를 거쳐 표시/초안/기존 저장값을 비교합니다. 실패 시에도 임시 검사 창을 보호하기 위해 닫기를 막으며, 가드가 닫기를 차단한 결정까지 확인해야 해당 검사를 통과시킵니다.

제품의 실제 MainWindow/TextBox/메모 명령/저장소를 사용합니다. 위쪽 안내·명시적인 사용자 확인 체크·결과 저장 버튼은 검사 창에서만 구성하며 제품 XAML/프로그램은 수정하지 않습니다. WPF composition start/update 이벤트와 이벤트 당시 한국어 입력 언어/IME On 관찰을 단계별 횟수·불리언으로 기록합니다. 이벤트의 Text/CompositionText나 키 입력을 수집·저장하지 않습니다. 네이티브 전역 입력 주입·키보드 후킹·입력 언어 변경·클립보드 자동 입력은 없습니다.

포커스 이동이 조합을 먼저 완료할 수 있으므로 마우스 down/닫기 시점 active=false만으로 입력기 실패라 하지 않습니다. 양 단계의 실제 이벤트/한국어 IME On 관찰, 저장·재열기/초안 보존, 사용자 확인을 함께 요구합니다. 직접 확인 항목을 자동 선택하지 않습니다. 붙여넣기·확정 문자열만으로 조합 검사 통과를 만들지 않습니다. 이벤트가 관찰되지 않는 입력기에서는 저장·취소가 정상이어도 증거 불충분으로 기록합니다.

## 결과와 한계

새 startup JSON의 Mode는 guided-ime이며 본 결과는 ime-*.json입니다. 임시 폴더/합성 예제만 사용하고 프로그램6파일을 검사 전후 확인합니다. 종료 때 임시 자료를 정리하고 원본 결과를 덮어쓰지 않습니다. 표시된 안내 문구는 알려진 예제이며 보고서에는 사용자 입력 내용·경로·장치 정보가 없습니다. 파일 확인/정리/오류/중단 실패는 통과가 아닙니다. 실제 보안 검사·서명·최종 출시는 false입니다.

이 모드는 사용자 참여 검사입니다. OS 입력기와 물리적 클릭을 무인 재현했다고 주장하지 않습니다. 이전 v2의 자동 검사 통과를 새 v3 모드의 실행 근거로 사용하지 않습니다. v3 실제 Windows IME 실행은 이후 위 수신 결과에서 부분 통과/닫기 검사 실패로 확인됐습니다. 독립 프로세스 경쟁·모든 입력기·모든 DPI/언어 조합의 전체 인증도 아닙니다.

판정/개인정보 회귀4개를 추가해 전체1267통과·실패/skip0, portable/별도 net48 WPF 도구 빌드는 경고/오류0입니다. 서명 배포 판정은 별도로13회귀가 통과했습니다. 인증서/실제 서명과 Windows 보안 검사·최종 배포 파일 재검증은 아직 수행하지 않았습니다.

startup/ime JSON을 받았으며 다음은 닫기 취소 불일치의 상세 진단과 원인 조사입니다. 이전 빠른/20분/충전 시험은 반복하지 않습니다.
