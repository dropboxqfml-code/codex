# 수동 제어 베타3 — 작은 창과 높은 배율에서의 배치 보정

**후속 배포:** 베타 표기를 제거하고 쉬운 상태 문구와 관찰 그래프를 추가한 [0.2.0](RELEASE_020.md)을 제공합니다. 아래는 이전 배포 기록이며 ZIP 바이트는 보존합니다.

2026-11-10 한국 시간. 버전은 **0.2.0-beta.3**입니다. 사용자가 보고한 3200×1800·250% 환경의 큰 창과 화면 밖 제목 표시줄 문제를 수정했습니다. 글자 크기와 접힌 기능은 사용자가 적절하다고 확인한 상태로 유지합니다.

## 이번 노트북에서 추가로 확인된 결과

사용자는 **Windows 10의 ‘다시 시작’으로 재부팅한 뒤 충전 제한이 유지됐음**을 확인했습니다. 이 사용자 실기 보고를 기존 80% 충전 억제·해제 후 충전 재개·GUI 해제 결과와 함께 보존합니다. 같은 충전·재부팅 시험이나 진단·TXT·삼성 DLL·EXE의 재제출은 필요하지 않습니다. 앱에 부팅 자동 적용 기능을 추가하지 않았습니다.

사용자는 글자 크기가 적절하고 접힌 기능이 잘 동작한다고도 확인했습니다. 이번 변경은 외곽 창 크기와 배치, 로컬 작업 안내에 집중합니다.

## 창 크기와 배치

| 항목 | 이전 | 베타3 |
| --- | ---: | ---: |
| 기본 가로 | 1120 | 750 |
| 기본 세로 | 850 | 565 |
| 최소 가로·세로 | 760×600 | 480×320, 작업 영역이 작으면 더 축소 |
| 글자·내용 배율 | 기존 값 | 동일 |

크기는 WPF 논리 단위입니다. 3200×1800 화면을250%로 사용하면 작업 표시줄을 제외하기 전의 공간도 약1280×720이므로, 이전 창 높이850은 화면을 넘을 수 있었습니다. 새 기본 크기는 약2/3이며 내용은 기존 세로 스크롤로 봅니다. 이전 버전의 최대화 기억값이 있어도 작은 일반 창으로 시작하고, 필요하면 사용자가 최대화할 수 있습니다.

첫 창은 마우스가 있는 모니터의 작업 영역에 배치하고 이후에는 현재 창이 있는 모니터를 사용합니다. 모니터의 음수 좌표와 작업 표시줄 영역을 보존한 실제 픽셀 좌표로 외곽 창을 맞춥니다. DPI는 크기에만 적용하고 화면 전체 좌표를 다시 확대하지 않습니다. 제목 표시줄과 최소화·최대화·닫기는 Windows 기본 모양을 유지합니다.

배율·화면·작업 표시줄 영역 변경, 최소화/최대화 뒤 복원과 다른 모니터로 이동한 경우에도 일반 창을 작업 영역 안으로 보정합니다. 사용자가 끌거나 크기를 바꾸는 중에는 보정을 미루고, 같은 모니터 안의 정상 수동 배치는 유지합니다. `MaxWidth/MaxHeight`로 최대화를 막거나 전체 화면을 축소하는 변환은 추가하지 않았습니다.

## 오류·취소·저장 안내

저장 폴더 열기의 성공·실패를 제어·관찰 저장 안내 옆에 표시합니다. 폴더를 열지 못해도 기존 저장 완료·파일명·보고서·중복 저장 방지 상태를 바꾸지 않습니다. 폴더 열기 실패는 오류 색으로 구분하고, 열기에 성공해도 TXT가 새로 저장됐다고 표시하지 않습니다.

취소 안내는 UAC와 helper 실행 확인을 모두 포함합니다. 일반 장치 진단, 상세 진단과 삼성 파일 진단의 오류는 각각 해당 진단의 실패로 설명합니다. 독립적인 수동 제어가 차단된 것처럼 표시하지 않습니다. 실제 종료 미확인에서는 기존 추가 동작 차단·강제 종료/재실행 금지 안내가 우선하며 장치 요청을 반복하지 않습니다.

새 ZIP 하나를 새 폴더에 모두 풀고 **ATIVBatteryGuard.exe를 일반 권한으로 실행**합니다. 이번 사용자 확인은 창 크기와 제목 표시줄·창 버튼의 접근성만 보면 됩니다. 필요할 때 기존 보호 상태 확인·켜기·해제·저장 버튼을 사용하며 과거 단발 시험을 다시 실행하지 않습니다.

새26그룹(창 배치16·로컬 안내10)을 포함해 **1119개 통과·실패0·건너뜀0**, Portable과 전체 net48 WPF Release 빌드는 각각 경고·오류0개입니다. 250% 크기 변환·음수 모니터 좌표·작업 표시줄·작은 영역·경계 입력·복원용 배치와 폴더 오류·저장 결과 유지·취소·진단 실패의 제어 상태 보존을 검증합니다.
