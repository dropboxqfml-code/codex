# 수동 GUI 베타의 보호 해제 실행 결과

2026-11-10 한국 시간. 구현 기준은 `973f651f7e3273e862b549b73f299f9b2f75e4ff`입니다. 사용자가 제출한 새 수동 제어 TXT를 데이터로 분석했습니다. 충전 효과는 [이전 전후 실기 결과](PROTECTION_CONTROL_FUNCTIONAL_RESULT_AND_GUI_PLAN.md)를 계속 근거로 사용합니다. 사용자는 같은 충전 자료를 다시 제출하지 않겠다고 밝혔으며, 이번 판정에 재제출이 필요하지 않습니다.

**이번 보고서에서 일반 GUI의 보호 해제 동작이 정상 완료된 것을 확인했습니다.** 단발 시험 도구 이후 새 GUI·관리자 helper·결과 저장으로 연결한 경로의 실기 근거입니다.

| --- | --- | --- |
| 동작 | 보호 해제 · 일반 충전 | `DisableProtection` |

이미 모드0이어서 설정을 생략한 결과와 다릅니다. 이번 기록에는 모드1에서 설정 1회를 거쳐 모드0을 다시 읽은 전환이 있습니다. 미조회인 임계값을 0·100 또는 복원된 값으로 채우지 않습니다.

검토한 소스의 GUI는 정리 완료 `Result` → 현재 요청의 ACK → 일치하는 `Released`를 받은 뒤에만 이 성공 결과를 반환합니다. helper는 실제 호출·출력·입력·대상 정리와 자기 작업 원장의 정상 해제 뒤에 `Released`를 보냅니다. 따라서 이번 결과는 해당 소스 계약에 따라 정리·해제 응답까지 완료된 경로와 일치합니다. TXT에 원시 통신이나 실행 바이너리 버전이 포함된 것은 아니므로, 개별 ACK 프레임이나 바이너리 출처를 독립 인증한 것으로 기록하지 않습니다.

이번 파일은 해제 결과 한 건입니다. 별도 **보호 상태 확인**과 **80% 보호 켜기**의 보고서까지 제출된 것으로 세지 않습니다. 새 GUI에서 모드1로 들어간 경위와 실행 시 GUI의 권한 토큰도 파일만으로 단정하지 않습니다. 이것들을 추가 파일·같은 시험을 요구하는 조건으로 삼지 않습니다.

## 현재 개발 단계와 다음 작업

이전 노트북 시험의 **80% 충전 억제와 해제 후 85%까지 충전 재개**는 유효한 기능 검증 결과입니다. 이번에는 **새 일반 GUI를 통한 해제 요청·모드 전환·정리·TXT 저장**이 추가로 확인됐습니다. 현재 단계는 확인된 모델 범위의 수동 제어 베타를 실사용에 맞게 다듬는 단계입니다.

2. 향후 제어 TXT에 배포 버전과 조회 시점을 남겨 결과가 어떤 프로그램에서 나왔는지 비교하기 쉽게 합니다. 전체 경로·계정·장치 식별자는 넣지 않습니다.
