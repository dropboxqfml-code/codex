# 보유 native SABI 드라이버의 전달 경로 검토 — 2026-11-07 한국 시간

같은 940X3G 계열의 과거 Settings 배포본에 포함된 **x64 Sabi.sys 본문을 새로 분석**했습니다. DLL과 드라이버의 요청 전달은 연결했지만, 선택한 드라이버 경로는 배터리 명령의 의미를 해석하지 않는 일반 중계입니다. 새 보호 상태 조회·충전 제한은 구현하지 않았으며 실제 제어는 **Unsupported**입니다.

## 사용한 원본

이미 확보한 [940X3G W7 Settings 2.0.0.78](BATTERY_PROTECTION_ACCESS_FOLLOWUP.md)의 파일을 사용했습니다. 드라이버는 예전 비교용 BLE 패키지의 기록과도 같은 해시입니다. 새 바이너리 취득이나 현재 노트북의 설치 파일 확인으로 보고하지 않습니다.

## DLL과 드라이버 사이에서 확인한 사실

선택한 device-control callback은 5개 IOCTL 분기를 가집니다. DLL의 일반 SABI 요청과 드라이버 분기의 IOCTL 값이 일치하는 것을 확인했습니다. 해당 분기는 입력 최소 26바이트·출력 최소 16바이트를 검사하고, 요청 안의 16바이트 프레임을 공유 영역에 복사한 뒤 다시 16바이트를 반환합니다. 포트·두 selector·공유 주소의 구성 값은 호출자 입력에서 가져옵니다.

해당 분기의 정상 복사 경로에서는 버퍼 조회의 성공 NTSTATUS와 반환 정보 크기 16바이트를 사용합니다. 길이·버퍼 조회 실패는 별도 오류 상태로 완료됩니다. **정상 복사 완료도 펌웨어 ACK·배터리 명령 처리·보호 설정 조회의 성공을 검증하지 않습니다.** DLL은 별도로 ACK를 확인하고 프레임 안의 11바이트를 호출자에게 복사합니다. 현재 순수 `Sabi3X64Abi.TryExtractDriverPayload`의 성공 여부·반환 크기·ACK 검사는 이 경계와 모순되지 않습니다. 새로운 장치 실행 경로를 추가할 이유는 없습니다.

초기화용 별도 분기는 기존 BIOS 영역의 64KiB 스냅샷을 전달합니다. SABI signature 검색은 별도로 분석한 DLL이 담당하며, 이 드라이버가 모델별 배터리 기능을 판정하는 것으로 해석하지 않습니다.

이 native 규약은 **요청 26바이트 / 응답 프레임 16바이트 / 호출자 payload 11바이트**입니다. WMI의 **프레임 21바이트 / payload 16바이트**와 다릅니다. 실제 노트북의 native selector·공유 주소·P05ACJ 레거시 처리자 사이의 결합은 확인하지 못했습니다. 숫자나 동작 형태의 유사성만으로 같은 실행 경로라고 판정하지 않습니다.

다른 선택 분기에는 일반 포트·물리 메모리 읽기와 쓰기가 있습니다. 이 드라이버를 검증된 읽기 전용 보호 조회 backend로 채택하지 않습니다. Queue 구성 필드나 호출 내부의 로컬 mutex만으로 모든 요청의 동시성 안전성을 주장하지 않습니다.

## 기존 명령 인벤토리 정정

Settings 2.2.0.18에서 과거에 'RTTI 미복구 생성자 후보 6개'로 남겼던 직접 호출 대상은 문자열 처리 helper였습니다. 실제 객체는 `GetCommand` 안에서 vptr를 직접 설정했습니다. 해당 원본의 객체·RTTI 연결을 복원해 Settings 실행, 음소거 LED, ExpressCache, OTP, 카메라/마이크, 절전 진입 작업으로 구분했습니다. 이 결과는 배터리 보호 처리자를 추가하지 않습니다.

이전의 289개 선언 명령·287개 고유 직접 대상·281개 RTTI는 당시의 서로 다른 후보 집계였습니다. 모든 직접 대상을 검증된 생성자로 부르거나, 이번 6개 복원으로 전체 명령 슬롯·동적 등록을 완전히 증명했다고 해석하지 않습니다.

## 검증과 현재 개발 판단

드라이버·DLL·INF 및 정정한 명령 모듈의 원본 해시를 다시 확인했습니다. 드라이버의 runtime-function 범위 25개를 정적으로 디코딩했고, 선택한 DeviceAdd/dispatch 명령 518행은 별도 검토자가 재생성해 일치를 확인했습니다. DLL의 IOCTL 값·버퍼 크기·ACK 검사와 드라이버의 길이 검사·복사·완료 경로도 독립 대조했습니다. 요약은 [검사 기록](reports/native-sabi-driver-audit.json)에 저장합니다. 원본·디스어셈블리·포트·물리 주소·개인 정보가 있는 원문은 공개하지 않습니다.

**실제 보호 설정을 처리하는 현재 모델의 명령과 응답·신뢰할 재조회는 여전히 미확정입니다.** 이번 결과는 native 드라이버를 설치하거나 시작하면 충전 제한을 구현할 수 있다는 증거가 아닙니다. 하드웨어의 영구 미지원 판정도 아닙니다. 구체적인 새 처리 근거 없이 기존 명령·초기화·예약을 다시 실행하지 않습니다.

앱·테스트 코드·EXE·기존 ZIP은 변경하지 않았습니다. 이번에는 정적 검증과 기록 정정만 수행했으므로 빌드·단위 테스트를 반복하지 않았습니다. C# 437개 / Python 85개 통과와 전체 빌드 경고·오류 0개는 직전 코드 커밋 `5d77df5`의 검증 기록입니다. 기존 프로그램과 개발 소스를 그대로 사용하며 추가 노트북 시험·자료 재제출·드라이버/서비스/보안 변경은 필요하지 않습니다.
