## 실제로 찾은 배터리 관련 명령의 범위

공개 DSDT의 표준 배터리 객체에는 상태·용량·전압·사이클 수를 구하는 별도 경로가 있습니다. 중요한 점은 **그 경로의 명령과 충전 상한 명령을 구분하는 것**입니다.

| 공개 DSDT 문맥 | 관측한 구문 | 현재 해석 범위 |
| --- | --- | --- |
| _BIF/_BIX 정보 | GSSW의0x82와 B0/B2/B4/B6/D0 selector | 설계/완충 용량·전압·경고/낮은 용량·사이클 수 관련 정보입니다. 80% 충전 상한 번호가 아닙니다. |
| _BST 상태 | GSSB의0x81/0x84 및 GSSW의0x82와 A4/A2/A6 selector | 충전/방전 상태·속도·남은 용량·전압 정보를 구성합니다. 실제 보호 ON/OFF를 뜻하지 않습니다. |
| _BTP | 별도 GSSW0x84 경로 또는 EC 분기에서 trip point 처리 | 표준 배터리 알림 임계값 문맥입니다. 충전을 멈추는 상한으로 채택하지 않습니다. |

이는 호출자 구문과 표준 배터리 package 항목의 연결을 읽은 결과입니다. 이 경로의 helper는 WMI 프레임 Field와 다른 선언을 사용하며 별도의 바이트/워드 반환 구문이 있습니다. EC에서 정보를 얻는 대체 분기도 존재합니다. 현재 Windows가 어느 분기를 사용하는지는 평가하거나 실행하지 않았습니다. 위 숫자를 WmiAcpiMethod의 opcode/payload로 옮기거나 실행하지 않습니다.

검토한 DSDT/SSDT와 표준 배터리 객체에서 충전 상한 getter/setter의 적용 계약은 확보하지 못했습니다. 이것을 BIOS/SMM 내부 기능이나 장치 기능의 부재로 확대하지 않습니다. 디스어셈블 결과에는 DSDT의 미해소 외부 메서드10개·마지막 SSDT의1개와 동적 표 로드 구문도 있어 완전한 펌웨어 namespace를 해소했다고 보고하지 않습니다.

## 다른 삼성 배터리 명령과의 대조

새로 검토한 [rapgenic/samsung-book-laptop의 고정 소스](https://github.com/rapgenic/samsung-book-laptop/blob/fa84979ec502f1f6c75e0fb783ccaf4e3f114495/samsung_acpi.c#L283)는 SAM0428·ACPI CSFI 경로입니다. 원문 SHA-256은 efdc3447952195253308418b732033fcc9fac738d89261d2b36b224e204c9490입니다.

이 소스의 배터리 조회는0x7A 그룹·0x82·E9/91 selector이고 응답의 다른 payload 항목을 사용합니다. 설정은 별도90 selector입니다. 현재 ATIV의 Windows0x65 후보와 같은 계약으로 적용할 근거가 없습니다. 이 출처에는 현재FF를 보호 OFF/ON·미지원으로 변환할 분기도 없습니다. 원본의 일부 응답 검증은 두 불일치를 AND로 묶으므로 그대로 복사하지 않습니다.

연결된 [Windows 역공학 댓글](https://github.com/joshuagrisham/samsung-galaxybook-extras/issues/21#issuecomment-2369407757)은 Galaxy Book360/SAM0428 문맥이며 작성자가 추측을 명시합니다. OEM 모듈 버전·해시·함수/기계어 근거가 없어 현재 모델의 공식 Windows 계약으로 승격하지 않습니다. 새 실행 후보·요청 바이트 목록으로 제품에 등록하지 않았습니다.

## 조사 범위·검증·개발 반영

- 보유 파일을 확인했으나 OEM 호출자 원본·기계어 덤프는 현재 작업 공간에서 찾지 못했습니다. BatteryToast/PowerAudit의 보유 TXT 메타데이터로 공개 후보를 대조했으며 파일명 일치만으로 같은 프로그램으로 판단하지 않았습니다. 기존 파일 재제출은 요청하지 않았습니다.
- GitHub 공개 저장소·README·이슈·파일 목록을 조사했습니다. NP940X3G README 검색은 기존 두 설정 저장소, BIOS 식별자 이슈 검색은 이번fwtr 출처로 이어졌습니다. API 접근은 정책상403, 일부 공개 검색은429였으며 우회하지 않았습니다. 조사 범위의 미확보를 전체 공개 자료나 기능의 부재로 해석하지 않습니다.
- Debian 공식 acpica-tools20250404-1 패키지를 임시 폴더에만 풀어 iasl20250404의 정적 -d 기능을 사용했습니다. AML 평가 도구·펌웨어·저장소의 수집 스크립트는 실행하지 않았습니다. 표를 한 namespace에 결합하는 -da 시도는 중복 정의 오류로 끝났으므로 각 표를 독립적으로 디스어셈블했습니다. 미해소 외부 참조의 한계는 유지합니다.
- reports/p05acj-public-static-review.jsonl에 고정 분류·수만 기록했습니다. 실제 OEM/AML/DLL/장치 실행·포트/메모리 접근·예약/서비스/보안 변경은 없었습니다. 앱 코드·디코더·요청·배포 ZIP은 바꾸지 않았고 새 빌드/전체 테스트를 반복하지 않았습니다. 429개·Python27개·빌드0경고/0오류는 기존v7 배포 기록입니다.

## 다음 구현 판단

이번 진전은 **동일 모델/BIOS의 공개 정의로 일반 중계와 표준 배터리 경로를 분리한 것**입니다. 모델에 맞는 공개 ACPI 자료가 없었던 조사 범위는 보완됐습니다. 그러나0x65/0x66의 현재 모델 Windows 계약과 실제FF의 의미는 아직 확인되지 않았습니다. 명령 수락·보호 상태·실제 상한을 입증하지 못한 채 새 호출 도구·알림 임계값 쓰기·포트 코드·제어 어댑터를 추가하지 않습니다.

다음 대상은 공개 중계의 세분화가 아니라 **적용 모델이 확인되는 OEM 배터리 호출자의 명령 선택/응답 분기 또는 같은 BIOS의 관련 펌웨어 처리 계약**입니다. 이 근거가 없으면 FF 의미·입력 바이트·허용 명령을 바꾸지 않습니다. 원본 재제출·v7 반복·관리자 비교·추가 OEM 시험은 요청하지 않으며 실제 충전 제어는 Unsupported로 유지합니다.
