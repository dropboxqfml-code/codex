## 기존 기능과 권한 경계 검토

현재 GUI/helper의 컴파일 소스 구성 207파일을 기준으로 HTTP/소켓 클라이언트 관련 API 검색을 수행했으며 검색 일치는 0건입니다. 검토 패턴은 HttpClient/WebClient/WebRequest/TcpClient/UdpClient/Socket 및 System.Net.Http/Sockets/NetworkInformation입니다. 이는 해당 API의 정적 검색이며 모든 우회 통신이나 Windows 실행 중 트래픽을 측정한 검사가 아닙니다.

WindowsManualProtectionOperationService의 고정 helper 경로·명시적 runas·현재 계정 파이프 ACL·Network SID 거부와 helper의 `.` 서버/Identification을 검토했습니다. ManualHelperAdmission의 제한된 작업/토큰, Program의 사용자 확인·preflight·lease·완료 절차, App의 일반 권한 시작·수동 작업 중 종료 차단, MainViewModel의 새 조회/지원/Mock/불확실 상태 경계를 검토했습니다. 이번에는 새 제어 명령이나 호출 한도를 추가하지 않았습니다.

기존 portable suite의 수동 요청·프로토콜·잘못된 인수·권한/지원 불일치·실제 자원 정리·시간 초과·미확인 결과·과거 관찰의 분리 검사를 함께 실행했습니다. 과거 기록/메모/묶음이 실제 제어 상태가 되지 않는 검사와 기존 표본/시계/장치 호출 횟수 검사도 유지합니다. 실제 OEM/펌웨어 동작은 0회입니다.

LocalUserInteraction과 LocalPathPolicy의 로컬 파일 열기·저장·복원, SettingsStore/ObservationNoteStore/RecentObservationStore의 크기·형식·잠금·원자적 교체, LocalLog의 고정 이벤트 정책을 검토했습니다. recent 파일의 전체 경로는 로컬 재열기용이며 내보내기 메타데이터에 포함하지 않습니다. TXT 본문·파일명·메모에 사용자가 적은 개인정보는 내보내기에 포함될 수 있습니다. 기록 구분 표시는 비밀 값이나 인증 수단이 아닙니다.

## 실제 실행과 남은 항목

Portable 및 전체 net48 WPF/XAML Release 빌드에서 경고/오류 0개입니다. Windows self-test의 최근 선택과 같은 이름 A/B 표시 검사를 추가해 컴파일했습니다. ZIP은 프로그램 6파일과 안내/BUILD-INFO/SHA256SUMS의 9항목, GUI 버전, 빌드 바이트, 내부 해시와 CRC를 확인합니다. 정확한 ZIP 해시와 로그 지문은 [검증 기록](reports/release-028-validation.json)에 저장합니다.

이번 환경은 Linux입니다. 사용자 확인을 인계한 0.2.7 저장/불러오기와 이번 0.2.8의 Windows 실행 결과를 구분합니다. Windows GUI self-test·실제 대화상자·한글 IME·고배율·오래 사용하는 동안의 메모리/응답성·디스크 부족·강제 종료/전원 차단은 이번에 직접 실행하지 않았습니다. 중단 폴더 검사는 준비한 fixture이며 실제 프로세스를 충전 제어 중 중단한 시험이 아닙니다.

파일 잠금은 협력하는 앱 사이의 충돌 방지이고, 악의적인 동일 계정 프로세스의 경로 교체·하드링크를 완전히 격리하지 않습니다. 경로 검사와 시스템 호출 사이의 모든 경쟁을 해결했다고 주장하지 않습니다. 여러 파일의 저장·장치 캐시를 하나의 전원 차단 안전 트랜잭션으로 만들지는 않았습니다. 복구본이 기록되기 전 저장 공간 부족/장치 오류나 정리 실패는 원본 묶음 보관과 오류 안내로 처리합니다. 중단 자료는 임의로 일괄 삭제하지 않습니다.

현재 개발 ZIP에는 Authenticode 서명이 없습니다. 서명된 배포 경로의 인증서와 정확한 파일의 최신 Windows Defender 검사 기록은 외부 준비/실행 의존성입니다. 이번 Linux에서 해당 서명·스캔을 수행했다고 기록하지 않습니다. 제품 보안 정책을 낮추거나 검증 조건을 우회하지 않습니다.

다음은 0.3.0 준비를 위한 [Windows 사용 흐름 확인](TEST_PLAN.md)과 배포 검증입니다. 확인 중 결함이 발견되면 0.2.9에서 수정하고 재검증합니다. 기존 충전 시험과 재부팅 유지 근거를 인계하므로 같은 하드웨어 시험을 반복할 필요는 없습니다.
