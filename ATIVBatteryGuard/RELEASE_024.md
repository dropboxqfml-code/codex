# ATIV Battery Guard 0.2.4

2026-11-25 한국 시간. 미저장 관찰 기록 보호와 최근 저장·열기 기록 목록을 구현했습니다. 사용자가 확인한 0.2.3의 과거 TXT 그래프 표시·키보드·마우스 표본 선택 결과를 인계했습니다.

[프로그램 ZIP](../downloads/ATIVBatteryGuard-0.2.4-WIN10-X64.zip) · [사용 순서](RELEASE_024_USER_STEPS.txt) · [검증 기록](reports/release-024-validation.json)

새 관찰 시작·관찰 지우기·일반 창 종료에서 저장 확인이 필요한 관찰 기록을 검사합니다. 확인 창의 예는 관찰 중단·최종 TXT 저장 후 진행, 아니요는 저장 없이 진행, 취소는 현재 기록 유지입니다. 기본 선택은 취소입니다. 저장 실패 시 요청한 작업을 중단하고 중단된 관찰 자료를 보관합니다. 현재 내용이 저장된 중단 기록과 빈 세션은 확인 창을 생략합니다. 기록 중 저장한 자료는 종료 상태를 확인하기 위해 최종 저장 선택을 제공합니다.

기존 helper 작업 진행·정리 대기 중에는 창 종료를 우선 차단합니다. 관찰 확인 창이 열린 동안 새 관찰·지우기·중복 종료 요청의 재진입을 막습니다. 확인 창에서 취소한 경우 관찰 자료와 진행 상태를 유지합니다.

최근 목록은 저장하거나 정상적으로 열었던 파일을 최근 순서로 10개까지 유지합니다. 파일명·표본 수·마지막 표본의 경과 시간·저장 당시 상태를 표시합니다. 항목을 선택하고 선택 기록 열기를 누르면 기존 로컬 경로 검사와 TXT 검증으로 파일을 다시 읽습니다. 파일이 이동·삭제됐거나 읽기에 실패하면 안내를 표시하고 앞서 열었던 과거 그래프를 계속 표시합니다.

로컬 설정 폴더의 recent-observations.json에 경로와 요약을 보관합니다. 재실행 시 목록의 메타데이터를 읽고, 항목을 선택해 열 때 해당 TXT를 읽습니다. 목록 갱신은 프로세스 간 파일 잠금·최신 목록 병합·임시 파일과 원자적 교체를 사용합니다. 파일 크기·개수·경로·메타데이터를 검증하며, 손상되거나 지원하지 않는 목록은 원본을 보존하고 안내합니다. 목록 갱신 오류는 완료된 TXT 저장 결과와 독립적으로 안내합니다.

새 회귀 16개 포함 1179개 통과·실패 0개·건너뜀 0개입니다. 세 동작의 취소·저장, 명시적 폐기·저장 실패·재시도, 진행 중 최종 상태, 재진입·확인 오류·helper 우선 차단을 검사했습니다. 실제 목록 파일의 재로딩·10개 제한·중복 제거·다중 저장소 병합·잠금 실패·원본 보존·잘못된 경로·손상·파일 이동/삭제와 성공한 TXT 저장 결과 보존도 검사했습니다.

Portable Release 및 전체 net48 WPF/XAML Release 빌드는 각각 경고 0개·오류 0개입니다. Windows GUI self-test에 목록 바인딩·항목 선택·최근 기록 열기·취소·최종 저장 검사를 추가해 컴파일했습니다. 이번 Linux에서 실제 Windows 확인 창과 최근 목록 UI 검사는 실행하지 않았습니다.

제품 수정 파일은 새 최근 기록 저장소·항목 모델, IUserInteraction·LocalUserInteraction, MainViewModel, App의 종료 처리, XAML, WindowsSmokeTest와 버전 상수입니다. 회귀 검사·패키징·사용 안내·인수인계도 갱신했습니다. 배포 ZIP의 9개 항목·프로그램 파일 6개·GUI 버전 0.2.4.0/0.2.4·내부 SHA·CRC·빌드 바이트 일치를 검증했습니다.

다음 개발 제안은 두 관찰 TXT 비교입니다. 두 파일을 선택하고 같은 경과 시간 축에서 잔량 변화를 살펴보며 각 파일의 공백과 선택 표본의 전원·충전 상태를 확인하는 기능을 우선합니다. 기록별 메모는 그다음 개선 후보입니다.
