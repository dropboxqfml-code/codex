## 재현한 메커니즘과 수정

ViewModel에는 ‘종료 취소 확’까지만 반영되고 화면에는 조합 중 ‘인’까지 보이는 지연 바인딩 상태를 모사했습니다. 확인창 진입의 Text 알림이 화면을 모델 값으로 다시 갱신해 확인창에서 보이는 글자가 짧아지는 회귀를 재현했습니다. 수정 전1267통과·1실패(1268등록)였고 그 재현 JSON을 보존합니다. 이는 코드의 지연 입력 덮어쓰기 메커니즘을 재현한 것으로 사용자 기기의 v3 복합 오류에서 정확히 어떤 값이 달랐는지를 로그로 확정한 것은 아닙니다.

RC3는 MainWindow.OnClosing에서 현재 창의 편집 가능한 메모 입력칸만 읽어 TryCapturePendingText로 초안에 먼저 반영한 뒤 기존 확인 가드를 실행합니다. 다른 창/다른 입력칸/읽기 전용 값은 건드리지 않습니다. 처리 중·확인 중·폐기된 편집기는 입력 반영을 거부하며, 입력을 안전하게 반영할 수 없으면 창을 유지합니다. 이 동작은 초안만 바꾸고 사용자가 저장을 선택하기 전에는 디스크 저장을 하지 않습니다.

확인 진입 시에는 값이 바뀌지 않은 Text 알림을 생략합니다. 읽기 전용/명령/상태 갱신과 확인 종료 후 표시 복구, 저장/저장 없이 진행/취소 정책은 유지합니다. 재진입 차단·저장 실패·읽기 전용/폐기 상태를 검사했습니다.

제품207소스 중 RC2 대비 Views/MainWindow.cs, ViewModels/ObservationNoteViewModel.cs, Core/Models/ApplicationRelease.cs만 바꿨습니다. XAML·크기/스타일·충전 제어·장치 검증·호출 제한·설정/메모/기록 형식은 유지합니다. 버전은 새 후보 RC3이며 정식 출시가 아닙니다. Core 버전 변경을 포함한 재빌드로 helper/WMI 어셈블리 바이트도 달라졌으며 해당 소스가 변경된 것은 아닙니다. 이전 파일의 Windows 검사 결과를 새 바이트의 검사 완료로 표시하지 않습니다.

## 닫기 전용 검사 v4

기존 저장 성공 근거는 인계하며 --ime-close/닫기취소확인.cmd는 미리 준비한 저장 기준값을 사용합니다. 사용자는 ‘종료 취소 확인’만 직접 입력하고 조합 중 X를 누릅니다. 저장 확인은 자동 취소하고 직접 확인 후 JSON을 저장합니다. 새 저장·재열기 시험을 실행한 것처럼 표시하지 않습니다.

검사 창의 네이티브 닫기 메시지를 관찰해 제품 닫기 처리 전, 확인 가드 진입 전, 취소 후의 상태를 분리합니다. 창 표시/수정 상태/VM문구 일치/화면 문구 일치/VM-화면 일치/조합 상태/저장값 읽기와 일치를 불리언 또는 관찰되지 않음(null)으로 남깁니다. 처음 닫기 메시지에서는 파일을 읽지 않습니다. 저장값 불가와 실제 불일치도 다른 코드로 나눕니다. 입력 글자·키 입력·개인 경로·장치 식별값은 기록하지 않습니다. 이 창의 메시지를 관찰만 하고 처리하지 않으며 전역 후킹/입력 주입은 없습니다.

일부 입력기에서 이벤트 증거가 부족하면 미확인으로 기록합니다. 직접 확인 체크는 자동으로 선택하지 않습니다. 실제 배터리/OEM/쓰기/helper/자동 전송은 없으며 기존 개인 자료 대신 새 임시 폴더의 합성 예제만 씁니다. 초안/창 보호를 위한 검사 호스트의 강제 유지와 제품 가드 결정은 서로 다른 필드로 보존합니다.
