# 0.3.0 서명 배포 준비

2026-11-25 한국 시간. 현재 배포본은 0.3.0-rc.2 개발 검증판으로 미서명입니다. 사용자 Windows GUI 자동 검사 통과와 이전 Defender 수동 보고는 인계하되 서명 완료나 정식 출시 승인으로 확대하지 않습니다. 이번에는 인증서를 발급/구매하거나 서명·Windows 검사를 실행하지 않았습니다.

## 이번에 준비한 항목

서명 후 검사 스크립트 `scripts/Test-WindowsRelease.ps1`의 고정 대상을 현재 프로그램의 6파일로 맞췄습니다. EXE/DLL 4개 모두 유효한 동일 배포자 서명을 요구하고 설정 파일 2개도 검사 전후 SHA-256 일치를 확인합니다. 예전 3파일 preview용 Python 검증기도 현재 배포 구성에서 제공되는 모든 EXE/DLL을 검사하도록 보강했습니다. helper/WMI 서명 누락·미서명·다른 배포자와 파일 변경 거부 회귀를 추가했습니다. 이 검증기 회귀는 가상 증거에 대한 판정 검사이며 실제 Windows Authenticode/Defender 실행은 아닙니다.

| 프로그램 구성 | 서명/확인 범위 |
| --- | --- |
| ATIVBatteryGuard.exe | 배포자 서명·신뢰/유효성·동일 배포자·최종 해시 |
| ATIVBatteryGuard.Core.dll | 위와 같음 |
| ATIVBatteryGuard.WmiInterop.dll | 위와 같음 |
| ATIVBatteryGuard.ManualProtectionHelper.exe | 위와 같음. 관리자 helper를 실제 실행하지 않고 파일만 확인 |
| ATIVBatteryGuard.exe.config | 서명 후 배포 구성의 해시 일치 |
| ATIVBatteryGuard.ManualProtectionHelper.exe.config | 위와 같음 |

검증 도구를 최종 묶음에 포함한다면 별도의 EXE도 배포자 서명과 같은 검증을 적용해야 합니다. 위 스크립트는 일반 프로그램 6파일만을 대상으로 하므로 도구 포함 배포 전체를 자동으로 보증하지 않습니다.

## 실제 서명 배포 시 순서

1. 최종 버전과 앱 소스를 확정하고 별도 폴더에 빌드합니다. 최종 소스 지문과 빌드 결과를 보존합니다.
2. 정당한 배포자 코드 서명 인증서/서명 서비스가 준비된 환경에서 4개 PE 파일에 SHA-256 서명과 인증기관이 안내한 RFC 3161 타임스탬프를 적용합니다. 개인 키·인증서 비밀번호는 저장소나 공유 로그에 넣지 않습니다.
3. Windows에서 각 파일의 게시자, 신뢰 체인·유효 상태와 타임스탬프를 직접 확인합니다. 수집기의 -RequireTimestamp는 OS의 Valid 판정과 TimeStamperCertificate 존재/지문을 함께 요구합니다. 독립적으로 타임스탬프 토큰/서명 시각을 해석하거나 모든 체인을 검증한 것은 아니므로 실제 Windows 신뢰 판정과 구분해 과장하지 않습니다.
4. 같은 Windows에서 `Test-WindowsRelease.ps1 -RequireTimestamp`를 해당 폴더에 실행해 서명·Defender 보호 상태·최신 정의·검사 결과·관련 탐지·검사 전후 파일 해시를 수집합니다. 실행 정책을 우회하거나 보호 기능/예외를 변경하지 않습니다.
5. 서명은 바이트를 바꾸므로 이전 RC2 해시/GUI 매니페스트를 새 서명 파일의 근거로 재사용하지 않습니다. 서명된 최종 파일로 새 해시와 검사 매니페스트를 만들고 해당 바이트의 실행·패키지 구성 검증을 연결합니다. 정식 배포용 패키징에도 이 증거 판정을 연결해야 하며 개발 RC 패키지의 finalReleaseApproved=false를 임의로 바꾸지 않습니다.

서명은 게시자 식별과 파일 무결성을 위한 것입니다. 모든 Windows 평판 경고의 즉시 해소나 악성 코드 부재를 보장하지 않습니다. 현재는 인증서/최종 서명 환경이 제공되지 않았으므로 실제 서명과 정확한 최종 파일의 Windows 보안 검사 근거가 남아 있습니다.

## 최종 판정 보강 — 2026-11-25

`validate_final_release`는 일반 preview 판정과 별도로 정확히 현재6파일을 요구하고, EXE/DLL4개 각각의 Valid/동일 게시자·타임스탬프 존재와 타임스탬프 인증서 지문, 최신 보안 검사·해시 일치를 모두 요구합니다. 예전 서명만 있는 보고서나3파일 범위로 최종 판정을 통과시킬 수 없습니다. PowerShell 수집기는 타임스탬프 메타데이터를 기록하며 -RequireTimestamp 옵션으로 누락을 검사 전에 거부합니다. 기존 개발/preview 호환 경로는 유지합니다. 새3개 타임스탬프 회귀와3파일 범위 거부를 더해13회귀 통과입니다.

실제 인증서/서명 서비스는 제공되지 않았고 인증서 발급/구매·서명/타임스탬프·Windows PowerShell/Defender 실행은 하지 않았습니다. 최종 버전/서명된 바이트의 GUI 검사와 이 판정을 실제 정식 패키징에 연결하는 단계는 여전히 필요합니다. 현재 미서명 RC나 도구에 finalReleaseApproved=true를 붙여 정식판으로 내보내지 않습니다.
