# 0.3.1 — 충전 제한 상태에 따른 버튼 강조

**후속 확인 완료 / 2026-11-26:** [사용자 0.3.1 결과](FIELD_031_PERSONAL_RESULT.md)에서 배포 지문/파일 전후/GUI/기본 조회가 통과했고 버튼 강조도 정상이라는 사용자 확인을 받았습니다. 기존 파일 그대로 개인용 안정판 기준으로 사용합니다. 아래 빌드 당시의 Windows 대기 설명은 이력이며 같은 검사를 반복하지 않습니다.

2026-11-26 한국 시간. [0.3.0 사용자 최종 파일 결과](FIELD_030_PERSONAL_RESULT.md)는 통과했습니다. 이후 보고된 고정 파란 버튼 표시를 작은 수정 버전으로 분리합니다.

## 표시 동작

| 마지막 확인된 상태 | 파란색 버튼 |
| --- | --- |
| 제한 해제 / 모드0 | 제한 해제 |
| 모드1·상한80·하한75 확인 | 80% 충전 제한 |
| 미조회·처리 중·실패·미확인·절전 복귀 무효화·시뮬레이션 | 없음 |
| 모드1이나 상한/하한이 다르거나 미확인 | 없음. 기존 상태 요약에 상세 상태 표시 |

고정 PrimaryButton 대신 두 버튼이 동일한 기본 스타일을 상속하고 마지막 수용된 결과에 따라 기존 파란색/흰 글자를 표시합니다. 기존 hover/pressed/disabled 색도 유지합니다. 상단 ‘마지막 확인’ 상태 요약과 조회 시각은 그대로입니다. 사용자 희망 설정·배터리 잔량·클릭한 동작을 확인된 상태로 간주하지 않습니다. 이미 켜진 모드의 단발 확인에서 상한/하한을 새로 읽지 않았다면 80%라고 추정하지 않습니다.

## 유지한 디자인과 안전 경계

XAML의 새 로컬 상태 스타일과 두 버튼의 Style/Tag 바인딩을 제외한 모든 노드/속성이 0.3.0과 같음을 XML 비교로 확인했습니다. 화면 배치·텍스트·크기·글꼴·둥근 테두리·간격과 다른 컨트롤 디자인은 유지합니다. 앱 전역 스타일/테마는 바꾸지 않았습니다.

제품207소스 중 MainViewModel.cs의 수동 결과 기반 표시 속성/알림, MainWindow.xaml의 두 버튼 스타일, WindowsSmokeTest.cs의 합성 검사, ApplicationRelease.cs의 버전/파일 버전(0.3.1/0.3.1.0)만 다릅니다. 나머지203소스는 0.3.0과 해시가 같습니다. 하드웨어 경로·조회/쓰기 횟수·수동 승인·명령 활성화 조건·파일 형식은 그대로입니다. 표시 속성은 하드웨어·시계·파일을 읽거나 설정하지 않습니다. 미서명 안내는 배포 텍스트에만 있습니다.

## 검증과 파일

새 회귀3개 포함1275통과·실패/skip0, Python27검사 통과, portable/전체net48 WPF/확인 도구 빌드 경고·오류0입니다. Python의 기존 서명030 경로는 새 UI 소스를 먼저 거부했으며 테스트의 기대 오류만 그 조건에 맞췄습니다. 실제 gate는 완화하지 않았습니다. [상세 근거](reports/release-031-validation.json)에 최초 실패와 재검사 범위를 구분했습니다.

두 ZIP의 제품6파일은 동일하고 CRC/내부 SHA/허용 목록/버전·매니페스트를 확인했습니다. 기존0.3.0 ZIP/검사 결과는 보존합니다. 개인용0.3.1 패키징은 현장 검증된0.3.0 지문과 위4파일 변경 범위만 허용합니다. 서명 배포 경로는 별도로 유지합니다.
