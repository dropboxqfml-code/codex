# 남은 직접 조회 후보와 중계 경로 검토 — 2026-11-06 한국 시간

**현재 자료에서 실제 배터리 보호 설정을 읽을 새 진입점은 확보하지 못했습니다.** 이번에는 기존에 열려 있던 직접 하위 함수, 삭제 함수의 호출자, 레거시 중계의 다른 분기와 SSDT 대응을 확인했습니다. 앱·제어 코드·실행 파일은 변경하지 않았습니다.

[직전 요청 범위 보강](FIRMWARE_QUERY_BOUNDARY_UPDATE.md)은 그대로 유지합니다. 아래는 고정된 저장 파일의 정적 분석이며 현재 노트북의 실행·설정 관측이 아닙니다. OEM/UEFI/AML 실행, 하드웨어·실험 예약 표식 접근은 없었습니다. 원본·기계어·ASL·I/O 상수·주소·식별자는 저장소 밖 비공개 캐시에 보존합니다.

## 초기화에서 열려 있던 직접 하위 호출

SecSabiDispatch 29,952바이트/SHA-256 `2795669f18e3fb787d908ba00e2e9da7ab7d398ee599f27aa2f068129b46f310`의 직접 함수8개를 검토했습니다. 기존 초기화21개·helper2개·descriptor 후보56개를 새 발견으로 다시 세지 않습니다. 아래 숫자는 파일 안의 RVA입니다.

| 함수 | 확인한 직접 효과 | 보호 조회 판단 |
| --- | --- | --- |
| DB4 / 1B94 | 자기30바이트 stack 메시지를 만들고 그 버퍼를 송신 helper에 전달 | 상속된 전체 RCX를 SABI 포인터로 해석하면 안 됨 |
| 2150 | PCI 조회 결과를 caller가 지정한 별도 static 구조2개에 기록 | 해당 caller의 descriptor나 parent-global 셀에 쓰는 경로로 연결되지 않음 |
| 230C | 다른 프로토콜의 중첩 데이터를 읽어 내부 메시지·스칼라 I/O 구성 | 새 typed SABI flag writer나 보호 상태가 아님 |
| 4C74 | 설정 테이블의16바이트 key 비교 후 포인터 반환 | 비교 대상에 직접 쓰지는 않음; 반환 데이터의 공급자를 별도 추적 |
| 5AEC | caller의30바이트를 읽어 I/O 송신 | caller 버퍼에 직접 쓰지 않지만 하드웨어 부작용 없는 getter는 아님 |
| 5B2C | 수신 성공 경로에서 caller 버퍼30바이트 기록 | 실제 caller의 scratch는 descriptor와 겹치지 않고 등록 뒤에 호출됨 |
| 5CC4 | indexed I/O 선택·읽기·복원 후 AL 반환 | I/O 쓰기도 있어 읽기 전용 대체 조회로 사용할 수 없음 |

특히5B2C의 수신 버퍼가 descriptor를 덮는지는 실제 stack 범위와 호출 순서로 검산했습니다. 해당 caller에서는 scratch와 descriptor 저장소가 분리돼 있고, 등록 루프 이후 수신합니다. 다른 caller의 스칼라/버퍼도 필요한 범위만 추적했습니다. 내부30바이트 메시지를 WMI payload 길이나 새 요청 규약으로 채택하지 않습니다.

이는 선택한 직접 효과의 확인입니다. 실제 I/O 효과, 불투명 서비스, 임의 caller·producer 별칭, 보존된 context 수명까지 닫은 증명은 아닙니다. 새65/66 처리자나 신뢰할 보호 상태 재조회는 나오지 않았습니다.

## 설정 테이블 포인터의 공급자

4C74의 선택된 key를 추적해 SecMemoryInfo 4,736바이트/SHA-256 `9a89012eb665953d423046b50fcf9103d449230e5f31fa49c899c5279a67afbc`의 구성 테이블 게시와 연결했습니다. key의 정확한 바이트와 실제 lookup·게시·buffer lineage를 대조했으며 모듈 이름만으로 역할을 정하지 않았습니다.

이 정상 소스 경로는 기존 테이블을 재사용하거나25바이트 버퍼를 할당·초기화한 뒤 게시합니다. provider는 그 데이터 포인터를 보관하거나 별도25바이트 fallback을 준비합니다. SABI 관리 객체를 게시하거나 새 배터리 callback을 등록하는 경로로 연결되지는 않았습니다. 다른 런타임 producer·오염된 테이블·임의 별칭의 부재를 전역적으로 증명한 것은 아닙니다.

## 공개 삭제 함수와 실제 호출자 구분

provider와 기존 외부 소비자4개에서 interface+8 삭제 함수의 직접 호출·함수 포인터 복사 후보를 대조했습니다. 새 typed SABI 삭제 호출이나65/66 삭제 descriptor는 복구하지 못했습니다. 같은 offset의 다른 프로토콜 호출을 삭제 함수로 세지 않았습니다.

지난 단계에서 확인한 것은 **삭제 API가 슬롯을 지울 수 있다는 사실**입니다. 실제 노트북에서65가 삭제됐거나 이것이 과거FF의 원인이라는 증거는 없습니다. 계산·보존된 별칭, 불투명 callback, 다른 외부 모듈과 런타임 삭제 여부는 남습니다.

## 레거시 중계의 다른 분기

SecLagacySabi 5,920바이트/SHA-256 `446360f3bea7cb7f6af8331f83ca183ca3316cf26592235931e61b7147c2a961`의 선택된 전체 callback을 대조했습니다. **외부 selector80/81/82는 프레임 안의5843/sub 번호와 다른 이름공간**입니다.

- 외부80 분기는 구성 I/O 값을 보존하고 일부 비트를 변경해 쓴 뒤 프레임 main/sub와 data+5..+24를 지웁니다. 이 clear 루프는 ACK+4를 쓰지 않습니다.
- 외부81은 기존과 같은 SABI interface+20으로 프레임을 전달합니다.
- 외부82는 앞서 보존한 바이트를 I/O로 다시 씁니다.

선택한 보조 함수의 IN/OUT까지 데이터로 확인했으며 실행하지 않았습니다. 이 분기들을 읽기 전용 보호 설정 조회로 사용할 계약은 없습니다. 현재 Windows의 native Sabi3 드라이버가 실제로 이 순서를 사용한다는 증명도 아니며, 다른 모든 펌웨어 진입점을 닫았다는 뜻도 아닙니다.

## SSDT의 실제 공개 수집본 대응과 ECMD

고정 공개 수집본의 SSDT4개는 캡슐의 Cpu0Ist·CpuPm·SataTabl·IsctTabl과 대응합니다. 정확한 원본·표 길이·checksum·메서드 경계를 대조했고, **MethodOp 패킷54쌍은 원시 바이트가 같습니다.** 54는 패킷 정의 쌍의 수이며 고유 이름이나 도달 가능한 메서드 수가 아닙니다.

전체 표의 차이는 각각227/35/0/7바이트입니다. CPU `_PSS`의 길이·개수·데이터도 달라 단순 주소 패치나 전체 동작 동일성으로 표현할 수 없습니다. 공개4개가 있다고 캡슐의 SSDT15개 전체 선택 또는 현재 사용자 namespace를 입증한 것도 아닙니다.

**ECMD 호출은 공개 IsctTabl에도 있습니다.** 따라서 캡슐에만 남은 미선택 템플릿이라고 제외하지 않습니다. 다만 확인한 두 caller는 조건부로 비트·외부 객체를 변경한 뒤 호출하며, ECMD 반환이나 보호 상태 재조회를 검사하지 않습니다. 이름이 비슷한 getter들은 ECMD를 호출하지 않습니다. ECMD의 본문·실제 namespace 결합·전체 효과는 여전히 미해결이지만, 읽기 전용 보호 조회나 대체 배터리 명령으로 실행할 근거도 없습니다.

## 구현 판단과 재개 조건

이번에 확인한 직접 경로에서는 보호 설정 조회를 구현할 새 handler·응답 의미·재조회 계약이 나오지 않았습니다. 현재 자료만으로 실행 경로를 추가할 검증된 지점은 없습니다. **충전 제한은 계속 Unsupported이며, 하드웨어의 영구 미지원을 입증한 것은 아닙니다.**

실제 기능 개발의 다음 착수 조건은 현재 모델·BIOS에서 사용 가능한 배터리 처리자 또는 이에 상응하는 제조사 근거를 확보하는 것입니다. 기존 후보·SSDT·첫FF를 반복 분석한 것만으로 이 조건을 충족했다고 보고하지 않습니다. 검토한 I/O helper·외부 selector·ECMD를 대신 실행하거나 새0B/65 시험으로 공백을 채우지 않습니다.

후속으로 같은 모델 계열의 실제 P04ACJ 원본을 확보한 [P04/P05 비교](P04_P05_FIRMWARE_COMPARISON.md)를 완료했습니다. 이는 새로운 과거 버전 자료의 검토이며, 선택된 경로에서 현재 보호 조회·제어 계약은 추가로 확보하지 못했습니다.

정적 source pin·선택된 기계어·메서드 패킷과 독립 검토 결과는 [검사 기록](reports/remaining-query-paths-audit.json)에 요약했습니다. 문서 링크·차이·개인정보/원본 제외도 검사했습니다. 앱·테스트 코드·EXE·기존 ZIP은 미변경이며 빌드·단위 테스트는 이번에 반복하지 않았습니다. C#436/Python85·빌드 경고/오류0은 직전 코드 변경의 검증 기록입니다.

기존 프로그램을 그대로 사용합니다. 새 실행 파일·개발 소스 ZIP·노트북 시험·자료 재제출은 필요하지 않습니다. 기존 원본과 분석 기록도 보존합니다.
