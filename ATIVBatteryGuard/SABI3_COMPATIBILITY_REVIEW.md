# 실제 Sabi3 식별 결과와 연동 준비 — 2026-11-01

**2026-11-05 해석 정정:** [Windows caller 대조와 코드 수정](WINDOWS_CALLER_CONTRACT_UPDATE.md)에 따라 native11 순수 디코더는0/1/FF를 보호 OFF/ON·미지원으로 해석하지 않습니다. API/길이 검사와 opaque 표식만 분리하고 보호/상한은null, 하드웨어 권한은false입니다. 당시 디코더는 실제 앱·어댑터에서 참조하지 않았습니다. 아래는 이전 단계의 파일 식별/준비 기록이며 현재 모델의 배터리 의미 계약으로 적용하지 않습니다.

## 사용자 TXT에서 확인한 사실

`samsung-files-20261101T105906` 결과에서 네 대상 파일을 모두 찾았습니다. 전체 범위에는 제한이 있었지만 기록된 9개 파일 항목은 정보 확인을 완료했습니다. 실제 위치 구분은 `Settings 하위 폴더`입니다. 원본 TXT와 삼성 바이너리는 저장소·배포에 포함하지 않습니다.

| 대상 | 실제 관측 | 현재 판단 |
| --- | --- | --- |
| Sabi3.dll | 버전 3, 2, 0, 0, x64 및 x86 각 1종 | 현재 x64 앱과 같은 구조의 후보 확보. 실제 호출 계약과 초기화는 별도 미검증 |
| wsabi.dll | 1.0.0.0 / 1.0.0.3, x86 / x64, 서로 다른 해시 4종과 중복 관측 1건 | 버전·파일 크기만으로 동일 파일이나 대체 DLL로 취급하지 않음 |
| BatteryToast.exe | 1.0.0.1, x86 네이티브. WinRT 관련 DLL 참조 | 배터리 알림이라는 추정에 맞는 단서이나 실제 동작·제어 기능은 미확인 |
| PowerAudit.exe | 2.2.0.0, x86 네이티브. POWRPROF.dll 참조 | Windows 전원 API 연결 단서이며 충전 상한 제어 증거는 아님 |

Sabi3 x64의 SHA-256은 `09a9714f0e11734872d60f2966edf8590ca721f0c05b2ca852a0bf20d6c006ae`, x86은 `d8ac306fa192d1d41591d0c846f1b0dfdfd4c2465752a671797ace2e6d824d3a`입니다. 두 파일 모두 공개 예제의 `InitBIOSInterface`, `UninitBIOSInterface`, `CheckSamsung`, `CallBIOSInterface`, `CallBIOSInterfaceEx` 이름이 있습니다.

Settings EXE가 x86이라는 이유만으로 x86 보조 앱을 만들 필요는 없습니다. x64 DLL 후보가 있으므로 현재 x64 앱 기준의 구조 검토가 가능합니다. 해당 DLL의 `MSVCR90.dll` 의존성과 SABI 드라이버의 실제 제공·접근 가능성은 아직 확인되지 않았습니다. 의존 DLL 이름만으로 런타임 해결을 단정하거나 인터넷에서 DLL을 받아 넣지 않습니다.

현재 x86 wsabi 1.0.0.3의 `b68452579a3f5f898ad8ccf63d655aed62c5be221784b799cdf471da674fbdcc`는 이전 정적 분석 파일 `564b640d62db2a4e4b56c6331e0e526bad2ac1fcf438a41a9e5241551f457b6e`와 다릅니다. 크기가 22,920바이트로 같아도 이전 분석의 동작을 그대로 적용하지 않습니다.

## 이번 구현

1. 표준 PE import lookup table을 실제로 읽어 **DLL 이름과 함수 이름 또는 ordinal**을 함께 분석합니다. x86/x64, 이름 참조·번호 참조, 원래 lookup table이 없는 경우를 구분하고 잘못된 주소·문자열·종료 누락은 실패 처리합니다.
2. 파일별 최대 256개 함수 참조를 표시하고 드라이버·파일·서비스·동적 로드 관련 API 이름의 정적 관측을 따로 표시합니다. 참조를 실제 실행으로 취급하지 않습니다.
3. Sabi3 후보를 네이티브 x64/x86 및 SHA-256으로 구분합니다. 중복 파일은 같은 후보로 세며 다른 x64 파일이 여러 개면 자동 선택하지 않습니다. 조회가 제한되면 전체 유일성·부재를 확정하지 않습니다.
4. 후보·예상 함수 이름이 있어도 실제 하드웨어 읽기/쓰기 권한은 항상 false입니다. 공개 래퍼의 함수 선언과 현재 DLL의 공식 ABI 검증은 다릅니다.
5. 함수 정보가 보조 프로세스 결과에서 사라지지 않도록 IPC 버전 2를 추가했습니다. 최대 2 MiB, 함수 배열 256개, 문자열 128자, 깊이·필수 필드·중복 검사를 적용하며 이전 버전은 혼합 해석하지 않습니다.

새 ZIP에서 기존 **삼성 파일 정보 만들기**를 선택하면 추가 정보가 포함된 새 `samsung-files-*.txt`가 생성됩니다. 기존 TXT를 다시 보내거나 삼성 파일을 옮길 필요는 없습니다. 이번 추가 함수 참조의 Windows 실기 실행은 아직 미검증입니다.

## 실제 조회 전 남은 조건

[공개 C# 래퍼](https://github.com/akastormseeker/samsung-hotkeys/blob/0d3947eea0003dd8e9372c36925c0fd0a8fd28d3/SamsungHotkeys/Controls/SamsungBIOSInterface.cs)의 Cdecl 선언은 Windows x64 호출 구성의 참고가 됩니다. 그러나 DLL 로드 시의 DllMain, InitBIOSInterface와 CheckSamsung 내부 동작, 현재 모델·BIOS의 지원은 이 TXT로 확인할 수 없습니다. 메타데이터를 근거로 OEM 초기화 함수를 실행하지 않습니다.

향후 보호 설정 조회에서는 API 오류, 응답 0·1·0xFF·기타를 구분해야 합니다. 공개 래퍼처럼 미지원을 OFF로 합치지 않습니다. 보호 ON을 읽더라도 현재 BIOS의 상한이 정확히 80%라는 증거 없이 Protection80으로 바꾸지 않습니다. ReadIo/WriteIo 계열은 배터리 어댑터 호출 대상에 포함하지 않습니다.

이번 결과로 DLL 식별 단계를 마쳤고 초기화·드라이버 연결 분석으로 범위를 좁혔습니다. 실제 충전 제어는 계속 미지원입니다. 자동 테스트와 빌드 결과는 [검증 기록](VALIDATION.md)을 참고하세요.
