# 삼성 파일 정보 확인 기능

새 [삼성 WMI 인스턴스 섹션](SAMSUNG_WMI_INSTANCE_INSPECTION.md)에서 두 고정 클래스의 Active/version 속성만 읽습니다. 클래스별 정상 0개·클래스 부재·오류·시간 초과를 구분하고 여러 행을 자동 선택하거나 서로 연결하지 않습니다. 메타데이터 전용 검사와는 별도 정책이며 OEM 메서드는 실행하지 않습니다.

현재 결과에는 [삼성/SABI 커널 드라이버 등록·실행 상태·시작 방식](SAMSUNG_KERNEL_DRIVER_INSPECTION.md)도 함께 표시합니다. SABI 연결 이름과 비교하되 정상 조회에서 후보 미관측인 경우와 오류·시간 초과를 구분합니다. 원래 서비스 이름·표시 이름·경로·식별자는 내보내지 않습니다. 삼성 DLL 초기화·서비스 변경·OEM 명령은 하지 않습니다.

2026-11-01 개발 기준입니다. 사용자 TXT로 기존 식별 기능의 노트북 동작을 확인했고, 현재는 실제 import 함수 참조와 Sabi3 후보 판정을 추가했습니다. [현재 결과와 구현 범위](SABI3_COMPATIBILITY_REVIEW.md)를 참고하세요. 실제 충전 제어는 계속 미지원입니다.

제공받은 x64 DLL의 [실제 버퍼 규약 분석](SABI3_NATIVE_ABI_REVIEW.md)을 반영해 현재 결과에는 QueryDosDevice로 읽는 **SABI 장치 연결 이름**도 포함합니다. 이는 Windows 이름 테이블 조회만 하며 DLL·장치·드라이버 명령을 실행하지 않습니다.

후속 `samsung-files-20261101T132149`에서 실제 Windows의 NotFound 관측을 받았습니다. 분석된 정확한 x64 해시에 한정해 이 선행 조건을 설명하도록 코드를 보완했습니다. [결과 해석과 다음 경로](SABI_LINK_RESULT_AND_WMI_REVIEW.md)를 참고하세요. 이번 소스 변경 때문에 같은 파일을 다시 생성할 필요는 없습니다.

## 사용 방법

새 ZIP을 모두 압축 해제하고 ATIVBatteryGuard.exe를 실행합니다. 창 아래쪽 **삼성 파일 정보 확인 → 삼성 파일 정보 만들기**를 누릅니다. **정보 파일 위치 열기**에서 `samsung-files-`로 시작하는 새 TXT를 확인할 수 있습니다. 후속 분석에는 그 TXT를 사용하며 삼성 DLL·EXE나 폴더 전체를 전달할 필요는 없습니다.

이 버튼을 선택했을 때만 확인하며 앱 시작과 10초마다의 배터리 표시에서는 실행하지 않습니다. 실패 결과도 파일별 상태로 표시하고 실제 제어 지원으로 바꾸지 않습니다. 저장만 실패하면 관측 결과는 화면에 유지합니다.

## 범위와 정보

- 실제 Windows Program Files (x86) 아래의 `Samsung\Setting`, `Samsung\Settings` 두 위치만 확인합니다. 사용자 제공 단수 경로와 알려진 복수 경로를 함께 제한합니다.
- 대상은 `Sabi3.dll`, `wsabi.dll`, `BatteryToast.exe`, `PowerAudit.exe`입니다. 이름 비교는 대소문자를 구분하지 않습니다.
- 하위 깊이 2, 디렉터리 32개, 항목 512개, 결과 16개, 파일별 16 MiB, 읽는 파일 합계 64 MiB로 제한합니다. 한도나 누락을 표시하며 결과에 없는 파일을 설치되지 않았다고 단정하지 않습니다.
- 크기·SHA-256·버전·회사/설명·PE x86/x64 구조·관리 코드 표시·정적 DLL 참조·이름으로 내보낸 함수를 기록합니다. 회사/설명은 파일 표시 정보이며 게시자 신뢰의 증거가 아닙니다.
- 표준 PE import/export와 최대 256개 import 함수의 이름 또는 ordinal을 읽습니다. bound IAT만 있어 함수 이름을 복원할 수 없으면 제한으로 표시합니다. 지연·동적 로드, 관리 코드의 P/Invoke·어셈블리 참조, 프로세스 간 통신을 모두 분석한 결과는 아닙니다. 관리 PE의 x86 헤더만으로 실제 실행 비트 수를 확정하지 않습니다.

Sabi3.dll의 공개 예제 함수 이름과 일치하는 항목을 별도로 표시합니다. 함수 수 한도·이름 장식·이름 없는 export가 있어 표시된 목록의 부재가 절대적인 함수 부재는 아닙니다. 존재나 이름 일치도 ABI·지원 모델·실행 안전성을 확정하지 않습니다.

## 서명

WinVerifyTrust를 내장 Authenticode 서명에 사용합니다. UI 없음, 로컬 캐시만 사용, 온라인 폐기 확인 없음으로 제한합니다. 카탈로그 서명은 확인하지 않습니다.

- 성공: 로컬 캐시 기반 검증 성공이며 온라인 인증서 폐기 여부는 미확인
- 내장 서명 없음: 검증 가능한 내장 서명을 찾지 못함. 카탈로그 서명 여부는 별도 미확인
- 불일치: 해시 불일치나 로컬의 명시적인 불신·폐기 근거
- 확인 불가: 오프라인 신뢰 근거나 제공 상태가 부족해 판정할 수 없음

확인 불가를 변조나 무서명으로 바꾸지 않습니다. 서명 성공도 배터리 제어 지원 근거는 아닙니다.

## 실행과 결과 보호

자체 EXE의 별도 조회 모드만 실행하며 삼성 코드나 초기화·제어 함수를 실행하지 않습니다. 보조 프로세스에 10초 제한을 두고 종료 요청 후 최대 1초 추가 대기합니다. 종료가 지연되면 슬롯을 유지해 프로세스가 누적되지 않게 합니다. 앱 종료 시에도 저장된 자체 프로세스만 종료 요청합니다.

파일과 상위 디렉터리의 읽기 핸들을 유지하고 링크·최종 경로를 검사합니다. 일반 권한에서 경로나 핸들을 확인하지 못하면 결과를 제외하며 권한 상승을 요구하지 않습니다. 다른 프로그램이 쓰기/삭제 핸들을 유지하는 디렉터리도 확인 불가가 될 수 있습니다.

보조 결과는 LocalAppData의 고정 앱 폴더에 GUID 이름으로 새로 생성하며 덮어쓰지 않습니다. 최대 2 MiB의 버전 5 형식으로 필수 필드·열거형·항목 수·문자열·배열 한도를 검사합니다. 새 드라이버 결과는 최대 32개 enum 항목만 전달합니다. UTF-8·단일 JSON 객체·깊이·문자열 길이를 검사하고 알 수 없는 추가 필드는 보존하지 않습니다.

TXT에는 고정 파일명과 Setting/Settings/하위 폴더 구분만 남깁니다. 전체 경로·사용자 이름·시리얼번호·예외 원문·삼성 원본 파일은 내보내지 않으며 자동 전송하지 않습니다.

## 검증 한계

회귀 테스트는 실제 Core·ViewModel·PE 파서의 메타데이터 보호, 잘못된 응답, 최대 유효 결과, 실패·중복 요청·저장 실패·종료 처리를 확인합니다. 네이티브 소스와 x64 구조 크기는 별도로 검토합니다. 최신 수치는 [검증 기록](VALIDATION.md)에 기록합니다.

사용자 TXT에서 파일 식별·함수 참조·기존 준비 판정과 SABI 이름 조회의 NotFound 경로를 확인했습니다. 모든 오류·이름 존재 경로와 이번 선행 조건 설명의 화면 표시는 아직 실기 미검증이며 Linux 빌드·자동 검증이 이를 대신하지 않습니다.
