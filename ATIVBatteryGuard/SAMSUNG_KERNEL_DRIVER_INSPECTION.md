# 삼성/SABI 커널 드라이버 상태 조회

2026-11-02 한국 시간 기준입니다. 기준 소스는 `4492bbaa6f9cb87a9fb7c24969c6f1efcf6b6bd9`이며, 저장된 [SABI 이름 관측과 WMI 분석](SABI_LINK_RESULT_AND_WMI_REVIEW.md)을 이어서 구현했습니다. 같은 배터리 진단·파일 목록·삼성 DLL을 다시 제출할 필요가 없습니다.

## 구현 범위

기존 **삼성 파일 정보 만들기** 버튼의 자체 보조 프로세스가 로컬 `ROOT\CIMV2`의 `Win32_SystemDriver`를 읽습니다. `ServiceType = 'Kernel Driver'`인 등록에서 `Name`, `DisplayName`, `State`, `StartMode`, `ServiceType`만 조회합니다. `PathName`, 계정, 장치 식별자, 레지스트리 값은 조회하지 않습니다. `ROOT\WMI`의 OEM 메서드를 실행하는 기능이 아닙니다.

이름 또는 표시 이름에 `SABI`나 `Samsung`이 포함된 항목을 대소문자 구분 없이 후보로 분류합니다. 둘 다 있으면 SABI 분류를 사용합니다. 이 조건은 제조사나 SABI 기능을 확인하는 증거가 아닙니다. 다른 이름으로 등록된 삼성 드라이버, 파일 시스템 드라이버, 사용자 모드 서비스는 이 범위에서 빠질 수 있습니다. 이 조건에 맞는 항목이 없다는 이유로 드라이버 미설치나 배터리 보호 기능 부재를 확정하지 않습니다.

원래 서비스 이름·표시 이름은 일시적으로 분류할 때만 사용합니다. 보고서와 IPC에는 **SABI 이름 일치 / Samsung 이름 일치**라는 고정 분류, 실행 상태와 시작 방식 enum만 남습니다. 후보 번호는 이번 목록의 순번이며 장치 식별자나 재조회 간 동일성을 나타내지 않습니다. 전체 경로·사용자 이름·고유 식별자·예외 원문은 새 조회 결과에 포함하지 않습니다.

후보별로 **등록 관측**, 실행 상태(`Running`, `Stopped`, 각 대기 상태, `Paused`, `Unknown`), 시작 방식(`Boot`, `System`, `Auto`, `Manual`, `Disabled`, `Unknown`)을 같은 TXT와 화면에 표시합니다. 알 수 없는 상태를 실행 중·중지 상태로 추측하지 않습니다. 삼성 파일 폴더를 찾지 못해도 완료된 드라이버 조회 결과는 별도로 유지합니다.

## 결과 해석

| 드라이버 조회 결과 | 의미 |
| --- | --- |
| 정상 조회 완료 + 후보 있음 | 해당 조회 시점의 이름 조건에 맞는 커널 드라이버 등록을 관측함 |
| 정상 조회 완료 + 후보 없음 | 정상 완료한 제한 범위에서 후보 미관측. 미설치 판정 아님 |
| 일부 관측 또는 한도 도달 | 표시한 등록만 관측함. 누락 등록의 부재는 판단 불가 |
| 조회 권한 없음 | 일반 권한 조회가 거부됨. 관리자 실행이나 설치를 요구하지 않음 |
| 조회 시간 초과 | 완료된 결과 없음. 미관측이나 미지원으로 바꾸지 않음 |
| 조회 오류 / 응답 형식 확인 실패 | 결과 확인 불가. 이전 실행 중 관측을 유지하지 않음 |
| 아직 조회하지 않음 / Windows 전용 | 관측을 수행하지 않았거나 실행 플랫폼이 다름 |

**SABI 장치 연결 이름** 결과를 옆에 함께 표시하고 비교 설명을 제공합니다. 등록이 관측되면서 SABI 이름이 NotFound일 수 있고, 반대로 SABI 이름이 존재하면서 이름 조건에 맞는 등록이 없을 수도 있습니다. 목록과 이름 테이블은 조회 범위·시점이 다르며, 후보가 그 연결을 제공하는지도 확인되지 않았습니다. 등록·실행 중·자동 시작이라는 사실은 DLL 초기화 성공, 장치 접근, 배터리 제어 가능성의 증거가 아닙니다.

## 제한과 쓰기 차단

WMI 연결·열거에 2초 제한, 협력적 전체 조회에 3초 제한, 최대 1,024행·32개 후보·필드당 256자 제한을 사용합니다. 네이티브 WMI가 제한을 따르지 않거나 이후 파일 검사에서 지연되면 기존 부모 프로세스가 전체 작업의 10초 제한을 적용합니다. 종료 요청 후 최대 1초 추가 대기하며, 종료 지연 시 새 프로세스를 누적 생성하지 않습니다. 전체 보조 프로세스가 실패하면 전달받지 못한 중간 결과를 복원하거나 추측하지 않습니다.

읽기 전용 조회는 앱 시작이나 주기적 배터리 표시에 추가하지 않았습니다. 로컬 IPC는 필수 드라이버 필드가 있는 버전 4로 갱신했고, 잘못된 enum·필수 필드 누락·항목 수 초과·실패 상태에 붙은 관측 행을 거부합니다. 오류나 시간 초과에서는 이전 관측을 지웁니다.

드라이버 설치·등록·시작·중지·시작 방식 변경, 장치 열기, 삼성 DLL 초기화, OEM 명령, 펌웨어 쓰기는 하지 않습니다. `UnsupportedChargeLimitController`와 실제 제어 버튼 비활성화는 유지합니다. 배터리 측정값·사용자 희망 모드·실제 보호 상태도 계속 분리합니다.

## 이번 검증과 실제 노트북 확인 항목

현재 클라우드 Linux에서 공유 Core·ViewModel 테스트 **204개 통과, 실패·건너뜀 0개**, .NET Framework 4.8 x64 WPF/XAML 빌드 **경고·오류 0개**를 확인했습니다. 새 13개 그룹은 후보 분류·상태·시작 방식·제한·개인정보·IPC·SABI 비교·기존 화면/저장 경로·오류 후 이전 결과 제거를 검사합니다. Windows WMI 제공자나 실제 노트북에서 새 조회를 실행한 결과는 아닙니다.

새 개발판을 Windows 10 x64 노트북에서 확인할 때는 일반 권한으로 다음 항목만 확인하면 됩니다. 이전 자료나 원본 DLL을 다시 제출할 필요는 없습니다.

1. 기존 **삼성 파일 정보 만들기**를 한 번 실행해 화면과 새 로컬 TXT에 드라이버 조회 결과가 함께 나타나는지 확인합니다. 테스트를 위해 서비스나 드라이버 상태를 변경하지 않습니다.
2. 조회 완료/후보 미관측과 오류·시간 초과가 구분되는지, 관측된 후보에는 등록·실행 상태·시작 방식이 표시되는지 확인합니다. 정상 완료 여부가 불명확한 결과는 미설치로 해석하지 않습니다.
3. 같은 TXT의 SABI 이름 조회 결과와 비교 문장을 확인합니다. 이전 NotFound와 다른 결과가 나와도 설치·배터리 기능 지원 결론으로 바꾸지 않습니다.
4. 전체 경로·사용자 이름·장치 식별자·원래 서비스 이름이 새 드라이버 섹션에 없는지, 실제 충전 제어가 계속 미지원인지 확인합니다.

Windows GUI 렌더링·권한 거부·시간 초과의 실기 재현, 실제 제공자 열거 결과는 아직 미검증입니다. 의도적으로 드라이버를 시작·중지하거나 Windows 보안 설정을 바꿔 재현하지 않습니다. 실행용 개발 미리보기를 만드는 경우 자체 앱 EXE/Core DLL/설정만 포함하며 삼성 원본 DLL은 포함하지 않습니다.
