# 삼성 WMI 인스턴스·버전·활성 속성 확인

2026-11-02 한국 시간 기준입니다. [기존 wsabi 정적 분석](SABI_LINK_RESULT_AND_WMI_REVIEW.md)에서 확인한 별도 WMI 경로의 다음 준비 단계입니다. 이전 커널 드라이버 확인판은 사용자가 실제 노트북에서 실행하고 TXT를 만들었다고 확인했습니다. TXT 내용은 전달받지 않았으므로 드라이버 조회 성공이나 Running 상태를 확인한 것으로 기록하지 않습니다.

## 이번에 구현한 범위

기존 **삼성 파일 정보 만들기** 버튼에서 로컬 Windows WMI 제공자의 다음 속성만 읽습니다.

| 네임스페이스 | 클래스 | 조회 속성 |
| --- | --- | --- |
| ROOT\WMI | WmiAcpiVersion | Active(Boolean), version(UInt32) |
| ROOT\WMI | WmiAcpiMethod | Active(Boolean) |

저장된 노트북 스키마에 근거한 고정 조회입니다. 인스턴스·속성 값 읽기는 클래스 정의만 읽는 작업보다 범위가 넓으며 WMI 제공자가 실행됩니다. 앱에서 OEM 메서드를 실행하는 것은 아닙니다. 기존 WindowsWmiSchemaSource와 WmiSchemaPolicy는 그대로 클래스 메타데이터 전용으로 유지하고 별도 SamsungWmiInstancePolicy로 새 범위를 제한합니다.

InstanceName, 개체 경로, 키, 시리얼번호, 사용자 이름, 고유 식별자, DataBuffer 내용은 조회하거나 보고하지 않습니다. SELECT *, 원격 WMI, 삼성 DLL 로드·초기화, CallSabiFunction, 다른 OEM 메서드, 드라이버·서비스 변경, 펌웨어 쓰기를 추가하지 않았습니다. 기존 worker에서 명시적 버튼을 선택했을 때만 실행하며 앱 시작·배터리 갱신에서는 실행하지 않습니다.

## 보고서와 해석

두 클래스의 조회 상태를 독립적으로 표시합니다. 정상 조회에서 인스턴스가 0개인 경우와 클래스 없음, 네임스페이스 없음, 권한 거부, 시간 초과, 조회 오류, 일부 관측, 잘못된 응답을 구분합니다. 한 클래스의 실패를 다른 클래스의 성공으로 덮지 않습니다. 완료된 파일/드라이버 결과는 WMI의 개별 실패만으로 지우지 않지만 전체 worker가 실패하면 전달받지 못한 중간 관측을 추측하지 않습니다.

각 인스턴스는 보고서 안에서만 쓰는 순번과 Active=True/False/Unknown, 버전 클래스의 version 원값을 10진수·8자리 16진수로 표시합니다. 실제 WMI 값이 Boolean/UInt32가 아니거나 누락되면 해당 값은 Unknown, 클래스 결과는 일부 관측으로 남습니다. 문자열이나 다른 정수형으로부터 값을 추측해 변환하지 않습니다. 0은 관측 가능한 버전 값이며 미지원 코드로 해석하지 않습니다.

**Active=True는 배터리 보호 ON이 아닙니다.** 버전 값의 비트 의미·모델 호환성·배터리 명령 지원도 아직 확인되지 않았습니다. 여러 인스턴스가 있어도 하나를 자동 선택하거나 두 클래스의 행을 서로 연결하지 않습니다. 서로 다른 조회 범위인 SABI 이름·커널 드라이버 목록과 함께 보되, 어느 결과도 충전 제어 지원으로 승격하지 않습니다. 실제 제어와 쓰기 경로는 계속 Unsupported입니다.

## 제한·응답 보호

클래스당 최대 8개를 기록하고 9번째 항목은 잘림 확인에만 사용합니다. 각 연결·열거에 최대 2초, 두 클래스 전체에 협력적 4초 제한을 적용합니다. 기존 커널 드라이버 조회·파일 검사와 합친 자체 보조 프로세스의 10초 강제 제한도 유지합니다. 종료 요청 후 대기는 기존 최대 1초이며, WMI가 내부 제한을 따르지 않더라도 새 프로세스가 누적 생성되지 않게 합니다.

IPC는 버전 5입니다. 두 고정 클래스의 필수 필드, enum, nullable Boolean/UInt32, 항목 한도, 실패+관측 행 모순, 메서드 클래스에 잘못 붙은 버전, 정상 완료에 붙은 알 수 없는 필수 값을 검사합니다. JSON 문자열을 Boolean/숫자로 자동 변환하는 동작도 거부합니다. 이전 버전 응답은 추측해 사용하지 않고, 알 수 없는 추가 필드는 보존하지 않습니다.

## 검증과 다음 확인

현재 환경에서 전체 공유 소스 테스트 **217개 통과·실패/건너뜀 0개**, 별도 Python 배포 검증 **6개 통과**, x64 net48 WPF/XAML 빌드 **경고·오류 0개**를 확인했습니다. 새 13개 그룹은 고정 범위, 엄격한 값 형식, 클래스별 결과, 부분/실패/미관측, 다중 행, 한도·불변 복사, 잘못된 IPC, 개인정보 제거와 기존 화면·저장 경로의 제어 차단을 검사합니다.

이번 WMI 인스턴스 조회의 실제 Windows 제공자 결과와 새 GUI의 실기 실행은 아직 미검증입니다. 이전 개발판 실행 확인은 새 조회 성공을 대신하지 않습니다.

노트북에서 새 개발판을 선택적으로 확인할 때는 일반 권한으로 **삼성 파일 정보 만들기**를 한 번 실행하고 새 **삼성 WMI 인스턴스** 섹션의 클래스별 상태와 Active/version 표시를 확인하면 됩니다. 드라이버·서비스·보안 설정을 바꾸거나 삼성 DLL을 별도로 준비할 필요는 없습니다. 기존 진단·TXT·삼성 DLL·EXE의 재제출은 요구하지 않습니다.

다음 실제 상태 읽기/제어 단계에는 현재 모델에 맞는 명령 의미·안전 범위·입출력 계약의 검증이 필요합니다. 이 단계의 속성값만으로 공개 명령 후보를 실행하지 않습니다. 새 실행 ZIP에는 자체 EXE/Core DLL/설정과 안내·검증 정보만 포함하며 삼성 원본 바이너리는 포함하지 않습니다.
