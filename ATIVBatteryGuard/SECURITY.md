# 보안과 권한 경계 — 0.2.9

2026-11-25 한국 시간. 현재 수동 충전 제어·관찰·기록·메모·묶음 이동 기능에 적용합니다. 이전 ‘제어 미지원’ 단계의 설명은 당시 개발 기록이며 현재 구현의 설명으로 사용하지 않습니다. 이번 변경과 확인 근거는 [0.2.8 품질 검토](QUALITY_028.md), 실행 범위는 [검증 계획](TEST_PLAN.md)을 참고합니다.

0.2.9는 표시 모델을 940X3G로 정리하고 사용자 GUI에서 희망값/시뮬레이션/과거 실험 화면을 제외했습니다. 내부 원본 장치 식별값과 실제 검증 코드는 유지합니다. 변경과 기능 분류는 [사용자 화면 정리](USABILITY_029.md)를 참고합니다.

## 장치 제어와 일반 화면

일반 GUI는 asInvoker로 실행합니다. 현재 배터리의 GetSystemPowerStatus 조회와 관찰·과거 그래프·메모·묶음 불러오기는 관리자 권한을 요청하지 않습니다. 과거 기록과 메모는 현재 하드웨어 상태·제어 권한·모델 적합성 판단의 입력으로 사용하지 않습니다. 원하는 모드, 장치의 마지막 조회 결과, Windows 잔량과 충전 상태는 별도 데이터입니다.

현재 설정 확인·80% 보호 켜기·보호 해제 버튼의 명시적 요청만 고정 helper를 runas로 실행합니다. helper에는 제한된 작업 종류와 상관 토큰만 전달하며 경로·임의 명령·임계값을 입력하지 않습니다. helper는 관리자 실행 여부·자체 확인 창·모델/BIOS profile·기존 작업 임대와 사전 조건을 확인합니다. 승인된 940X3G·P05ACJ 범위의 조회/켜기/해제는 각각 최대 3/7/3 SDK 진입이며 설정은 요청당 최대 1회입니다. 지원 범위와 새 조회가 불명확하면 쓰기를 차단합니다.

GUI 서버의 로컬 파이프 ACL은 현재 계정으로 제한하고 Network SID를 거부합니다. helper는 `.` 서버와 Identification 수준으로 연결합니다. nonce/job 값은 연결 상관관계이며 장치 인증이나 신뢰할 수 없는 같은 계정 프로그램에 대한 완전한 보안 경계가 아닙니다. 실제 호출·자원 정리 완료, 결과 승인·해제 절차를 유지합니다. 시간 초과·통신 손실을 정상 완료로 취급하지 않으며 자동 재시도·역설정·강제 프로세스 종료를 제품 흐름에 추가하지 않습니다.

미지원 기본 어댑터와 Mock은 실제 펌웨어 쓰기를 수행하지 않습니다. 새로운 드라이버·서비스·자동 실행·작업 스케줄러·보안 정책·서명 우회·포트 I/O·메모리 패치·BIOS 플래시를 설치하거나 구현하지 않습니다. 기존 충전 효과와 Windows 재시작 후 유지의 사용자 확인은 해당 모델의 과거 근거로 기록하며 새 클라우드 실행 결과로 표현하지 않습니다.

## 파일 입력과 저장

외부 관찰 TXT는 UTF-8, 256 KiB, 721표본, 2시간, 시간 순서·값·상태·요약을 검증합니다. 메모는 최대 1000 UTF-16 코드 단위와 일반 텍스트·줄바꿈·탭을 지원하며 잘못된 UTF-16과 제어 문자를 거부합니다. 메모 파일은 16 KiB, 최근 목록과 설정은 각각 64 KiB로 제한합니다.

`.ativrecord` 버전 1은 최대 2 MiB의 단일 UTF-8 JSON입니다. 형식·필수 필드·버전·내용 해시·파일명·TXT·메모를 검사합니다. 설정·메모·최근 목록·묶음은 공통 JSON 판독기로 문서 뒤 추가 내용, 잘린 문서, 중복 필수 필드, 잘못된 UTF-8과 깊이 8 초과를 거부합니다. 기존 UTF-8 BOM과 JSON 공백은 지원합니다. JSON 내용으로 실행 파일·어셈블리·파일 경로를 선택하거나 압축 항목을 추출하지 않습니다.

로컬 파일 정책은 UNC/URL/장치 경로·스트림·예약 이름·Windows의 끝 공백/점 별칭·리파스 경로를 차단합니다. 원래 경로 문자열에서 네트워크 접두사를 먼저 검사합니다. 경로를 정규화한 뒤 네트워크 접두사를 잃는 경우도 막습니다. Windows 드라이브는 로컬 고정·이동식·RAM으로 제한합니다. 경로 검사는 파일 열기와 이동·교체 직전에도 적용합니다.

메모와 최근 목록은 앱 간 파일 잠금, 메모는 수정 버전 확인, 임시 파일 flush와 원자적 교체를 사용합니다. 설정도 파일 잠금과 읽은 바이트의 SHA-256 수정 버전으로 오래된 창의 덮어쓰기를 막습니다. 잠금/권한 문제로 저장할 수 없어도 유효한 기존 설정은 읽기 전용으로 표시하며, 손상 파일 복구는 잠금 안에서만 수행합니다. 최신 설정은 명시적 다시 읽기/앱 재실행 후 저장합니다. 손상·미지원 메모와 최근 목록은 원본을 유지합니다. 손상 설정은 원본 바이트를 별도 파일로 보관한 뒤 기본값을 사용합니다.

묶음 내보내기는 새 파일만 생성하며 기존 대상을 덮어쓰지 않습니다. 현재 표시한 TXT 원문과 메모 초안을 복사하고 로컬 메모의 미저장 상태를 유지합니다. 불러오기는 새 고유 폴더에 TXT를 준비하고 새 위치의 메모 저장 후 폴더를 게시합니다. 준비 전에 `import-recovery.ativrecord`를 flush합니다. 처리 가능한 실패는 해당 작업의 자료와 수정 버전만 되돌리고, 복원 작업의 잠금으로 다른 창에서 진행 중인 복원을 중단 자료와 구분합니다. 강제 종료 등으로 남은 복구 자료는 자동 삭제하지 않습니다. 현재 기록을 교체하는 확인에서 취소·실패하면 기존 그래프와 초안을 보존합니다.

이 잠금은 같은 규약을 사용하는 앱 창 사이의 충돌 방지입니다. 악의적인 동일 계정 프로세스의 경로 변경·하드링크·파일 교체를 완전히 격리하는 파일 시스템 보안 장치는 아닙니다. 경로 검사와 실제 파일 작업 사이의 경쟁을 모두 제거했다고 주장하지 않습니다. 여러 파일을 함께 쓰는 복원과 장치 캐시의 전원 차단까지 하나의 원자적 트랜잭션으로 보증하지 않습니다. 원본 묶음을 유지하고 중단된 복구본을 검증해 새 위치로 다시 불러올 수 있습니다.

## 네트워크와 개인정보

제품의 실행 중 로그인·원격 오류전송·업데이트 확인·telemetry·웹뷰·CDN·HTTP 클라이언트를 사용하지 않는 정책을 유지합니다. 현재 제품 소스 경로와 컴파일 참조의 정적 검토에서 새 네트워크 클라이언트를 추가하지 않았습니다. Linux 빌드/portable 검증은 Windows의 실제 네트워크 통신 0건을 관측한 결과가 아닙니다. Windows 실행 중 통신 검증은 별도 확인 항목입니다.

로그에는 허용한 고정 이벤트 코드와 시각만 기록합니다. 0.2.8은 기존 수동 제어·관찰 오류 코드가 UNRECOGNIZED_EVENT로 뭉개지던 문제를 수정했습니다. 임의 문자열·메모·경로·계정·SID·상관 토큰은 로그 본문으로 저장하지 않습니다. 로컬 최근 목록에는 파일 재열기에 필요한 전체 경로가 들어가며, 묶음에는 그 경로와 로컬 메모 키를 포함하지 않습니다.

묶음의 TXT 본문·메모·파일명은 사용자가 작성한 내용을 포함합니다. 자동 업로드하지 않으며, 공유 전에 내용을 확인할 수 있습니다. SHA-256과 화면의 짧은 기록 구분 표시는 손상 확인과 화면 식별용입니다. 작성자 인증·전자서명·암호화·익명성을 제공하지 않습니다.

삼성 파일의 제한된 정보 확인은 명시적 진단 요청에서 수행합니다. 현재 앱 프로젝트는 SamsungAnalysisBundleService와 SamsungSettingsLocator를 컴파일 제외하고 시작 구성에 수집 서비스를 연결하지 않습니다. 자체 배포 ZIP에는 삼성 모듈·사용자 진단 ZIP·개인 기록·펌웨어·PDB·과거 단발 실행 도구를 포함하지 않습니다.

## 배포 검증과 남은 확인

현재 0.3.0-rc.2 ZIP은 디지털 서명이 없는 개발 검증 배포본입니다. 구성 파일·GUI 버전·빌드 바이트·SHA-256·CRC·관리자 실행 manifest와 기존 수동 제어 경계를 패키지 검증기로 확인합니다. 해시가 일치하는 것만으로 배포자의 진위나 악성 코드 부재를 인증하지 않습니다.

별도 서명된 배포 검증 경로의 release_validation.py는 동일 서명자 Authenticode와 정확한 파일의 최신 Windows Defender 검사 기록을 요구합니다. 이번 Linux 환경에서는 그 서명·Defender 검사와 Windows GUI/IME/고배율/전원 차단 시험을 수행하지 않았습니다. 서명 인증서와 Windows 검사 실행은 확인이 필요한 배포 의존성으로 기록합니다. 보안 기능을 끄거나 예외를 추가해 검증을 통과시키지 않습니다.

## 0.3.0 서명 검증 범위 보강 — 2026-11-25

Windows 서명 후 검사 스크립트는 현재 프로그램6파일을 확인하며 EXE/DLL4개(GUI/Core/WMI/helper) 모두 동일한 유효 배포자 서명을 요구합니다. Python 증거 판정도 전달된 모든 PE의 서명을 검사합니다. 서명 누락·다른 게시자·파일 변경을 거부하는9개 회귀가 통과했으나 실제 서명이나 Defender 실행 결과는 아닙니다. 별도 검증 도구를 최종 배포에 넣으면 해당 EXE도 별도 서명/검증해야 합니다. 타임스탬프·최종 바이트 재검사와 정식 패키징 증거 연결은 [서명 배포 준비](RELEASE_030_SIGNING_READINESS.md)에 기록합니다.
