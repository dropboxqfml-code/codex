# 검증 계획과 결과 — 0.3.0 실사용 검증 진행 중

현재 후보는 0.3.0-rc.2입니다. [현황](VALIDATION_030.md), [RC1 실사용 결과](FIELD_030_RC1_RESULT.md), [이번 확인 순서](VALIDATION_030_USER_STEPS.txt)가 현재 지침입니다. RC1은 파일 검사 통과/GUI 선택 유지 실패이며 사용자 수동 확인은 별도 기록했습니다. 목록 갱신 시 양방향 선택 초기화 재현 회귀는 수정 전 1실패, 수정 후 전체 1252통과·실패/skip0입니다. Portable/전체 WPF/별도 검증 도구 빌드는 경고/오류0이고 배포 조건 회귀6개도 통과했습니다.

이번에는 Windows에서 RC2 검증시작.cmd 자동 검사만 다시 실행합니다. 기존 실패 조건은 유지합니다. 화면 디자인/충전 제어는 보존했고 이미 확인한 수동 사용과 충전·재시작 유지 시험은 반복하지 않습니다. RC2의 실제 Windows GUI·Defender는 Linux에서 미실행입니다. 사용자의 RC1 수동 Defender 특이사항 없음 보고와 미서명 첫 실행 경고를 분리해 기록합니다. 자동 도구는 수동 확인·보안 검사·최종 출시를 완료로 표시하지 않습니다. 구체적인 IME 조합/취소·충돌/반복 사용과 서명 배포는 남은 항목입니다.

아래는 기존 검사의 세부 범위와 개발 환경 실행법입니다. 새 Windows 수동 확인은 위 실사용 순서를 우선합니다.

2026-11-25 한국 시간. 최신 구현은 [0.2.9 변경 기록](RELEASE_029.md)와 [기능 분류](USABILITY_029.md), 수정 근거와 한계는 [품질 검토](QUALITY_028.md), 기계 판독 결과는 [검증 기록](reports/release-029-validation.json)을 참고합니다. 과거 단계의 ‘실제 제어 미구현’ 절차는 현재 검증 지침으로 사용하지 않습니다.

## 이번 자동 검사

기존 1236개에 사용자 화면 관련 7개를 추가해 portable 회귀 1243개를 등록합니다. 설정·Mock/Unsupported·진단·장치 전송/수명·수동 helper·관찰·그래프 선택·TXT·최근 목록·A/B·메모·묶음의 기존 검사를 함께 실행합니다. 최신 실행의 통과·실패·건너뜀은 위 JSON에 기록합니다.

기존 0.2.8 추가 범위는 메모/최근/설정의 추가 JSON·UTF-8·깊이·중복 필드 거부와 원본 바이트 보존, BOM·공백·기존 스키마 호환, 설정 동시 수정·삭제·잠금·읽기 전용 복구, 네트워크 접두사와 예약/스트림 이름, 같은 이름 기록의 구분, 최근 선택 유지와 항목 삭제, 한글 줄바꿈과 저장 상태, 진행 중 복원과 중단 자료의 구분·복구본 재가져오기·링크 차단·원본 유지, 고정 로그 코드와 개인정보 제외입니다. 100회 열기·비교·메모 저장·닫기 뒤 파일/잠금의 배타적 재열기와 최근 목록 크기도 확인합니다.

Linux 심볼릭 링크 사례를 실제 실행합니다. Windows에서 테스트용 링크 생성 권한이 없으면 새 사례의 일반 경로/폴더 검사를 유지하고 링크 생성 부분을 수행하지 않습니다. 테스트 때문에 관리자 권한·개발자 모드·보안 정책 변경을 요구하지 않습니다. 해당 플랫폼의 링크와 파일 시스템 행위는 별도 확인이 필요합니다.

```powershell
dotnet run --project tests/ATIVBatteryGuard.PortableTests.csproj -c Release -- --report reports/portable-tests.json
```

전체 솔루션의 실제 net48 WPF/XAML Release를 빌드합니다. Linux에서 WindowsDesktop SDK를 이용한 교차 빌드는 Windows 실행 결과를 대신하지 않습니다.

```powershell
dotnet build ATIVBatteryGuard.sln -c Release
```

Windows 개발 환경에서 Visual Studio 2022의 .NET 데스크톱 개발·.NET Framework 4.8 targeting pack과 .NET 8 SDK를 준비한 뒤 실행할 통합 검사입니다.

```powershell
powershell -File scripts/Test-Windows.ps1
```

GUI self-test에는 기존 그래프·키보드/마우스·메모·묶음 검사에 최근 선택 유지와 같은 파일명 A/B 구분을 추가해 컴파일합니다. self-test는 모의 상호작용을 사용하며 실제 파일 대화상자·UAC·IME·충전 효과를 확인하는 절차가 아닙니다. 이번 Linux에서 실행하지 않았습니다.

0.2.9에는 표시용 모델과 원본/쓰기 권한 분리, 진단 문구, 탭 이동 시 장치/배터리/저장 작업 없음, 첫 안내와 확인 전 차단·실패·상한 미확인, XAML의 필수 기능 유지와 불필요 UI 제외를 검사합니다. Windows self-test의 Mock/희망값 UI 검사는 제외하고 새 탭과 기록/진단 화면 검사를 컴파일합니다. Mock 안전성과 기존 설정 호환은 portable suite에서 유지합니다.

## 사용자 확인을 인계한 항목

창의 적절한 크기, Tab·마우스 그래프 접근과 표본 선택, 과거 TXT 그래프, 최근 목록 열기, A/B 비교, 메모 입력과 0.2.7의 .ativrecord 저장·불러오기 성공을 사용자가 확인했습니다. 기존 80% 충전 억제·해제 후 충전 재개·Windows 재시작 후 유지 결과도 인계합니다. 동일한 충전 시험이나 과거 자료 재제출을 요구하지 않습니다.

## 새 Windows 사용 흐름 확인

1. 일반 권한으로 ZIP을 새 폴더에 풀어 실행하고 버전 0.2.9와 기존 기록·메모 복원을 확인합니다.
2. 최근 항목을 선택해 열고 메모를 저장합니다. 선택 항목과 갱신된 미리보기가 유지되는지 확인합니다.
3. 같은 파일명의 묶음을 A와 B로 불러옵니다. 파일명 아래의 기록 구분 표시가 다르고 각 메모를 독립적으로 편집할 수 있는지 확인합니다. 구분 표시는 보안 인증이 아닙니다.
4. 한글 IME 조합 중/완료 직후 클릭·Tab 이동·저장·내보내기·닫기를 확인합니다. 줄바꿈·붙여넣기·글자 수·최대 길이, 초안/저장됨/원래 내용으로 되돌림 안내와 저장·저장 없이 진행·취소를 확인합니다. 이 입력기 동작은 portable 문자열 검사로 검증됐다고 취급하지 않습니다.
5. Windows의 읽기 전용 위치·잠긴 파일·남은 공간 부족과 복원 취소를 확인합니다. 기존 파일·그래프·초안 보존, 저장 상태와 재시도 안내를 기록합니다.
6. 준비된 테스트 자료로 중단된 복원 안내와 import-recovery.ativrecord 재가져오기를 확인합니다. 강제 종료·전원 차단 시험은 하드웨어 작업이 없는 격리된 테스트 데이터에서 별도로 설계하며 일반 충전 제어 중 앱/helper를 강제로 닫지 않습니다.
7. 100%/150%/250% 배율과 작은 창에서 긴 파일명·메모·같은 이름 A/B·오류 안내의 줄바꿈, 스크롤, Tab/Shift+Tab 초점과 그래프 표본 선택을 확인합니다.
8. 배터리/기록/도움말·진단 탭, 처음 실행 안내, 새 버튼명과 개발 UI 제외를 확인합니다. 희망값/Mock은 새 GUI에서 조작하지 않으며 기존 설정 충돌·호환은 자동 검사로 유지합니다.
9. 제품의 Windows 실행 중 네트워크·파일 핸들·메모리·응답성을 확인하고 정확한 배포 파일의 보안 검사 결과와 플랫폼을 기록합니다. 기존 충전 제어를 반복할 필요는 없습니다.

## 배포 확인

프로그램 6파일과 안내·BUILD-INFO·SHA256SUMS의 총 9항목만 ZIP에 포함합니다. 버전 0.2.9/0.2.9.0, 공유 DLL/EXE 바이트, 소스 구성 지문, 내부 SHA와 CRC를 확인합니다. 디지털 서명·Windows Defender·Windows GUI 검사의 미실행 여부를 BUILD-INFO와 검증 기록에 구분합니다. 디지털 서명 없는 개발 ZIP을 서명된 최종 배포 검증 통과로 표시하지 않습니다.
