# 사용 안내

## 현재 삼성 파일 정보 확인판

창 아래쪽 **삼성 파일 정보 확인 → 삼성 파일 정보 만들기**를 선택하고 **정보 파일 위치 열기**에서 새 `samsung-files-*.txt`를 확인합니다. 삼성 DLL·EXE는 전송할 필요가 없습니다. 결과에는 파일별 조회 상태와 버전·구조·서명·참조 정보가 표시됩니다. [상세 사용법](SAMSUNG_FILE_INSPECTION.md)을 참고하세요. 새 기능의 실제 노트북 실행은 아직 미검증입니다.

## 이전 배터리 진단 결과 해석판

삼성 DLL 추출 없이 표준 Windows 배터리 드라이버의 요청 지원 여부를 읽는 진단을 추가했습니다. **진단 파일 만들기**로 생성되는 TXT의 ‘Windows 표준 배터리 드라이버의 요청 지원 여부’ 섹션에서 볼 수 있습니다. BatteryCharge/BatteryDischarge 지원 비트는 80% 충전 상한 지원의 증거가 아니며, 결과가 있어도 실제 제어는 미지원으로 유지합니다.

GENERIC_READ, QUERY_TAG(대기 0), QUERY_INFORMATION(정보 수준 0)만 사용합니다. 자체 보조 프로세스의 10초 제한과 최대 8개 인터페이스·16 KiB 결과 한도를 적용합니다. 장치 경로·태그·시리얼번호·고유 ID를 보고하지 않습니다. SET 요청이나 OEM 메서드는 실행하지 않습니다. 앱 시작이나 주기적 표시에서는 보조 조회를 실행하지 않습니다.

최신 진단에서 Windows 조회 성공과 `0x80000000`을 확인했습니다. 시스템 배터리 표시만 있고 표준 충전·방전 요청 지원 비트는 없습니다. 삼성 OEM 충전 상한의 가능성은 별도 미검증입니다.

현재 해석판은 이 차이를 메인 화면과 진단 TXT에서 설명합니다. 조회가 불완전하면 판단 불가로 남기고 재조회 시 이전 결과를 지웁니다. 같은 진단 파일을 다시 전달할 필요는 없습니다. 회귀 테스트 **138개 통과·실패 0개·건너뜀 0개**입니다. 새 해석 화면의 Windows 실행은 아직 미검증입니다. [구조·출처·검증 한계](WINDOWS_BATTERY_QUERY.md)에 상세히 기록했습니다. 아래 버전별 설명은 이전 단계의 이력입니다.


## 삼성 파일 추출 제외판의 현재 조건

사용자의 Samsung Settings에서 DLL을 추출할 수 없다는 조건으로 진행합니다. WPF 배포 프로젝트에서 삼성 파일 수집기와 위치 탐색기를 컴파일 제외했고 수집 확인 창과 UI도 제거했습니다. 장치 조회·로컬 설정·시뮬레이션·공식 문의문 복사는 유지합니다. 추출한 삼성 DLL은 필요하지 않습니다. 자체 Core DLL과 Windows 내장 프레임워크는 앱 구성 요소입니다.

Microsoft 공식 문서에서 일반 배터리 설정 요청 경로는 확인했지만, 검토한 인터페이스에는 지속되는 80% 충전 상한 항목이 없습니다. OEM WMI 입력 규약은 아직 확보하지 못했으며 실제 제어는 미지원입니다. [DLL 추출 없는 개발 경로와 실제 확인한 출처](DLL_INDEPENDENT_RESEARCH.md)를 참고하세요.

아래 수집 관련 설명은 이전 단계의 기록이며 현재 배포 기능이 아닙니다.


ATIV Battery Guard는 배터리 상태와 저장한 사용자 선택을 보여주고 로컬 진단 자료를 만드는 프로그램입니다. **아직 실제 충전 상한을 80%나 100%로 바꾸지는 않습니다.**

## 이번에 할 일

배터리 표시와 삼성 인터페이스 정의 조회는 사용자 화면·진단에서 확인됐습니다. 현재는 Samsung Settings 2.2.0의 사용권과 모델별 공식 지원 여부를 먼저 확인하는 단계입니다.

삼성 실행 파일·DLL 및 해당 분석 ZIP의 추가 업로드 요청은 보류했습니다. 이전의 Settings.exe 전달 요청도 철회했습니다. 지금은 프로그램의 분석 파일 생성 기능을 추가로 실행할 필요가 없습니다. 새 공식 지원 검토판은 제품 시작 구성에서 삼성 파일 수집기를 해제해 생성 버튼을 비활성화했습니다. 이전 배포본에는 이 변경이 적용되지 않습니다.

새 화면의 **공식 문의문 복사**는 장치 정보 조회 후 문의 초안을 클립보드에 복사합니다. 조회 전·갱신 중·종료 후에는 복사할 수 없습니다. 초안을 검토한 뒤 직접 전달할 수 있으며 앱은 삼성에 연락하거나 전송하지 않습니다. 삼성 파일과 상세 오류는 문의문에 넣지 않습니다.

공식 확인 항목과 미전송 문의 초안은 [OFFICIAL_SUPPORT_REVIEW.md](OFFICIAL_SUPPORT_REVIEW.md)에 있습니다. 사용자 노트북의 추가 테스트도 현재 필요하지 않습니다.

## 화면 읽기

- **현재 배터리**: Windows가 알려준 잔량·외부 전원·충전 상태입니다. 최근 확인한 상태는 62%, AC 연결 안 됨, 방전 중이었으며 수치는 현재 상태에 따라 갱신됩니다. 이전의 0%도 당시의 유효한 측정값이었습니다.
- **사용자 선택값**: 원하는 80% 보호 모드 또는 일반 100% 모드입니다. 선택을 저장하는 것과 실제 장치 적용은 다릅니다.
- **실제 하드웨어 상태**: 검증된 제어 인터페이스가 없어 미지원으로 표시됩니다. 저장한 선택값으로 바뀌지 않습니다.
- **시뮬레이션**: 화면과 모드 전환을 확인하는 개발용 기능입니다. 실제 충전에는 영향을 주지 않습니다.

앱은 일반 권한으로 실행합니다. 관리자 권한·드라이버 설치·보안 설정 변경은 필요하지 않습니다. 배터리 80%나 충전 중 아님 표시만으로 충전 제한이 작동했다고 판단하지 않습니다.

## 분석 자료에 포함되는 것

Settings 분석 ZIP에는 허용된 설치 위치의 삼성 EXE·DLL 복사본과 파일별 분석 정보가 포함될 수 있습니다. 용량·파일 수·탐색 범위를 제한한 자료로 설치 파일 전체를 복사하지는 않습니다. 설정·로그·개인 문서는 따로 수집하지 않습니다. 원본 파일을 실행하거나 변경하지 않고, 삼성 제어 함수도 호출하지 않습니다. 확인 창에서 아니요를 선택하면 분석 수집을 취소합니다.

기존 **진단 파일 만들기** 기능도 사용할 수 있습니다. 이 기능은 필요한 장치 정보와 삼성 인터페이스의 정의를 TXT로 저장하며, 제어 함수를 실행하지 않습니다. 클래스가 발견되어도 충전 제한을 지원한다는 뜻은 아닙니다.

## 저장 위치와 검증 범위

사용자 설정과 로컬 진단·분석 자료는 `%LOCALAPPDATA%\ATIVBatteryGuard` 아래에 저장합니다. 설정을 기억하는 기능은 다음 부팅 때 펌웨어 충전 제한을 적용하는 기능이 아닙니다. 앱은 서비스·자동 시작 항목을 설치하지 않습니다.

이전 WMI 진단판은 노트북의 창 실행과 실제 클래스 정의 조회가 확인됐습니다. 새 Settings 분석판은 빌드 경고·오류 0개와 자동 테스트 108개 통과를 확인했습니다. 새 Settings 파일 수집 기능의 Windows 동작은 이번 ZIP 결과로 별도 확인해야 합니다. 실행용 ZIP과 소스 백업은 저장소의 해당 배포 브랜치 downloads 폴더에 함께 보관합니다.
