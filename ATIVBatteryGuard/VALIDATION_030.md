## 후보와 변경 범위

검증 후보는 **0.3.0-rc.1**, 파일 버전은 0.3.0.0입니다. 정식 0.3.0 검증 완료판으로 표시하지 않습니다. 사용자 확인 기준 커밋 dce62bf9056246fb14234a2a31cb18924c695b05의 앱·helper 구성 소스를 동결하고 ApplicationRelease 버전 상수만 바꿉니다. 새 화면·새 충전 제어·새 설정 기능을 추가하지 않습니다. 소스 구성 비교로 그 범위를 확인합니다.

별도의 net48 콘솔 검증 도구와 패키징/테스트 자료를 추가합니다. 일반 프로그램 구성에는 도구를 넣지 않고 VALIDATION-KIT에만 포함합니다. GUI/helper 및 기존 사용자 설정·기록·메모 형식은 유지합니다.

## 개발 도구 없는 Windows 검사

검증 키트를 새 로컬 폴더에 풀고 `검증시작.cmd`를 실행하면 파일 확인과 GUI 자동 검사를 진행합니다. 도구 자체는 asInvoker이며 개발 SDK나 관리자 실행을 요구하지 않습니다. 검증 도구는 허용한 프로그램 6파일·후보 버전·크기·SHA-256을 먼저 확인한 뒤 고정 GUI EXE의 `--self-test`만 실행합니다. 결과의 종료 코드·필수 필드·쓰기 없음·바인딩 오류 없음·실패 코드 없음과 검사 후 파일 일치를 확인합니다. 해시 목록은 배포자 인증 수단이 아닙니다.

기존 GUI self-test는 임시 폴더와 모의 배터리로 차트·메모·복원·글자 대비·작은 창의 헤더 경계 등을 확인합니다. 실제 OEM 쓰기나 관리자 helper를 실행하지 않습니다. 네이티브 배터리/기본 WMI 읽기 결과가 완전하지 않아도 GUI 검사와 구분해 기록합니다. 시간 초과·파일 변경·누락·잘못된 결과는 통과로 처리하지 않습니다. 프로세스를 강제로 종료하거나 검사 결과를 자동 전송하지 않습니다.

도구 결과는 새 `validation-results/validation-*.json`과 `gui-*.json`입니다. 자동 검사만 통과한 경우에도 Outcome은 automated-checks-passed-manual-checks-pending이며 ManualUserFlowsConfirmed/DefenderScanExecuted/FinalReleaseApproved는 false입니다. 실제 대화상자·IME·고배율·장시간 사용·백신 검사를 완료한 것으로 간주하지 않습니다.

두 예제 묶음은 실제 측정이 아닌 합성 자료임을 TXT·파일명·메모에 표시했습니다. 실제 Core 파서로 검사한 뒤 키트에 넣습니다. 기존 개인 기록을 재제출하거나 새 충전 시험 자료를 만들 필요 없이 파일 대화상자·A/B·한글 메모 저장/재열기·왕복 내보내기를 확인할 수 있습니다.

## 다음 진행

우선 자동 검사와 예제의 한글 메모 저장/재열기·왕복 이동 결과를 받습니다. 이후 현재 사용 배율·작은 창·취소/실패·두 창 충돌·반복 사용·정확한 파일의 보안 검사 결과를 보완합니다. 문제가 나오면 같은 RC1 바이트의 검증 결과를 수정해서 덮지 않고 새 후보를 만들어 다시 검증합니다. 최종 버전 변경 뒤의 실제 배포 파일도 버전·구성·해시·필요한 검사를 연결해 확인합니다.
