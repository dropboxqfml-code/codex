## RC3 수정 후보와 닫기 전용 검사

[RC3](RELEASE_030_RC3.md)는 지연 입력 덮어쓰기 회귀(수정 전1실패)를 재현한 뒤 닫기 전에 현재 메모를 초안에 반영하고 확인 진입의 불필요 Text 알림을 생략합니다. 제품3파일만 바꾸고 XAML·충전 제어·저장 형식은 보존합니다. [v4 닫기 검사](../downloads/ATIVBatteryGuard-0.3.0-rc.3-EXTENDED-CHECKS-v4.zip)는 닫기 전/확인 전/취소 후 각 조건을 원문 없이 기록합니다. 새 회귀5개 포함1272통과, 네 빌드 경고/오류0입니다. 이후 [사용자 RC3 결과](FIELD_IME_CLOSE_030_RC3_RESULT.md)에서 시작/닫기 전용 검사 모두 통과했습니다. 조합8/17회와 실제 지연 VM 상태/닫기 전 반영, 취소 후 초안/기존 저장값 보존을 확인했습니다. 같은 검사를 반복하지 않습니다. 최종 출시 완료로 확대하지 않습니다.

[v3 사용자 결과](FIELD_IME_030_V3_RESULT.md)에서 시작 정상/본 검사 종료1, 저장·재열기와 실제 조합 이벤트는 확인했습니다. 닫기 취소 후 IME_CANCEL_DRAFT_MISMATCH로 실패했습니다. 창/초안 수정 상태/VM·화면 문구/기존 저장값의 복합 조건 중 어느 값이 달랐는지는 현재 JSON에 없습니다. ## 실제 IME 확인 도구 준비 이력

[사용자 참여 IME 모드](IME_030_CHECK.md)를 v3 도구에 추가했습니다. [새 ZIP](../downloads/ATIVBatteryGuard-0.3.0-rc.2-EXTENDED-CHECKS-v3.zip)의 한글입력확인.cmd만 실행해 두 문구의 실제 조합 중 저장/닫기를 확인합니다. 실제 입력 이벤트와 한국어 IME On 관찰·명시적 직접 확인이 없으면 통과로 표시하지 않습니다. 새 판정 회귀4개 포함1267통과, WPF 빌드 경고/오류0이며 이후 실제 Windows 모드는 위 수신 결과에서 저장 통과/닫기 취소 검사 실패로 확인됐습니다. 기존 빠른/20분 검사는 반복하지 않습니다.

최종 서명 판정은6파일 전체/PE4개 타임스탬프를 요구하도록 보강했습니다. 실제 인증서/서명·Windows 보안 실행·최종 버전/패키징 연결은 미완료입니다. [검증 기록](reports/ime-030-validation.json)과 [서명 배포 준비](RELEASE_030_SIGNING_READINESS.md)를 참고합니다.

## 후보 변경 범위

RC1(d705c9c43be84c94ad6374b3559776756775502b)의 앱/helper 소스 207파일과 비교해 MainViewModel의 최근 목록 갱신 중 선택 setter 재진입 방지, ApplicationRelease의 버전 상수만 바꿨습니다. WPF가 ItemsSource 교체 때 전달하는 임시 선택 해제 값이 선택을 덮어쓰지 않도록 했습니다. 명시적 선택 해제와 제거된 항목의 선택 해제는 유지합니다. XAML·충전 제어·설정/기록 형식은 바꾸지 않았습니다.

검증 도구와 패키징은 후보 버전을 RC2로 연결합니다. 실패를 발견한 기존 Windows GUI 검사 조건은 유지하며 RC1 원본 결과와 ZIP은 보존합니다. Linux에서 WPF를 컴파일한 결과와 실제 Windows 실행 결과를 구분합니다.

## 검증 도구와 보안

키트를 새 로컬 폴더에 풀고 `검증시작.cmd`를 실행합니다. 도구는 일반 권한(asInvoker)이며 개발 SDK가 필요하지 않습니다. 프로그램 6파일·버전·크기·SHA-256을 확인한 뒤 고정 EXE의 `--self-test`를 실행하고 결과와 파일을 다시 확인합니다. 임시 자료를 사용하며 helper·OEM 쓰기·정책 변경·자동 전송은 없습니다. 실제 기본 장치/배터리의 읽기 전용 조회는 포함될 수 있습니다. 시간 초과 때 프로세스를 강제 종료하지 않습니다.

성공해도 수동 사용·Defender·최종 출시는 미완료로 기록합니다. 따라서 사용자의 별도 수동 보고와 JSON 필드를 구분하고 원본의 false 값을 임의로 바꾸지 않습니다. 예제 A/B는 실제 측정이 아닌 합성 자료입니다.

현재 미서명 배포의 첫 실행 경고는 Defender의 악성 코드 검사와 구분합니다. 정식 배포 전 배포자 코드 서명 인증서·타임스탬프·서명 후 파일 검증을 준비해야 하며 서명이 모든 평판 경고의 즉시 제거를 보장하지 않습니다. 보호 기능 해제나 예외 추가를 요구하지 않습니다.

## 추가 도구 시작 실패와 v2 수정

사용자가 v1 두 모드의 시작 실패를 보고했습니다. 바탕화면 위치 문제로 판단하지 않으며 v1의 현장 통과 근거는 없습니다. [수정 기록](EXTENDED_030_STARTUP_FIX.md)에 WPF 리소스/실제 객체 타입의 어셈블리 불일치 결함과 v2 독립 호스트·원본과 같은 스타일 사전, 초기 단계별 startup JSON을 기록했습니다. 리소스·시작 진단 회귀5개를 더해1263통과, 실제 XAML WPF 빌드 경고/오류0입니다. 이후 사용자 v2 두 실행에서 시작/본 검사가 통과했으며 위 수신 결과에 별도로 기록했습니다. 과거 v1의 정확한 예외가 로그로 확인된 것은 아닙니다.

## 남은 항목의 추가 자동화

[별도 추가 검사 도구](EXTENDED_030_AUTOMATION.md)를 작성했습니다. 프로그램은 기존 RC2 그대로이며 [추가 ZIP](../downloads/ATIVBatteryGuard-0.3.0-rc.2-EXTENDED-CHECKS-v2.zip)의 빠른추가검사.cmd/20분반복검사.cmd로 실제 화면·바인딩·저장 확인 대화상자·취소·같은 프로세스의 두 창 충돌·초안 백업·잠금 재시도·반복 사용을 검사합니다. 확정 한글 주입을 실제 IME 검사로 표시하지 않고, 파일 선택 대화상자/독립 프로세스 경쟁/물리적 포인터 적중·누수 부재 증명도 자동화 범위에 포함하지 않습니다.

## 추가한 품질 검사

두 MainViewModel의 동일 기록 충돌 뒤 닫기 차단·A/B 초안 유지·실제 .ativrecord 백업·취소·최신 내용 다시 읽기·반대 방향 충돌까지 확인했습니다. 실제 잠금 파일로 저장 실패와 해제 후 재시도를 검사했습니다. 250회의 A/B 편집기 생성·500회 저장·닫기 후 편집기 객체500개가 주 ViewModel이 살아 있어도 수거되고 파일/잠금이 해제되며 임시 파일이 남지 않았습니다. portable 빌드는 경고/오류0입니다. 이는 Linux의 모델/저장소 검사로 실제 WPF 메모리·IME·장시간 사용을 대신하지 않습니다.

서명 후 Windows 검사 도구는 현재 프로그램6파일을 확인하고 EXE/DLL4개의 동일한 유효 서명을 요구합니다. Python 증거 판정도 공급된 모든 PE 파일을 검사합니다. helper/WMI 서명 누락·미서명·다른 게시자 및 바이트 변경 거부를 회귀로 확인했습니다. 실제 Windows PowerShell 실행이나 서명/백신 검사는 미수행입니다. [서명 배포 준비와 남은 의존성](RELEASE_030_SIGNING_READINESS.md)을 참고합니다.

프로그램과 원래 RC2 배포 ZIP은 변경하지 않았습니다. [수동 확인 자료 ZIP](../downloads/ATIVBatteryGuard-0.3.0-rc.2-MANUAL-CHECKS.zip)은 텍스트 순서/결과 양식/기준정보3개만 담고 실행 파일은 없습니다.
