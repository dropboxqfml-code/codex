## 후보 변경 범위

RC1(d705c9c43be84c94ad6374b3559776756775502b)의 앱/helper 소스 207파일과 비교해 MainViewModel의 최근 목록 갱신 중 선택 setter 재진입 방지, ApplicationRelease의 버전 상수만 바꿨습니다. WPF가 ItemsSource 교체 때 전달하는 임시 선택 해제 값이 선택을 덮어쓰지 않도록 했습니다. 명시적 선택 해제와 제거된 항목의 선택 해제는 유지합니다. XAML·충전 제어·설정/기록 형식은 바꾸지 않았습니다.

검증 도구와 패키징은 후보 버전을 RC2로 연결합니다. 실패를 발견한 기존 Windows GUI 검사 조건은 유지하며 RC1 원본 결과와 ZIP은 보존합니다. Linux에서 WPF를 컴파일한 결과와 실제 Windows 실행 결과를 구분합니다.

## 검증 도구와 보안

키트를 새 로컬 폴더에 풀고 `검증시작.cmd`를 실행합니다. 도구는 일반 권한(asInvoker)이며 개발 SDK가 필요하지 않습니다. 프로그램 6파일·버전·크기·SHA-256을 확인한 뒤 고정 EXE의 `--self-test`를 실행하고 결과와 파일을 다시 확인합니다. 임시 자료를 사용하며 helper·OEM 쓰기·정책 변경·자동 전송은 없습니다. 실제 기본 장치/배터리의 읽기 전용 조회는 포함될 수 있습니다. 시간 초과 때 프로세스를 강제 종료하지 않습니다.

성공해도 수동 사용·Defender·최종 출시는 미완료로 기록합니다. 따라서 사용자의 별도 수동 보고와 JSON 필드를 구분하고 원본의 false 값을 임의로 바꾸지 않습니다. 예제 A/B는 실제 측정이 아닌 합성 자료입니다.

현재 미서명 배포의 첫 실행 경고는 Defender의 악성 코드 검사와 구분합니다. 정식 배포 전 배포자 코드 서명 인증서·타임스탬프·서명 후 파일 검증을 준비해야 하며 서명이 모든 평판 경고의 즉시 제거를 보장하지 않습니다. 보호 기능 해제나 예외 추가를 요구하지 않습니다.

## 다음 진행

이번에는 **RC2 자동 검사만 다시 실행**해 새 JSON 결과를 받습니다. 이미 확인한 수동 흐름·화면과 기존 충전 시험은 반복하지 않습니다. 이후 남은 IME 조합 처리·취소/동시 수정·반복 사용과 서명 배포 근거를 보완합니다. RC2 결과 전에는 Windows 수정 확인이나 최종 출시 완료를 주장하지 않습니다.
