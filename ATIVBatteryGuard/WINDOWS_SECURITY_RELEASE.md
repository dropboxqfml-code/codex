## 반영한 배포 조건

`scripts/package_preview.py`는 기본적으로 실행용 ZIP 생성을 거부합니다. 개발 검토용으로는 `--source-only`만 사용할 수 있습니다. 실행용 배포에는 아래를 묶은 Windows 검사 보고서가 필요합니다.

1. 합법적으로 확보한 게시자 인증서로 EXE와 자체 Core DLL을 서명하고 동일 게시자인지 확인
2. Defender와 실시간 보호가 켜져 있고 최신 정의가 있는 Windows에서 실제 빌드 폴더 검사
3. 검사 종료 코드뿐 아니라 해당 경로의 탐지 이력·격리/파일 변경 여부 확인
4. 검사한 EXE·DLL·config의 해시, 소스 fingerprint, 서명 상태를 보고서로 연결
5. 패키징 시 파일/소스 일치와 24시간 이내 검사 결과를 재검증

개발자용 `scripts/Test-WindowsRelease.ps1`은 보호 설정을 바꾸지 않고 이 증거를 생성합니다. 현재 환경에는 Windows Defender와 게시자 서명 인증서가 없으므로 해당 스크립트를 실행하거나 검증 통과를 주장하지 않았습니다. 사용자에게 이 개발자 스크립트를 실행하도록 요구하지 않습니다.

검사 보고서는 내부 배포 실수를 막는 증거이며 위조 방지 인증서가 아닙니다. Defender 검사 통과나 서명만으로 영구적인 안전을 보장하지 않습니다. 공식 Microsoft 파일 검토 요청은 외부 제출이므로 이번 작업에서 자동 제출하지 않았습니다.

기존 불변 Git 커밋의 다운로드 주소는 여전히 존재할 수 있습니다. 최신 다운로드 안내에서 실행 링크를 제거해도 과거 주소를 회수하거나 탐지를 해소한 것은 아닙니다. 보안 검토가 완료되기 전 새 실행 파일을 배포하지 않습니다.
