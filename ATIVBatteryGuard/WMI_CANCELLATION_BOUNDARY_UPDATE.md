# WMI 전송 취소와 제한 시간 보강 — 2026-11-07 한국 시간

**후속:** [미분류 영역의 EC 업데이트 분류 연결](EC_UPDATE_REGION_RESULT.md)을 완료했습니다. 아래 당시의 영역 용도 미확정과 달리 후속에서는 실제 소비·block-info 생산·EC 옵션 선택을 연결했습니다. 칩·명령어 해석 기준과 충전 보호 계약은 여전히 미확정이며 프로그램은 변경하지 않았습니다.

순수 전송 조정 코드의 **제한 시간 이후에도 반환이 멈출 수 있는 결함**을 재현하고 수정했습니다. `CancellationTokenSource.Cancel()`은 등록된 callback을 동기로 실행하므로, 채널의 취소 callback이 멈춰 있으면 기존 `ExchangeAsync`도 결과를 반환하지 못했습니다.

이 코드는 명시적으로 전달한 채널을 조정하는 개발용 구성 요소이며 현재 앱의 실제 장치 경로에는 연결되지 않습니다. 새 OEM 명령·보호 설정 조회·충전 제한은 추가하지 않았습니다. 실제 제어는 계속 **Unsupported**입니다.

## 수정한 동작

- 채널의 취소 callback은 별도 worker에서 실행합니다. timeout 또는 사용자의 취소 결과를 반환하는 경로에서 그 callback의 종료를 기다리지 않습니다.
- 채널 작업과 취소 callback 작업이 **모두 끝난 후** token source를 정리하고 작업 슬롯을 해제합니다. 채널만 먼저 끝나도 `Busy` 상태를 유지해 이전 callback과 다음 요청의 중첩을 막습니다.
- 늦은 예외를 관측하고, 이미 반환한 timeout/cancel 결과에 응답 payload를 다시 붙이지 않습니다.
- 결과 게시 전에 관측한 사용자 취소는 우선합니다. timeout 뒤 callback이 나중에 일으킨 사용자 취소를 기다리거나, 그 부수 효과로 이미 게시한 결과를 바꾸지 않습니다.

callback이나 채널이 영원히 멈추면 해당 인스턴스의 작업 슬롯도 계속 유지됩니다. 이는 미완료 작업을 끝났다고 처리하지 않기 위한 동작입니다. worker의 강제 종료 기능을 추가한 것은 아니며, 장래 실제 native backend에는 별도의 프로세스 제한이 필요합니다.

변경 파일은 `src/ATIVBatteryGuard.Core/Services/WsabiWmiFrameExchange.cs`와 `tests/WsabiWmiFrameExchangeTests.cs`입니다. 프레임 형식·요청 범위·응답 의미·실험 정책·예약·권한·실제 제어 어댑터·앱 연결은 변경하지 않았습니다.

## 재현과 검증

기존 코드에 새 차단 callback 회귀만 추가했을 때 **436개 통과 / 1개 실패 / 건너뜀 0개**로 대기를 재현했습니다. 수정 후에는 다음 항목을 확인했습니다.

- 사용자 취소와 timeout 양쪽에서 callback이 막혀 있어도 결과 반환
- 채널이 먼저 완료돼도 callback 종료 전 다음 요청 거부
- callback 종료 후 슬롯 해제와 다음 요청 정상 처리
- 늦은 사용자 취소·callback 예외에도 기존 timeout 결과와 빈 payload 유지
- 실제 장치 관측·OEM 실행·읽기·쓰기 권한으로의 승격 없음

최종 **C# 437개 / Python 85개 통과**, 실패·건너뜀 0개입니다. .NET Framework 4.8의 WPF 앱을 포함한 전체 솔루션 빌드는 **경고·오류 0개**입니다. 별도 코드 검토에서도 새 차단 결함이나 token source 수명·동시성·API 호환 결함을 발견하지 못했습니다.

현재 Linux 환경의 WindowsDesktop 빌드 도구는 기본 모드에서 MSB4062 / BadImageFormat으로 실패했습니다. 동일한 SDK를 `COMPlus_ReadyToRun=0`, `DOTNET_ReadyToRun=0`으로 실행해 전체 빌드를 통과했습니다. 이는 빌드 명령에만 적용한 설정이며 실행 프로그램의 보안 설정이나 환경 게시를 변경하지 않았습니다. Windows GUI·노트북에서 새로 실행한 검증은 아닙니다.

요약은 [검사 기록](reports/wmi-cancellation-audit.json), 실행 기록은 `reports/wmi-cancellation/`에 저장했습니다. 과거 검증 수치를 새 결과로 재사용하지 않았습니다.
