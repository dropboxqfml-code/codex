# 1회 실험 도구 결과: 사전 검증 중단·OEM 요청 없음

2026-11-04 한국 시간, 사용자가 전달한 콘솔 출력의 고정 상태만 기록합니다. 원본 TXT는 저장소·배포물에 넣지 않습니다.

| 항목 | 수신한 관측 |
| --- | --- |
| 프로세스 토큰 | Elevated |
| 결과 | PreflightFailed |
| 사전 검증 상태 | Unavailable |
| OEM 호출 요청 | 없음 |
| 메서드·프레임·후보 표식 | 모두 미관측 |

이 조합은 해당 실행의 준비 과정이 Complete로 반환되기 전에 중단됐음을 뜻합니다. Core에서 사전 검증 상태가 Complete로 바뀌었다면 뒤의 예외도 그 상태를 유지합니다. 따라서 이번 Unavailable 조합에서는 reservation.TryClaim과 채널 호출에 도달하지 않았습니다. **이번 실행의 0x65 요청과 새 예약 확보는 없었습니다.** 기존 예약 파일이 없거나 다른 실행도 없었다는 뜻은 아니므로 파일을 확인·삭제·초기화하도록 요구하지 않습니다.

현재 토큰 상승은 확인됐지만 WMI 권한 전체, 모델/BIOS 확인 완료, 규약 확인 완료, 단일 대상 확인 완료를 각각 입증한 결과는 아닙니다. 배터리 보호 상태·0x65 응답·충전 제어 지원은 관측하지 못했습니다. 과거의 클래스 규약 일치와 관리자 속성 조회 결과는 각각의 이전 관측으로 보존합니다. 드라이버 미설치나 배터리 기능 부재로 바꾸지 않습니다.

## 기존 문구의 한계와 보고 전용 보완

기존 “메타데이터 조회 결과 확인 불가”는 공통 Unavailable 상태의 표시 문구입니다. 실제 실패 위치가 클래스 메타데이터 단계였다는 증거는 아닙니다. 모델/BIOS 읽기·메서드 대상 준비·입력 속성/qualifier·DataBuffer 생성 중의 분류되지 않은 오류도 같은 문구가 됩니다. 이 파일만으로 정확한 원인을 선택할 수 없습니다.

이를 보완하기 위해 고정된 사전 검증 단계 enum을 보고서에 전달하도록 수정했습니다. 경로·실제 기기값·인스턴스 키·예외 원문을 수집하는 기능은 추가하지 않습니다. 예전 출력에 없던 단계는 Unknown으로 유지하고 역으로 추정하지 않습니다. 실패 상태도 일반 사전 검증 상태로 표시해 메타데이터 오류라고 단정하지 않습니다.

이 변경은 보고 기능만 다룹니다. 권한·모델/BIOS·WMI 규약·메서드 번호·정확히 하나인 활성 대상·입력 검증·영속 예약·고정 요청·호출 횟수·시간 제한을 완화하지 않습니다. 실제 호출 메서드와 예약/재시도 정책은 바꾸지 않습니다. 이번 단계에서는 새 실험 EXE나 노트북 재실행을 요청하지 않습니다.

입력 객체의 qualifier 검사, 메모리 객체 생성, provider/COM의 분류되지 않은 오류 등은 코드상 가능한 가설일 뿐입니다. 이를 원인으로 확정해 검증 조건을 제거하거나 쿼리 옵션을 변경하지 않았습니다.
