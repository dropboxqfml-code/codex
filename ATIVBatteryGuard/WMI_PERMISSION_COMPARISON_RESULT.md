# 일반·관리자 WMI 속성 조회 비교 결과

2026-11-03 한국 시간 기준입니다. 사용자가 승인된 비교 절차로 전달한 두 콘솔 출력 파일을 관측 자료로 읽었습니다. 원본 파일은 저장소·배포물에 복사하지 않고 아래 제한된 결과만 기록했습니다.

## 이번에 확인한 결과

| 항목 | 일반 실행 | 관리자 실행 |
| --- | --- | --- |
| 토큰 상승 상태 | NotElevated | Elevated |
| WmiAcpiVersion 조회 | Complete, Completed, None | Complete, Completed, None |
| 버전 클래스의 관측 | 1개, Active=True, version=16 (0x00000010) | 1개, Active=True, version=16 (0x00000010) |
| WmiAcpiMethod 조회 | AccessDenied, Enumerate, WBEM_E_ACCESS_DENIED (0x80041003) | Complete, Completed, None |
| 메서드 클래스의 관측 | 값 미관측 | 1개, Active=True |

이번 일반 실행에서 ROOT\WMI의 명시적 연결과 쿼리 시작은 진행됐고, 메서드 클래스 인스턴스 열거 단계에서 거부가 관측됐습니다. 이는 네임스페이스 연결 자체가 거부됐다는 결과와 구분합니다. 단계와 고정 코드만으로 정확한 ACL·제공자 내부의 원인을 확정하지 않습니다.

버전 속성은 일반 토큰에서도 읽혔습니다. 메서드 클래스의 고정 Active 속성은 이번 상승 토큰 실행에서 읽혔습니다. 따라서 모든 ROOT\WMI 속성이 일반 사용자에게 거부된다거나, 모든 WMI 작업이 관리자 권한이면 가능하다는 결론으로 넓히지 않습니다.

같은 계정에서 비교하도록 승인·안내한 절차이며, 도구는 사용자 식별자를 읽지 않습니다. 두 출력이 같은 사용자 계정이라는 점을 파일 안의 식별자로 독립 검증한 것은 아닙니다.

## 이전 결과와의 관계

이전 메인 앱 TXT에서는 두 클래스 모두 거부됐지만 이번 별도 도구의 일반 실행에서는 버전 클래스가 읽혔습니다. 두 빌드는 흐름과 시점이 다르고 새 도구는 scope.Connect를 명시합니다. 따라서 PacketPrivacy 또는 Connect 중 무엇이 차이를 만들었다고 인과를 확정하지 않습니다. 이전 결과는 당시 관측으로 그대로 보존합니다.

이번 도구는 SABI 이름이나 커널 드라이버 목록을 다시 읽지 않았습니다. 이전의 SABI NotFound·Samsung 이름 후보 7개 Stopped/Manual은 별도 시점의 기록이며 이번 두 출력으로 재검증한 결과가 아닙니다.

## 실제 배터리 조회에 아직 없는 근거

1. version=16은 UInt32 원값입니다. 저장된 분석에는 이를 프로토콜 1.0, SABI3, 현재 모델의 배터리 명령 지원으로 해석할 근거가 없습니다.
2. Active=True는 WMI 인스턴스가 보고한 활성 속성이며 배터리 보호 ON/OFF가 아닙니다.
3. 속성 열거 성공은 CallSabiFunction의 실행 허가·안전성·실제 응답을 확인한 것이 아닙니다. OEM 메서드는 실행하지 않았습니다.
4. 두 클래스에서 각각 한 행을 관측했지만 키를 대조하지 않았으므로 같은 backing instance라고 단정하거나 행을 자동 연결하지 않습니다.
5. 기존 서비스 wsabi의 16바이트 payload·21바이트 입력은 특정 x86 해시의 정적 계약입니다. Sabi3 x64의 11바이트 payload·26바이트 장치 입력·16바이트 응답과 별개입니다. 제공자의 실제 SAFEARRAY 길이도 아직 미검증입니다.
6. 공개 0x65/0x66 명령 후보의 현재 940X3G/930X3G·BIOS·Windows WMI에서의 의미와 조회 안전성이 아직 검증되지 않았습니다. 공개 조회 함수 이름만으로 실행 가능한 OEM 코드를 추가하지 않습니다.

[공개 명령 근거](PUBLIC_CONTROL_PROTOCOL_REVIEW.md), [특정 wsabi 전송 분석](SABI_LINK_RESULT_AND_WMI_REVIEW.md), [Sabi3 x64 분석](SABI3_NATIVE_ABI_REVIEW.md)을 대조했습니다. 현 자료에서 버전 16의 의미나 위 누락 계약을 새로 확정할 근거는 찾지 못했습니다.

## 이번 코드·기록 반영

승인된 한정 권한 비교의 결과를 받았으며 비교 단계는 완료됐습니다. 이 승인을 상시 관리자 앱·자동 상승 브로커·반복 관리자 시험·OEM 메서드·드라이버/서비스/ACL 변경으로 확대하지 않습니다. 같은 진단·원본 TXT·삼성 파일을 다시 요청하지 않습니다.

단일 보고서의 “관리자 실행이 해결한다는 근거도 없음” 문구를 “단일 조회 결과만으로 거부 원인이나 관리자 실행에서의 결과를 확정하지 않음”으로 좁혔습니다. 실제 비교 근거가 생긴 상황에서도 단일 관측을 일반화하지 않도록 한 표현 수정입니다.

두 실제 결과를 개인정보 없는 합성 회귀 사례로 추가했습니다. 일반 실행의 선택적 열거 거부와 관리자 실행의 속성 성공, 버전 원값 16, 독립된 관측과 OEM/제어 비활성화를 검사합니다. 전체 테스트 238개 통과·실패/건너뜀 0개, Core·WPF·별도 도구 빌드는 경고·오류 0개입니다.

새 기능이나 장치 호출 경로는 추가하지 않았으며 이 기록 반영 때문에 새 진단 실행 파일을 배포하지 않습니다. 기존 237개 검증 도구의 Windows 속성 읽기는 위 두 사용자 결과로 확인됐고, 이번 표현 수정 소스의 Windows 재실행은 하지 않았습니다. 실제 충전 제어는 계속 Unsupported입니다.
