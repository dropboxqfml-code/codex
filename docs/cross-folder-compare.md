# 두 폴더 간 비교 — v0.2.0

사용자가 제공한 [개발 요구사항 v1.0](cross-folder-requirements.md)을 기준으로 구현했습니다.
기존 `폴더 내부 중복 검색`은 유지하며, 새 기능은 `feature/cross-folder-compare`에서 검토합니다.

## 사용 방법

1. 상단에서 **서로 다른 두 폴더 비교**를 선택합니다.
2. **A**에는 보호할 기준 원본 폴더, **B**에는 정리할 대상 폴더를 선택합니다.
   각 `하위 폴더 포함`은 독립적이며 기본 꺼짐입니다. 같은 폴더와 상위·하위 관계는 차단합니다.
   `A/B 폴더 바꾸기`는 역할 변경을 확인한 뒤에만 적용하며 기존 화면 결과를 비웁니다.
3. 유사 후보 검색 여부와 pHash 거리(기본 6, 0~12)를 선택하고 검색합니다.
4. 결과는 B 파일 하나당 한 항목입니다. 좌측 A와 우측 B를 비교하고 상단 선택기로 다른 A
   매칭도 확인합니다. 두 이미지 모두 경로·크기·해상도·확장자·수정시각이 나옵니다.
   `큰 미리보기`는 원본을 읽어 최대 1200×900으로 축소한 비교 화면입니다.
5. 탭으로 판별 유형·오류를, 필터로 처리 상태·파일명을 좁힙니다. 한 B가 여러 유형에 해당하면
   해당 탭마다 보일 수 있으나 실제 후보와 처리 상태는 하나입니다. 대표는 가장 강한 매칭입니다.
6. B만 `미결정 / 보관 / 보류 / 휴지통 이동 예정`으로 수동 지정할 수 있습니다.
   **미결정·보관·보류는 모두 파일을 유지합니다. A에는 처리 선택 컨트롤이 없습니다.**
7. `휴지통 이동 예정 N개…`에서 전체 B 경로·종류·개수를 확인합니다. 기본 응답은 **아니요**입니다.
   유사 후보만 있는 B는 다른 사진일 수 있다는 두 번째 확인에도 동의해야 합니다.
8. 변경 검사를 통과한 B만 Send2Trash로 이동합니다. 실패하면 후속 이동을 중단하고 건너뛴
   개수를 표시합니다. 취소는 이미 이동한 파일을 되돌리지 않습니다. 복원은 Windows 휴지통에서 합니다.

검색·매칭·미리보기·내용 재검증·휴지통 처리는 워커에서 실행합니다. 검색과 미리보기 중 역할 변경과
모드 변경은 비활성화됩니다. 취소는 파일/해시 블록/인덱스 조회 사이에서 확인하며 단일 Pillow 디코딩과
OS 휴지통 API 호출은 강제 중단할 수 없습니다. 종료 요청은 워커가 끝날 때까지 기다립니다.

## 실제 저장소 구조와 재사용

| 기존 `privacy.py`, `folder_dialog.py`, `recycling.py` | 로컬 경로·네트워크/프로세스 가드, 로컬 전용 선택기, Windows modern 휴지통 재사용 |

A/B 내부 비교 루프나 연결 그룹은 생성하지 않습니다. A의 `(크기, SHA-256)`와 픽셀 해시를
해시맵에 넣고 B로 조회합니다. pHash는 64비트 해밍 거리 BK-tree로 조회하며 동일 해시의 A는
한 버킷에 보관합니다. BK-tree의 최악 시간 복잡도는 선형 조회에 가까워질 수 있으며 모든 데이터에서
로그 시간이라는 보장은 없습니다. 반환되는 매칭 수가 많으면 그 수만큼 메모리가 필요합니다.

각 쌍은 **완전 동일 > 픽셀 동일 > 유사 후보** 중 하나입니다. 대표는 종류, 거리, A 경로 순으로
결정하며 다른 A 매칭을 버리지 않습니다. pHash 0은 픽셀/바이트 동일성을 증명하지 않습니다.
A↔B1과 A↔B2로 B1↔B2를 추론하지 않으며 A1↔B와 A2↔B로 A1↔A2를 추론하지 않습니다.

픽셀 비교는 EXIF orientation 적용 후 RGBA 크기·바이트 기준입니다. 알파 및 완전 투명 픽셀의
RGB 값도 유지합니다. ICC 색 공간 변환은 하지 않아 서로 다른 프로필의 시각적 색상 일치를
보장하지 않습니다. pHash는 흰 배경 알파 합성 후 RGB 기준입니다. JPEG 재압축은 보통 픽셀을
바꿉니다. 지원 형식은 기존과 같은 PNG/JPEG/BMP/정적 WebP/단일 프레임 GIF/TIFF입니다.
외부 디코더, HEIC/RAW, 애니메이션·다중 페이지는 지원하지 않습니다.

## 안전 경계와 캐시

- A/B 루트는 로컬 경로 검사를 통과해야 합니다. 같은 경로·중첩·심볼릭 링크·junction·알려진
  클라우드 placeholder/원격 경로는 차단합니다. 앱 데이터 위치를 포함하는 검색 루트도 거부해
  A/B 폴더 안에 분석 캐시가 기록되는 것을 방지합니다. A와 같은 실파일인 B 하드 링크도 후보에서 제외합니다.
- 이미지의 `root_role`은 서비스에서도 검사합니다. 기존 단일 모드 휴지통 API로 A/B 기록을
  전달해 보호를 우회할 수 없습니다. 전용 서비스도 B 루트 밖의 경로와 A 역할 파일을 거부합니다.
- 이동 직전 B의 경로·일반 파일 여부·크기·mtime_ns·장치·inode·전체 SHA-256을 검사합니다.
  A 근거도 다시 검사하며 유효한 다른 A가 있으면 사용할 수 있습니다. 강한 근거가 사라지고
  유사 후보만 남으면 추가 동의 없이는 이를 대체 근거로 사용하지 않습니다.
- 명시적 확인 없는 backend 호출은 거부합니다. 영구 삭제 fallback은 없습니다. 전체 파일 작업의
  원자성은 보장하지 못하므로 다른 앱이 동시에 폴더를 수정하지 않는 환경에서 사용하세요.

SQLite 위치와 키는 기존과 같습니다. Windows 기본 위치는
`%LOCALAPPDATA%\ImageDuplicateFinder\Image Duplicate Finder\reviews.sqlite3`와
인접한 `reviews.sqlite3.key`입니다. 원본 이미지 폴더에 DB나 썸네일을 만들지 않습니다.

| 테이블 | 보관 정보 |
| --- | --- |
| 기존 reviews | 단일 모드 HMAC 식별자와 기존 보관/삭제 선택. 변경 없음 |
| cross_cache | HMAC cache_id, 크기·mtime_ns·장치/inode·해상도·픽셀 해시·pHash |
| cross_reviews | HMAC review_id와 보관/보류 선택만. 휴지통 예정은 저장·자동 복원하지 않음 |

캐시 ID는 알고리즘 버전·루트·역할·하위 폴더 범위·정규화 경로·파일 정보·SHA-256에 묶습니다.
**전체 경로·파일명·원본 SHA는 평문 저장하지 않고 HMAC 입력으로만 사용합니다.** 요구사항의
재검색 캐시를 기존 최소 저장 보안 정책에 맞춰 구현한 선택입니다. 픽셀 해시/pHash는 분석 재사용에
필요해 로컬 DB에 추가되므로 DB가 식별 가능한 정보를 전혀 포함하지 않는다는 뜻은 아닙니다.
HMAC는 가명화이며 DB 암호화가 아닙니다. 로컬 계정/키가 침해되면 기밀성을 보장하지 않습니다.

캐시가 있어도 매 검색마다 원본 SHA를 스트리밍 재계산해 크기·시간을 유지한 내용 변경을 감지합니다.
캐시 적중 시 디코딩·pHash 계산을 생략하며 임계값 변경에도 분석을 재사용합니다. 미리보기는 선택한
쌍만 읽고 최대 12쌍을 메모리에 보관합니다. 검토 기록은 양쪽 루트·옵션·내용·메타데이터·전체 A 매칭
근거가 같을 때만 복원합니다. A 근거가 달라지면 보관/보류도 미결정으로 돌아갑니다.

분석 캐시는 완료 시 최대 20,000행으로 정리하고 진행 중에도 128회 쓰기마다 제한합니다. 폴더당
일반 파일 100,000개, 총 매칭 200,000쌍, 이미지당 40,000,000픽셀 제한을 둡니다. 파일·쌍 한도
초과는 불완전한 후보를 처리 대상으로 제공하지 않고 검색 실패로 표시합니다. 큰 이미지 제외는
오류 목록에 남깁니다. 워커는 한 번에 하나이며 총 결과 수와 디코딩 메모리는 데이터에 따라 달라집니다.

`두 폴더 캐시·검토 기록 지우기`는 기본 아니요 확인 후 두 새 테이블만 정리합니다. 기존 단일
모드 기록·이미지는 유지합니다. SSD/백업·페이지 파일·운영체제 휴지통 메타데이터까지 삭제하는
보장은 없습니다. 기존 [보안 점검의 운영체제·동기화·네이티브 통신 검증 한계](security-review.md#6-추가로-필요한-동적-검증과-운영-조건)도 적용합니다.

| 20 | Linux native 인터넷 소켓 거부 및 strace 아래 양 모드의 검색/미리보기/확인/휴지통 검사 |
| 21 | 기존 57개 통과·1개 플랫폼 제외 테스트 유지 및 전체 회귀 재실행 |

추가로 캐시 적중 시 재디코딩 생략, 같은 메타데이터의 내용 변경 감지, 역할/옵션별 검토 복원,
휴지통 예정 자동 복원 금지, 저장 실패 시 상태 복구, 기록 삭제 확인도 검사합니다.
Windows 경로 대소문자 검사는 Windows 전용이며 Linux에서 제외합니다. 권한 거부 테스트는
의도적으로 주입한 오류입니다. Windows ACL/일반 사용자 권한 실측과 대규모 실사용 성능 시험은 별도입니다.

2026-10-17 Linux 최종 전체 회귀는 **120 passed, 2 skipped**입니다. 제외된 두 검사는
Windows OneDrive 정책과 경로 대소문자 별칭 검사입니다. 기존 기준선은 57 passed, 1 skipped였습니다.
실제 자동 결과는 `reports/pytest.xml`, CI 플랫폼별 결과는 JUnit Artifact에서 확인합니다.
동일 의존성 51개 버전의 PyPI 권고 조회는 알려진 취약점 0, 누락 0입니다. 이는 전체 네이티브
라이브러리나 미공개 취약점까지 안전하다는 뜻은 아닙니다.
재현 명령:

```bash
uv sync --locked --group security
QT_QPA_PLATFORM=offscreen uv run --locked pytest -q --junitxml=reports/pytest.xml
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked --group security python scripts/audit_dependencies.py
QT_QPA_PLATFORM=offscreen strace -f -e trace=network,process -o reports/offline-syscalls.log .venv/bin/python scripts/offline_probe.py
.venv/bin/python scripts/check_network_trace.py reports/offline-syscalls.log
```

Python 의존성 추가는 없으며 기존 uv.lock의 프로젝트 버전만 갱신합니다. 의존성 조회와 CI 설치·
Artifact 업로드는 개발 단계의 통신입니다. 배포 앱에 업로드/API/자동 업데이트를 추가하지 않았습니다.

## Windows 빌드·실행 검증 범위

두 워크플로는 main/PR 외에 `feature/cross-folder-compare` push에서도 실행합니다.
[Windows executable](https://github.com/dropboxqfml-code/codex/actions/workflows/windows-build.yml)에서
**브랜치와 커밋을 확인하고 성공한 실행**의 `ImageDuplicateFinder-Windows-x64-실행번호`를 받으세요.
ZIP 전체를 풀고 `Image Duplicate Finder/Image Duplicate Finder.exe`를 실행합니다.
기존 [빌드/서명·Defender 안내](windows-build.md)와 동일하며 Python/uv 별도 설치는 필요하지 않습니다.

CI는 테스트·취약점 조회·빌드·번들 통신 DLL 검사 이후 실제 frozen exe를 qwindows로 실행합니다.
기존 단일 모드에 이어 A/B 합성 폴더 검색, 바이트/픽셀/유사 분류, 두 이미지 미리보기, B 상태 선택,
아니요 보존, 예 확인 후 B 사본만 휴지통 이동, A 보존과 실제 휴지통 바이트를 확인합니다.
`frozen-smoke.json`, 두 화면 PNG, JUnit, 번들 목록이 reports Artifact에 남습니다. 하나라도
실패하면 실행 파일 Artifact를 배포하지 않습니다. 이 문서의 절차가 해당 커밋의 CI 성공 자체를
증명하지는 않으며 실행 페이지 결과와 BUILD-INFO의 commit을 확인해야 합니다.

Python 없는 망분리 PC, DPI/장시간/대량 사진, 실제 휴지통 복원, Windows 패킷 캡처, 모든 네이티브
