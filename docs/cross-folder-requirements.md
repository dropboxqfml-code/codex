# Cross-Folder Image Duplicate Finder — Codex 개발 요구사항 v1.0

> 목적: **서로 다른 두 폴더 A(기준·보호)와 B(검사·정리 대상) 간** 동일 또는 유사한 이미지를 검색하고, 사용자가 **B의 파일에 대해서만** 보관·보류·휴지통 이동 여부를 결정하는 오프라인 Windows 데스크톱 프로그램.
>
> 작성 기준: 기존 단일 폴더용 Image Duplicate Finder의 Python/PySide6 프로젝트를 재사용하는 **확장 개발안**. 실제 저장소의 코드 구조·함수·의존성은 Codex가 먼저 확인한다.

## 1. 프로젝트 목표와 기본 정책

- **플랫폼:** Windows 10/11, 한국어 GUI, 로컬·오프라인 실행.
- **개발 방식:** 기존 저장소에 별도 비교 모드("단일 폴더 내부 비교" / "두 폴더 간 비교")를 추가한다. 기존 단일 폴더 기능과 테스트는 유지한다.
- **기준 폴더 A:** 비교 대상이 되는 원본 보관 폴더. 앱에서 변경·이동·삭제 불가.
- **대상 폴더 B:** A에 있는 이미지와 같은지 조사할 폴더. 사용자 검토 및 별도 확인 후 **B의 파일만** 휴지통 이동 가능.
- **비교 범위:** 오직 A↔B 비교. A↔A 또는 B↔B 중복은 이 모드에서 보고하지 않는다.
- **폴더 간 검색:** 파일명·확장자가 달라도 실제 바이트/픽셀/시각적 특징으로 비교한다.
- **삭제 정책:** 자동 삭제, 영구 삭제, 자동 삭제 대상 선택 없음. 후보는 사용자 검토 전에는 모두 **미결정**.
- **보안 정책:** 개인 사진·썸네일·파일 경로·해시를 업로드하지 않는다. 실행 중 외부 API·텔레메트리·자동 업데이트 없음. CI 테스트에는 생성된 가상 이미지나 공개 테스트 픽스처만 사용.

### 주요 사용자 시나리오

1. 사용자가 보존해야 할 사진 10,000장이 있는 A와, 정리할 사진 8,000장이 있는 B를 지정한다.
2. A/B 각각 하위 폴더 검색을 설정하고, pHash 허용 거리를 선택한다.
3. 프로그램이 A↔B 동일 파일/동일 픽셀/유사 이미지 후보를 검색한다.
4. 결과에서 **A의 기준 사진과 B의 후보 사진을 나란히** 확인한다.
5. 사용자가 B의 후보마다 `보관`, `보류`, `휴지통 이동 예정` 중 하나를 선택한다.
6. `휴지통 이동 예정` 파일을 경로·개수와 함께 재확인하고, 변경 검사 후 운영체제 휴지통으로 보낸다.
7. A는 처음부터 끝까지 읽기 전용으로 취급하고, 실행 결과와 오류를 표시한다.

## 2. 범위 및 제외 사항

### MVP 필수

- 기존 앱에 "두 폴더 간 비교" 모드 추가. 단일 폴더 모드 유지.
- 폴더 A/B 각각 선택·경로 표시·하위 폴더 포함 여부(기본 꺼짐).
- 경로 검증: A와 B가 같거나 한쪽이 다른 쪽의 상위/하위 폴더이면 비교 시작 전 명확히 경고하고 차단. 심볼릭 링크/정션 경로와 경로 대소문자·정규화도 고려. 중첩 폴더 지원은 추후 별도 설계.
- 지원 정적 이미지: JPEG/JPG, PNG, BMP, 정적 WebP, 단일 페이지 TIFF. 이미지 파일을 실제 디코딩해 검증.
- A↔B 후보의 (1) 바이트 완전 동일 (2) 픽셀 동일 (3) 시각적 유사 구분.
- 좌우 썸네일/원본 미리보기, 파일 정보, 판별 유형, pHash 거리.
- 각 B 파일의 보관/보류/휴지통 이동 예정 선택(기본 미결정). A 선택 UI는 읽기 전용.
- 휴지통 이동 전 사용자 확인, 실파일 변경 확인, 실패 시 안전하게 중단.
- 검색 진행률·취소·오류 목록·백그라운드 실행.
- 재검색용 로컬 캐시 및 검토 상태의 조건부 복원.
- 한국어 안내, 테스트, README, Windows 패키징 안내.

### 후속 릴리스

- 3개 이상 폴더 비교, 폴더 쌍 일괄 비교, 비교 설정 프리셋.
- CSV 보고서 내보내기(경로/해시 개인정보 주의 안내 포함), 동기 확대·비교 화면.
- 크롭/회전/좌우 반전/부분 이미지 검색(별도 알고리즘과 오탐 방지 필요).
- HEIC/RAW/애니메이션 이미지 지원, 대규모 탐색 고급 최적화.

### MVP 제외

- 폴더 A 파일 변경·삭제, B의 자동 삭제·영구 삭제·폴더 전체 정리.
- 이미지 클라우드 업로드, 외부 인공지능 서비스, 웹 계정·서버.
- 원본 이미지에 EXIF 수정·압축·변환 등 쓰기 작업.

## 3. UI/UX 요구사항

### 3.1 메인 화면

- 상단 **비교 모드 선택:** `폴더 내부 중복 검색` / `서로 다른 두 폴더 비교`.
- 두 폴더 비교 화면:
  - `폴더 A — 기준 원본 (보호됨)` 선택 버튼과 전체 경로
  - `폴더 B — 정리 대상` 선택 버튼과 전체 경로
  - 각 폴더의 `하위 폴더 포함` 체크박스(독립 설정)
  - `A/B 폴더 바꾸기` 버튼: **실행 중에는 비활성화**, 실행 전 역할 설명 후 변경
  - `유사 이미지 찾기` 사용 여부와 pHash 거리 설정(기본 6, 0~12)
  - `검색 시작`, `검색 취소`, 파일수·진행 단계·오류 건수 표시
- 초기 파일 개수 표시 등은 검색 단계에서 계산되므로 UI 스레드를 멈추지 않음.

### 3.2 결과 화면

- 상단 요약: A/B 스캔 이미지 개수, 발견된 B 후보 파일 수, 매칭 쌍 수, 종류별 건수, 오류 건수.
- 결과 탭: `완전 동일`, `픽셀 동일`, `유사 후보`, `제외/오류`.
- 기본 보기: **A 이미지(좌측) ↔ B 이미지(우측)** 한 쌍 비교. 파일별 썸네일·미리보기·파일명·전체 경로·바이트 크기·해상도·확장자·수정시각 제공.
- 판별 이유 표시: 완전 동일 / 픽셀 동일 / pHash 거리 `n` (확률이나 정확도 퍼센트로 표현 금지).
- B 하나가 A 여러 장과 일치할 수 있으므로, `B 후보 1개`를 중심으로 가장 신뢰도 높은 매칭을 대표로 표시하고 다른 A 매칭도 열람 가능하도록 제공.
- A 이미지에는 `보호된 기준 원본` 표시, 삭제·이동 선택 컨트롤을 두지 않음.
- B 이미지의 기본 처리 상태는 `미결정`; 수동으로 `보관` / `보류` / `휴지통 이동 예정` 선택. 보류/보관은 모두 원본 파일 유지(차이는 사용자 검토 상태).
- 필터: 미결정/보관/보류/휴지통 예정, 일치 유형, 파일명 검색. B 파일이 여러 매칭에 등장하더라도 **상태는 B 파일 단위로 하나**만 존재.
- 자동 미리보기 캐시 및 지연 로드. 대규모 결과 목록이 GUI를 멈추게 하지 않음.

### 3.3 처리 및 확인 화면

- `휴지통 이동 예정 N개` 버튼을 누르면 B 파일의 전체 경로·개수·일치 유형을 보여주는 최종 확인 창 표시.
- 유사 후보로만 매칭된 파일은 `시각적으로 비슷하지만 동일 사진이 아닐 수 있음` 경고를 명확히 표시하고 추가 확인 요구.
- 확인 시 각 B 파일은 한 번만 휴지통에 이동하며, 성공/실패/건너뜀 사유를 보여줌.
- 이동 후 결과는 즉시 갱신하고, 동일 파일의 다른 후보 행에도 변경 상태가 반영됨.

## 4. 매칭 엔진 설계

### 4.1 탐색과 인덱싱

- A와 B 이미지 목록을 **별도** 수집. 이미지 형식 판별과 손상 파일 처리를 분리.
- A용 검색 인덱스 생성 → B의 각 이미지에 대해 A 인덱스에서만 매칭.
- A↔A 또는 B↔B 비교 루프를 생성하지 않는다.
- 파일명·확장자·경로는 메타데이터이며 동일성 판단 조건으로 사용하지 않는다.
- 심볼릭 링크 및 정션은 기본적으로 따라가지 않고, 실제 경로 중복/중첩을 감지한다. 무한 순회 금지.
- A/B 스캔된 고유 파일 식별자를 관리하여 동일 파일 경로가 양쪽에 포함되지 않도록 검사한다.

### 4.2 비교 우선순위

1. **완전 동일:** 파일 크기로 후보를 줄인 뒤 SHA-256 스트리밍 비교. A와 B 사이에서 해시가 같으면 `바이트 완전 동일`.
2. **픽셀 동일:** EXIF orientation 처리 후 일관된 디코딩·색상 모드로 정규화한 픽셀 크기 및 내용의 해시 비교. JPG↔PNG처럼 컨테이너가 달라도 실제 픽셀이 동일하면 `픽셀 동일`. 색 공간/ICC 프로파일 및 알파 처리 범위와 한계를 문서화.
3. **유사 후보:** 정규화된 시각 콘텐츠의 64비트 pHash(hash_size=8) 계산, 해밍 거리 임계값 비교. 첫 권장 설정 `6`, 사용자가 `0~12` 조정 가능. **pHash 거리 0도 픽셀 동일/완전 동일을 증명하지 않으며**, 앞선 검사에 통과하지 않으면 유사 후보로만 분류.
4. 우선순위 `완전 동일 > 픽셀 동일 > 유사 후보`. 하나의 A-B 쌍에 중복 유형을 여러 개 부여하지 않는다.
5. 유사도 임계값은 검색 후보 범위를 정하는 기준이지 실측 정확도/확률 퍼센트가 아니다. 유사해도 다른 사진일 수 있으므로 자동 삭제 결정을 해서는 안 됨.

### 4.3 속도·결과 일관성

- A의 SHA-256/픽셀 해시를 해시맵에 구축해 B를 조회한다.
- A의 pHash 검색은 BK-tree 등 해밍 거리 인덱스를 사용하거나 그에 준하는 효율적인 인덱스를 사용. 기본 구현을 무조건 A 수 × B 수의 전수 비교로 작성하지 않는다.
- 한 B가 여러 A와 일치하면 A 매칭 전체를 보관하되 B 파일 단위로 중복 결정을 단일화한다. 가장 강한 판별 유형, 그다음 pHash 거리 등을 기준으로 대표 매칭을 선택한다.
- `A↔B1` 및 `A↔B2` 결과가 있다고 B1↔B2의 동일성을 단정하지 않는다. `A1↔B` 및 `A2↔B`가 있다고 A1↔A2의 동일성을 단정하지 않는다. 유사 관계의 추이성 가정 금지.
- 고해상도 이미지의 디코딩 리소스를 제한하고, 파일 단위 에러 시 전체 검색 계속 진행.
- A와 B가 큰 경우 검색·해시·썸네일 생성은 워커(QThread/QRunnable 등)에서 처리. UI 스레드에서 대용량 처리를 하지 않는다. 메모리와 동시 실행 작업자 수를 제한한다.
- 임계값 변경만 발생하면 기존 pHash 캐시를 활용하여 후보 결과를 재평가할 수 있도록 설계한다.

## 5. 파일 및 삭제 안전장치 (필수)

- A는 읽기만 허용. UI/서비스 계층 둘 다에서 `root_role == A`이면 휴지통 이동을 거부.
- 검색 시작 전 A와 B가 동일 경로이거나 중첩된 경로인지 판정하고 차단. 심볼릭 링크/정션·Windows 경로 규칙도 고려.
- B 파일의 기본 상태는 `미결정`; 어떤 종류의 매칭도 자동으로 삭제 대상으로 체크하지 않는다.
- 실제 이동 직전에 반드시 B 파일의 실경로·존재·정규화 경로·파일종류·수정 여부를 재검사. 스캔 당시 내용 해시를 저장해 **내용이 바뀐 파일을 거부**하도록 한다.
- 삭제 근거가 된 A 파일이 삭제·변경·접근불가 상태가 된 경우 그 근거에 의한 B 이동은 거부하거나 재검사 요구. A가 여럿이라면 유효한 다른 A 매칭 근거가 있는지 다시 확인.
- 휴지통 이동은 Send2Trash만 사용; 실패 시 `os.remove`·`Path.unlink` 등 영구 삭제로 대체 금지.
- 네트워크 드라이브·외장 저장장치에서 휴지통을 지원하지 않으면 해당 작업을 거부하고 설명. 드라이브 유형을 사전 완벽 판별할 수 없다면 Send2Trash 실패 시 중단한다.
- 사용자 확인 이후에도 작업 중 선택되지 않은 파일 또는 A의 파일이 이동되지 않도록, 파일 목록·경로 검증과 로직 테스트를 수행.
- 검색과 미리보기에서 원본 파일은 읽기 전용으로 다루고, 이미지 폴더 안에 캐시/썸네일 파일을 만들지 않는다.
- 보호된 A 폴더에 기존 A 이미지와 일치하는 사진이 있다는 사실만으로 B 사진을 무조건 지워도 된다는 의미는 아님: 화질/메타데이터/압축 차이와 보관 필요성은 사용자 판단.

## 6. 캐시/보안/품질

- SQLite 앱 데이터 폴더에 `검색 캐시(경로·역할/스캔 범위·파일 크기·mtime_ns·해시 및 알고리즘 버전)`와 `검토 상태` 저장. 파일 변경 시 결과/상태 무효화. 정확한 스키마는 현재 프로젝트와 호환되도록 설계.
- 파일명, 전체 경로, SHA-256 및 썸네일은 개인 정보를 유추할 수 있으므로 캐시·로그를 사용자 PC 외부로 송신하지 않는다. 원본 이미지나 썸네일을 로그에 저장하지 않음.
- 앱 실행 중 네트워크 API·자동 업로드·원격 업데이트·텔레메트리가 없음. GitHub Actions나 빌드 의존성 내려받기는 **개발·배포 단계의 네트워크 활동**으로 별도로 구분.
- CI에는 실제 개인 사진을 사용하지 않는다. 테스트 데이터는 Pillow 등으로 생성한 합성 이미지 기반.
- 소스·외부 라이브러리·배포 아티팩트의 보안 검증 결과는 각각 구분. Chrome이나 Defender 탐지를 피하려고 난독화/보안기능 비활성화 요구 금지.
- 기존 단일 폴더 모드 동작을 회귀 테스트로 보호.
- Windows용 .exe 빌드가 가능하더라도 **실제 Windows GUI 수동 검증**과 CI 자동 테스트는 구분하여 보고한다.

## 7. 필수 수용 테스트

### 탐색·매칭

1. A에 `a.jpg`, B에 내용이 같은 `x.jpg` → 완전 동일 (이름은 다름).
2. A와 B에 내용은 같으나 파일명도 다름 → 동일 판정.
3. A에는 PNG, B에는 BMP로 저장한 동일 픽셀 이미지 → 픽셀 동일.
4. A에 원본, B에 JPEG 재압축·축소한 이미지 → 적절한 임계값에서 유사 후보(정확히 매칭되는 사례를 합성 테스트 픽스처로 선정).
5. A와 B에 서로 무관한 사진 → 잘못 매칭될 수 있음을 인정하되, 지정된 검증용 테스트에서는 탐지 오탐 회귀 방지.
6. A 내부에만 같은 사진 2장, B에는 해당 이미지 없음 → **결과 없음**.
7. B 내부에만 같은 사진 2장, A에는 해당 이미지 없음 → **결과 없음**.
8. 한 B 이미지가 A 여러 이미지와 맞을 때 → 다중 매칭은 표시되되 삭제 결정은 해당 B 파일에 하나만 존재.
9. A와 B 폴더가 동일하거나 중첩 → 검색 차단, 명확한 메시지.
10. A/B 중 하위 폴더 옵션을 독립적으로 켜고 끄기; 한글·공백·긴 경로·손상 파일·권한 부족 테스트.
11. 검색 중 취소, 큰 파일, 많은 파일 처리 시 화면 응답 유지 및 원본 변경 없음.

### 안전

12. A의 이미지에 이동/삭제 액션 요청 시 UI 뿐 아니라 내부 서비스 API에서 차단.
13. 모든 B 후보는 최초 `미결정`; 보관 및 보류는 절대 이동하지 않음.
14. `휴지통 이동 예정` B 파일만 최종 확인 후 처리, 미선택 파일은 보존.
15. 검색 후 B 파일 내용 변경(가능하면 mtime·크기 유지한 변경도 포함) → 이동 차단.
16. 검색 후 매칭한 A가 변경되거나 삭제 → B 이동 차단 또는 근거 재검사.
17. Send2Trash 실패 또는 취소 → 영구 삭제 없이 파일 보존.
18. 휴지통 이동 실패 시 예외 처리와 결과 갱신.
19. 동일 B가 여러 결과 쌍에 등장해도 중복 이동 시도 없음.
20. 오프라인 환경에서 전체 검색/미리보기/보류/안전한 휴지통 이동 기능 작동(실행 환경에서 검증 가능한 범위를 분명히 기록).
21. 기존 단일 폴더 모드의 테스트를 모두 재실행해 동작 유지 확인.

## 8. Codex 개발 작업 순서

1. **현황 분석:** 현재 GitHub 저장소 구조, 기존 스캔/매칭/GUI/파일 작업 모듈, 의존성, 테스트 상태 조사. 없는 기능을 있다고 가정하지 않는다.
2. **개발 계획:** 기존 단일 모드를 유지하면서 두 폴더 모드를 추가하는 최소 변경 계획을 제시한다. 변경 파일, 데이터 모델, 테스트 전략 명시.
3. **새 개발 브랜치:** 가능하면 `feature/cross-folder-compare` 브랜치에서 작업하고, 사용자 검토를 위한 PR로 제시. 저장소 권한/환경에 따라 대체 절차 안내.
4. **핵심 구현:** A/B 별 스캔, 경로 보호, A 인덱스/B 후보 매칭, 일치 유형 분류 및 후보 모델.
5. **화면 구현:** A/B 선택, 각 하위 폴더 옵션, 비교 결과 및 상태 선택, 최종 삭제 확인.
6. **안전 보호 구현:** B만 휴지통 이동 가능한 서비스 API, 파일 변경·근거 A 재검사, 실패 안전 처리.
7. **자동 테스트:** 합성 이미지 기반 21개 수용 시나리오 및 기존 회귀 테스트.
8. **검증/배포:** 현재 프로젝트의 Windows 빌드 작업과 통합하고 실제 검증된 항목·미검증 항목을 명확히 보고. 다운로드 차단 문제가 있었던 경우 탐지 우회가 아닌 원인 분석.
9. **결과 보고:** 구현 기능, 변경 목록, 테스트 건수/결과, 알려진 한계, 설치·실행 방법, 다음 개선점.

## 9. 구현 품질 합격 기준 (Definition of Done)

- 두 폴더 모드로 지정한 **A↔B** 매칭만 표시되고, 단일 폴더 모드에 회귀 문제가 없다.
- 파일명·확장자가 달라도 바이트/픽셀/유사 후보를 탐지할 수 있다.
- 동일 B 파일의 다중 매칭 정보와 단일 상태가 정확히 연결된다.
- A 보호는 UI뿐 아니라 삭제 서비스 코드와 테스트로 강제된다.
- 삭제는 명시적 선택과 최종 확인 후 B 파일에 대해서만 운영체제 휴지통으로 이동한다.
- 원본 수정 없음, 외부 전송 기능 없음, 스캔 취소·예외 처리가 가능하다.
- README, 자동 테스트 결과, 기능 제한, Windows .exe 빌드 및 실제 실행 검증 범위가 제공된다.
