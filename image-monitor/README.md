# Image Monitor — 개발 중

Windows에서 공개 게시글의 본문 이미지를 감시하고 브라우저 네이티브 저장 창으로
저장하는 별도 프로젝트입니다. 기존 Image Duplicate Finder는 그대로 유지합니다.
현재는 **로컬 정책·검증·영구 대기열 구현** 단계이며 실제 감시·수집 프로그램은 아직 아닙니다.

Windows 전용 [이미지 1장 네이티브 저장 시험](docs/native-probe.md)을 추가했습니다.
전용 브라우저에서 합성 이미지를 실제 우클릭/저장 창으로 저장하고 원본 해시와
비교하는 명령입니다. Windows UI 실검증은 아직이며, Linux 모의 테스트와 구분합니다.
미해결 저장은 세션 공통 상태로 보존하며, 다른 작업 루트로 실행해도 차단됩니다.
실패 후에는 전용 브라우저를 닫고 안내된 `native-recover` 명령으로 복구합니다.

## 현재 구현

- Asia/Seoul 작성일/최초 발견일 경로 계획과 작성일 누락 사유.
- 날짜 계획 직렬화/복원 및 발견 시 DB 영구 고정.
- Windows 금지 문자·예약 이름·대소문자/정리값 충돌 방지용 결정적 접미사,
  저장 루트 이탈·심볼릭 링크 이탈·경로 길이 검사.
- 최초 시도 포함 8회/최초 실패 24시간 한도, 단기 5회와 장기 2회 재시도 계산,
  추가 지연과 Retry-After 초/HTTP-date·공통 대기 중 가장 늦은 시각 적용.
- 완료된 로컬 파일을 Pillow verify 후 재오픈/load하고 모든 프레임 검사,
  실제 형식/크기/SHA-256 산출. 바이트 변경·재인코딩 없음.
- 파일·프레임·누적 픽셀·시간 검사 한도. 한도 초과와 손상 오류 구분.
- 수집이나 폴더 생성을 하지 않는 경로 시험 명령, 기존 파일 검증 명령.
- [SQLite 영구 대기열](docs/queue.md): 발견/검색어 이력/확인 지점의 원자적 저장,
  안정적 이미지 작업 ID·파일 슬롯, 동시 선점, 재시도·공통 대기 보존과 중단 작업 보류.
- 로컬 합성 대기열 시험 `queue-demo`, 읽기 전용 상태 조회 `queue-status`.

경로 구성은 `감시이름/실제ID/날짜/작성자/글번호`입니다. 이름 충돌 방지를 위해
감시 이름과 작성자 폴더에 원문 기반 해시 접미사를 항상 붙입니다.
공개 IP는 입력된 표시값만 사용하며 추가 추정하지 않습니다.

## 설치·개발

Python 3.12와 uv가 필요합니다. 이 디렉터리에서 실행합니다.

```powershell
uv sync --locked
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked image-monitor plan --root D:/Images --watch 만화 --gallery comic_new6 --post 123456 --nickname 예시 --first-seen 2026-11-14T23:59:00+09:00
uv run --locked image-monitor verify D:/Images/completed.webp --writer-finished
```

Linux에서도 위 로컬 명령과 테스트는 가능합니다. `--writer-finished`는 호출자가
브라우저의 쓰기 종료를 확인했다고 명시하는 옵션으로, 크기 안정화를 자동 탐지하는
기능이 아닙니다. 검증 성공은 파일 자체에 대한 결과이며 본문 이미지와의 대응,
브라우저 저장 완료, 최종 파일 확정/메타데이터 저장까지 보장하지 않습니다.
Pillow 단일 디코딩 호출을 강제 중단하는 프로세스 격리는 아직 없습니다.

## 다음 개발 단계와 검증 경계

1. **Windows 선행 검증:** 로그인된 대화형 세션에서 전용 Edge/Chrome 프로필로
   이미지 1장을 실제 우클릭 → 메뉴 식별 → 저장 창 조작으로 저장합니다.
   OS/브라우저 버전·언어·배율·모니터 조건과 창 소유권·잠금 시 중단을 기록합니다.
   현재 Linux 환경에서는 실제 Windows UI를 검증할 수 없습니다.
2. 검증된 UI 경로를 Playwright + pywinauto 어댑터로 연결합니다. 직접 HTTP 저장,
   응답 바이트 추출, download.save_as, 스크린샷으로 대체하지 않습니다.
3. 본문 전용 파싱·이미지 로딩 검사·첨부 목록의 근거 기반 이름 매칭과
   세 파일명(공개 첨부명/저장 창 제안명/최종명)을 분리합니다.
4. 구현된 SQLite 대기열/확인 지점·시도 이력·날짜 경로 고정을 실제 작업자에 연결하고,
   회로 차단·중지/재개, staging/최종 이동/DB/JSON 사이 장애 복구를 구현합니다.
5. 새 글 우선 60초 감시·누락 구간 보고·다중 갤러리·설정과 열람 UI를 연결합니다.

일반/마이너/미니 갤러리의 실사이트 DOM, 정기 감시와 파일 확정/재시작 대조 복구는
**미구현**입니다. 대기열은 재시작 후 유지되며 미확정 활성 작업은 수동 확인 상태로 보존합니다.
실제 저장 창 어댑터와 단일 이미지 시험 명령은 구현했지만 **Windows에서 미검증**입니다.
이 프로젝트는 아직 사이트에 접근하지 않습니다.
인증정보를 로그로 남기거나 수집 파일을 자동 삭제하는 기능은 없습니다.
환경 설정 변경 및 환경 게시 작업도 수행하지 않습니다.
