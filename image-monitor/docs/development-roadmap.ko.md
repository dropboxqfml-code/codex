# Image Monitor 개발 단계와 버전 계획

검토 기준은 2026년 11월 14일자 「이미지 모니터링 프로그램 Windows용 설계안」 개정 2판과
v23 및 이후 버전별 사용자 시험 기록이다. 설계안의 목표는 Windows에서 공개 검색 결과의 새 글을
주기적으로 발견하고, 본문 이미지를 실제 우클릭으로 저장한 뒤 파일과 메타데이터를 검증하며,
중단 후에도 남은 작업을 이어가는 것이다. [버전별 시험 기록](validation.md)

## v23에서 어디까지 동작하는가

v23은 정지 상태로 열린다. 사용자가 감시를 시작하면 기본 60초 간격으로 새 글을 SQLite에
기록한다. 간격은 앞선 관찰이 끝난 뒤부터 계산하고, 서버가 더 긴 대기를 지정하면 이를 따른다.
이 버전의 상세 확인은 감시를 멈춘 뒤 요청한다. 이후 배치 실행기를 열고 전용 Chrome에서
게시글별로 저장을 시작하면 검증된 파일 규칙을 적용한다. 사용자 v23 결과에는 내용 미확인
후보 1개, 저장 완료 2건, 기존 JPEG 2장의 재검증과 정상 종료가 기록됐다. [v23 검증 기록](validation.md#사용자-v23-완료-2건내용-미확인-1건의-현황-확인과-정상-종료)

| --- | --- | --- |
| §1~2 Windows 저장·본문 선별 | Edge와 Chrome에서 합성 이미지의 실제 메뉴 저장에 성공했다. 실사이트 통합 저장은 전용 Chrome에서 본문 요소와 로딩 상태를 확인하고 우클릭·저장 창을 조작한다. | 통합 Edge, 지원 애니메이션의 실사용 저장, 본문 디시콘 설정, 다양한 본문 구조·배율·잠금·전경 전환 검증 |

v23의 전체 회귀 결과는 Linux 2,638개 통과·333개 건너뜀, Windows CI 2,967개 통과·4개
건너뜀이다. CI는 시험 페이지에서 실제 Windows 메뉴와 저장 창을 조작한다. 사용자 PC에서
확인한 실사이트 범위는 위 표와 같이 게시글·갤러리별로 기록한다. [검증 기록](validation.md) · [요구사항별 상세 검토](project-review.md)

## 버전 정책

기존 `v1`~`v23`은 Windows 시험 ZIP 번호로 보존한다. v1~v10은 기본 저장과 한 게시글
전체 저장, v11~v16은 검색 후보의 발견·상세 확인·한정 저장과 종료 복구, v17~v23은
로컬 감시 화면·배치 저장·결과 열람과 작업 현황을 검증한 시기다. 당시 배포물과 시험
기록은 원래 번호로 찾을 수 있다. [기존 배포 이력](validation.md)

새 개발판부터 배포물과 프로그램에 같은 제품 버전 `주버전.기능단계.수정번호`를 사용한다. 새 체계의 첫 표기는
**0.4.0-alpha.1**이다. `0.4`는 앞선 세 검증 단계에 이어 단일 갤러리의 발견·상세·저장을
연결하는 단계다. 같은 단계에서 기능 범위를 넓히는 동안 `alpha`, 합의한 기능이 모두
연결되어 실제 사용 조건을 확인하는 동안 `beta`, 정식 후보에 대해 전체 회귀와 Windows
인수를 진행할 때 `rc`를 붙인다. 접미 번호는 그 단계에서 배포한 판을 식별한다.
단계 배포 후 같은 기능의 결함만 고칠 때 수정번호를 올린다. SQLite 스키마 번호는 실제
데이터 형식 변경에 맞춰 독립적으로 관리한다.
