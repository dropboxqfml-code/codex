# 검색 목록과 감시 기준점 — 개발 단계

사용자 v10 시험에서 검증한 게시글 하나의 이미지 4개 저장과 재개를 완료했습니다.
다음 단계는 검색 목록 발견을 이미지 저장과 분리하는 것입니다. 목록 선택자와 페이지 이동은
아직 실제 사이트에서 검증하지 않았으며, 현재 정기 감시나 새 글 자동 저장을 시작하지 않습니다.

## 읽기 전용 목록 검사

`RUN_LIST_INSPECTION.cmd`는 설치된 Chrome을 화면 없이 실행해 기본 검색 목록 한 페이지를
읽고 닫습니다. 초기 범위는 일반 갤러리 `comic_new6`, 제목+내용 검색
`search_subject_memo`, 검색어 `ai`입니다. 사용자 절차는 ZIP 안의 안내 TXT 하나에 정리합니다.

목록·행·제목 링크·번호·표시 작성자·작성 시각 원문·페이지 이동 후보와 DOM 구조를 기록합니다.
작성 시각이 `13:00`처럼 보이면 원문 그대로 남기며 날짜나 시간대를 추정하지 않습니다.
공지·광고·다른 갤러리 행을 구분하고, 번호와 링크가 충돌하거나 필드가 모호하면 근거를 남깁니다.
빈 목록 표시와 목록 구조를 찾지 못한 경우도 별도 상태로 기록합니다.

검사는 페이지 탐색 한 번으로 제한합니다. 첨부 링크나 페이지 이동 후보를 클릭하지 않고,
이미지 저장·대기열 기록·네이티브 저장 창 조작을 수행하지 않습니다.
HTTP 오류·차단·연결 오류는 보고하고 반복 탐색하지 않습니다.
결과는 `inspected_unverified`이며 이것은 관찰 보고서가 생성됐다는 뜻입니다.
실제 목록 검증·새 글 수집 가능 여부는 보고서의 구조를 검토한 뒤 판단합니다.
공유 보고서는 쿠키·인증 헤더·로컬 보고서 경로를 제외하고 과거 검색 커서를 해시로 표시합니다.

일반·마이너·미니 URL 형식과 합성 DOM은 검사하지만 실제 목록 검증은 모두 대기 중입니다.
본문의 기존 `site_verified` 상태가 검색 목록까지 검증됐다는 의미는 아닙니다.

## 독립적으로 구현한 감시 계획

`watch_planner.plan_scan`은 현재 명시적인 합성 fixture 입력만 허용합니다.
브라우저를 실행하거나 이미지를 저장하지 않으며 다음 규칙을 검증합니다.

- 매 주기는 커서가 없는 최신 1페이지부터 시작합니다. 과거 검색 위치를 다음 최신 주기에 재사용하지 않습니다.
- 첫 정상 관찰은 `new` 기준점과 정확한 게시글 ID 목록을 기록하고 기존 행을 수집 후보로 만들지 않습니다.
- 다음 관찰에서는 마지막 완료 지점의 정확한 ID에 도달한 뒤 한 페이지를 겹쳐 읽거나,
  명시적인 합성 마지막 페이지 근거를 확보해야 완료로 처리합니다.
- 최대 글번호만으로 확인 완료를 선언하지 않습니다. 범위·순서·행 정체성·빈 목록 근거가
  불확실하면 기준점을 전진하지 않고 미확인 구간으로 기록합니다.
- 공지·광고·검증된 외부 행처럼 명확한 제외와, 필드 충돌·누락으로 읽지 못한 행을 구분합니다.
  모호한 행이 있으면 기준점을 전진하지 않아 다음 관찰에서 복구할 수 있게 합니다.
- 같은 검색 범위에서 실제 관찰한 다음 페이지 링크만 사용합니다.
  `search_pos` 변경이 정확히 다음 과거 검색 구간이라는 근거는 아직 없어 미확인 상태로 남깁니다.
- 목록에서 새로 보였다는 사실은 실행 이후 작성됐다는 증거가 아닙니다. 후보에
  `requires_published_at_filter`를 남기며, 향후 상세 페이지의 작성 시각으로 확인해야 저장할 수 있습니다.

`next_poll_at`은 정상 완료 뒤 기본 60초와 관측한 서비스 대기 시각 중 늦은 시각을 계산하는
순수 함수입니다. 실제 반복 실행·중복 탐색 잠금·회로 차단 연결은 다음 단계입니다.

## 영구 기록과 경로 고정

SQLite v4의 별도 `watch_*` 테이블에 기준점·후보·관찰·미확인 기록을 저장합니다.
세대 번호를 비교하는 하나의 트랜잭션으로 관찰과 후보를 기록하므로 오래된 작업이나 경쟁
작업이 확인 지점을 덮지 못합니다. 불완전한 탐색도 후보와 후속 커서를 보존하지만 마지막
완료 기준점은 그대로 유지합니다. 미확인 구간의 자동 해결 처리는 아직 연결하지 않았습니다.

목록 후보는 `posts`나 이미지 작업을 생성하지 않습니다. 목록의 불완전한 작성자·시각으로
최종 폴더를 미리 고정하지 않으며 상세 게시글 검증과 연결할 때 경로를 정합니다.
기존 게시글·파일 슬롯·이미지 확정 기록과 사용자 저장 파일은 유지됩니다.

개발자는 새 DB로만 합성 통합 시험을 실행할 수 있습니다.

```powershell
uv run --locked image-monitor watch-demo --db ./reports/watch-demo.sqlite
```

이 시험은 첫 기준점 → 페이지 상한으로 중단 → DB 재연결 → 정확한 기준점과 겹친 구간 확인을
검사합니다. 후보 2개·관찰 3개·과거 미확인 기록 1개를 보존하고 이미지 작업은 생성하지 않습니다.
DB v1/v2/v3의 정확한 알려진 스키마만 원자적으로 v4에 추가 마이그레이션하며,
읽기 전용 조회는 기존 버전을 변경하지 않습니다.
