# 실제 사이트 DOM 확인 기록

## 2026-11-15: 클라우드 탐색 연결 실패

대상 검색 URL:

`https://gall.dcinside.com/board/lists/?id=comic_new6&s_type=search_subject_memo&s_keyword=ai`

프로젝트의 잠금 의존성에 포함된 Playwright와 설치된 `/usr/bin/chromium`을 사용해,
새 임시 브라우저 컨텍스트에서 일반 페이지 탐색을 한 번 시도했습니다.

결과는 `Page.goto: net::ERR_TUNNEL_CONNECTION_FAILED`입니다. HTTP 응답과 사이트 DOM을
받기 전의 연결 실패이므로 HTTP 403/429, 사이트 접근 차단 또는 DOM 변경으로 판정하지 않습니다.
다른 프로토콜·프록시·접근 경로나 정책 변경으로 재시도하지 않았습니다.

따라서 이번 실행에서 확인된 실제 게시글·본문 선택자·작성자/날짜 속성·첨부 목록 구조나
본문/첨부 공통 식별자는 없습니다. 게시글과 첨부 링크를 열거나 직접 이미지 요청을 보내지
않았으며 응답 바이트 저장과 스크린샷도 사용하지 않았습니다.

## 구현과 검증의 구분

합성 HTML을 사용하는 파서 검사는 실제 사이트 호환성 검증과 구분해야 합니다.
특정 본문 선택자 또는 URL의 식별자 규칙을 실제 사이트에서 확인된 것으로 표시할 근거는
아직 없습니다. 본문이 없거나 중복되면 페이지 전체 이미지 수집으로 대체하지 않습니다.

실사이트 어댑터의 검증 범위를 넓히려면 정상 탐색이 가능한 환경에서 본문·첨부 DOM과
공통 식별자 근거를 별도로 확인해야 합니다. 이름·개수·순서만으로 원본 첨부명을 확정하지
않으며, 불확실한 대응은 원본명 `null`과 사유로 보존합니다.

## 2026-11-15: 사용자 Windows v7 관찰 결과

사용자 TXT에서 Chrome 155.0.8059.84의 예제 게시글
`https://gall.dcinside.com/board/view/?id=comic_new6&no=7036949` 탐색이 HTTP 200으로
완료되고 검사 브라우저가 종료된 것을 확인했습니다. 이미지 저장과 대기열 변경은 없었습니다.

- `.write_div` 한 개에서 일반 이미지 4개를 로딩·decode했고 `.written_dccon` 이미지 1개를 제외했습니다.
- `.appending_file`에 공개 첨부 목록 4개와 완전한 표시 파일명이 있었습니다.
- `.view_head`는 없고 `.gallview_head`가 한 개였습니다. 그 안의 제목·작성자·날짜 요소도 각각
  한 개였으므로 이전 선택자가 메타데이터 누락 원인입니다. 선택자를 수정했습니다.
- 본문 `https://dcimg3.dcinside.co.kr/viewimage.php`와 첨부
  `https://image.dcinside.com/download.php`의 `no` 값 해시가 네 경우 모두 유일하게 일치했습니다.
  개수나 순서가 아닌 동일 식별자에 근거해 첨부 이름을 대응할 수 있습니다.
- `data-fileno`를 `f_no`나 `no`와 같다고 가정하지 않습니다. 새 조회에서도 안정적인지는 별도 관찰이 필요합니다.

이 관측은 일반 갤러리 `comic_new6`의 예제 게시글 하나에 대한 것입니다. 다른 갤러리·호스트·
엔드포인트까지 검증된 것으로 확대하지 않습니다. 식별자 원문·첨부 URL 토큰·사용자 로컬 경로와
원본 결과 TXT는 저장소에 게시하지 않습니다. 헤더 값 추출과 새 대응 결과 확인 전에는 실사이트
관찰 결과의 저장 대기열 등록을 계속 차단합니다.
