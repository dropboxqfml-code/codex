# Chrome 단일 게시글 네이티브 저장 작업자

사용자 실행 절차는 ZIP 안의 `WINDOWS_TEST_GUIDE.txt`에만 정리합니다.
`RUN_POST_SAVE_TEST.cmd`는 검증한 공개 예제 게시글 한 개를 전용 Chrome으로 열고,
사용자가 게시글·이미지 수·저장 위치를 확인해 `저장 시작`을 누른 뒤 저장합니다.
개인 프로필에 연결하지 않으며 검색·정기 감시나 다른 게시글 저장을 시작하지 않습니다.

## 완료를 확정하는 순서

1. Windows 세션 공통 mutex와 미해결 상태를 확인하고, 같은 세션 전용 DB/출력 루트를 사용합니다.
   이전 미해결 브라우저가 있으면 작업 루트를 바꿔도 새 네이티브 저장을 차단합니다.
2. 작업자가 모두 멈춘 상태에서 확정 저널만 로컬 복구합니다. 불확실한 중단 작업은 보류합니다.
3. 게시글 관찰 결과와 작업을 원자적으로 저장하고, 사용자 시작 후 이미지 집합을 재검사합니다.
   이번 게시글의 작업 ID로만 선점을 제한하며 선점 시 불변 관찰 결과를 고정합니다.
4. 제목·작성자·날짜·공개 IP와 정확한 `currentSrc`, 본문 소속·자연 크기를 재검사합니다.
   확인한 이미지 핸들 하나를 유지하므로 DOM 교체 시 다른 이미지로 재지정하지 않습니다.
5. 실제 우클릭과 네이티브 메뉴·저장 창을 조작합니다. 매 이미지마다 새로운
   `_staging/<작업ID>/<시도ID>/`를 사용하며 기존 파일을 저장 대상으로 사용하지 않습니다.
   제안명에 확장자가 없으면 선택한 파일 형식의 명시적 필터 또는 Windows의 읽기 전용
   확장자→ProgID→형식 설명 연결로 한 가지 이미지 형식임을 확인합니다.
   언어별 문자열을 추측하거나 여러 형식을 가리키는 이름을 허용하지 않습니다.
6. 첫 저장 전에 소유한 Chrome에 백그라운드 `chrome://downloads/` 탭을 열어 읽기만 합니다.
   원래 페이지·창 제목·전경·문서 포커스가 유지돼야 합니다. 정확한 저장 경로와 전체 원본 URL이
   일치하는 유일한 행의 숫자 상태 `2`와 위험/삭제 플래그를 검사합니다.
   다른 상태·모호한 행·알 수 없는 모델은 성공으로 간주하지 않습니다.
7. 쓰기 종료 근거를 확보한 뒤 배타적 파일 읽기와 SHA-256, Pillow verify/reopen/load,
   전체 프레임과 선택 이미지의 자연 크기를 확인합니다. 크기 안정화만으로 완료 처리하지 않습니다.
8. 불변 관찰 ID·검증 결과·완료 근거·목표 경로를 `prepared` 저널로 커밋합니다.
   같은 볼륨 안에서 덮어쓰기 없는 최종 발행 후 DB를 완료 처리하고,
   소유한 `metadata.json`을 원자적으로 갱신해 저널을 `finalized`로 확정합니다.

최종 확장자는 저장 창 제안명이나 URL이 아닌 검증된 실제 이미지 형식으로 정합니다.
파일 바이트는 이동 외에 변경하지 않습니다. 원본 첨부명·브라우저 제안명·최종명은
각각 보존합니다. 메타데이터에는 고정한 게시글 관찰과 검증·재시도 이력을 함께 기록합니다.

## 중단과 복구

브라우저 쓰기가 불확실하면 전용 브라우저·세션 공통 미해결 표시·staging을 유지합니다.
작업은 `paused_ui` 또는 `paused_local`로 보존하며 자동 재저장하지 않습니다.
완료가 입증된 파일의 로컬 확정 실패는 브라우저를 닫을 수 있지만 파일과 저널은 유지합니다.

`prepared` 이후 중단은 staging/최종 파일과 기록한 해시를 대조해 로컬에서만 복구합니다.
DB 완료 뒤 메타데이터만 미완료이면 메타데이터를 다시 생성합니다.
알 수 없는 파일·덮어쓰기 충돌·해시 불일치·소유권이 다른 메타데이터는 그대로 보존하고 보류합니다.
이미 `finalized`인 파일의 나중 외부 변경을 검사하는 상시 무결성 감시 기능은 아직 없습니다.

`RETRY_POST_SAVE_TEST.cmd`는 개발자 안내 후에만 사용합니다. 이전 전용 브라우저를 사용자가
닫은 다음 세션 공통 프로세스·프로필 검사를 통과해야 미해결 표시를 해제합니다.
이 실행기는 보류된 작업의 DB 상태를 초기화하지 않습니다. 확정 근거가 없는 작업은
새로 네이티브 저장하지 않고 사용자 검토 대상으로 남습니다.

성공은 종료 코드 0과 `status: post_completed`입니다. 결과 TXT에는 단계·오류 유형·저장 수·
파일 형식/해시·출력 위치를 남기며 원본 제목·작성자·첨부명·전체 이미지 URL은 공유하지 않습니다.
상세 보고서·DB·메타데이터는 사용자 PC에 보존하며 공개 저장소에 올리지 않습니다.

## 검증 경계

Chrome의 영어·한국어 기본 저장 시험은 실제 Windows CI에서 생산 완료 판독기로 확인했습니다.
[Windows CI #26](https://github.com/dropboxqfml-code/codex/actions/runs/43678523305)에서
영어·한국어 Chrome 각각 PNG·JPEG·애니메이션 GIF의 연속 저장·확정과 재실행 중복 방지를
확인했습니다. 확장자 없는 실제 저장 창 제안명 여섯 건도 현재 PC의 형식 연결 근거로 처리했습니다.
fixture의 원본 해시는 시험 최종 검증에만 사용하고 생산 저장 완료의 입력으로 사용하지 않습니다.
Edge의 기본 우클릭 저장은 성공했지만 통합 완료 판독은 아직 검증하지 않아 이 작업자에서는 거부합니다.
실제 게시글 이미지 저장의 사용자 인수 결과와 정기 감시는 별도 단계입니다.
