# Windows에서 이미지 1장 네이티브 저장 검증

Windows 사용자용 짧은 안내는 [WINDOWS_TEST_GUIDE.txt](../WINDOWS_TEST_GUIDE.txt)입니다.
최초 시험은 `RUN_WINDOWS_TEST.cmd`, 기존 시험 뒤 명시적 재시험은 `RETRY_WINDOWS_TEST.cmd`를
사용합니다. 재시험은 이전 시험 브라우저를 닫은 뒤 실행하며, 종료를 확인할 수 없으면 중단합니다.
새 시험 페이지의 `시험 시작` 버튼을 누른 뒤에만 자동 조작합니다. 아래 명령은 개발자 수동 실행용입니다.

이 명령은 개발 중인 Windows 어댑터의 수동 인수 시험용입니다. 별도 Windows CI에서
실제 브라우저 메뉴와 네이티브 저장 창을 검사합니다. [실행 결과와 환경](validation.md)은
사용자 PC의 인수 시험 결과와 구분합니다.
실사이트 수집·정기 감시·프로덕션 저장 큐를 실행하는 명령이 아닙니다.

## 준비와 실행

Windows 10/11의 로그인된 대화형 세션, 설치된 Edge 또는 Chrome, Python 3.12와 uv가
필요합니다. 저장소의 `image-monitor` 디렉터리에서 PowerShell로 실행합니다.

```powershell
uv sync --locked --extra windows
uv run --locked --extra windows image-monitor native-probe --work-root C:/IMProbe --browser edge
```

Chrome은 `--browser chrome`을 사용합니다. 자동화용 Chromium 설치 명령은 필요하지
않습니다. 현재 코드는 표준 설치 위치의 Edge/Chrome을 찾으며, 조직 정책에 의해
디버깅 연결이 차단된 경우 실패합니다. 해당 정책을 변경하거나 우회하지 않습니다.

열리는 **전용 시험 브라우저를 전경에 유지**하세요. 다른 앱으로 포커스를 옮기거나
화면을 잠그면 이후 UI 입력을 중단합니다. 프로그램에서 포커스나 잠금 상태를 강제로
복구하지 않습니다. Ctrl+C는 후속 자동화를 중단합니다. 이미 진행 중인 브라우저
저장 자체를 취소한다고 보장하지 않으므로 중단 뒤 파일과 브라우저를 확인하세요.

## 실행 내용

1. Windows 세션 전역 이름의 mutex를 얻고 사용자 LocalAppData 아래의 세션 공통
   미해결 상태를 확인합니다. 브라우저를 시작하기 전에 이 상태를 디스크에 기록하므로
   강제 종료되거나 다른 작업 루트로 실행해도 이전 저장 확인을 건너뛰지 않습니다.
2. `C:/IMProbe/<고유ID>/`에 시험용 PNG/HTML과 전용 브라우저 프로필을 생성합니다.
   개인 브라우저 프로필에는 연결하지 않습니다. 프로필마다 새 로컬 CDP 포트를 열며,
   Playwright는 새 브라우저 컨텍스트나 다운로드 가로채기를 설정하지 않고 연결합니다.
3. 로컬 HTML의 본문 시험 이미지 하나만 찾아 스크롤·decode·자연 크기를 확인하고
   Playwright로 실제 우클릭합니다. 이 조작 전에는 사용자가 페이지의 `시험 시작` 버튼을
   누르고 대상 창이 전경이라는 조건을 최대 5분 동안 입력 없이 기다립니다.
   창을 강제로 앞으로 가져오지 않으며, 실제 조작이 시작된 뒤 포커스를 잃으면 즉시 중단합니다.
4. 고유 시험 페이지 제목으로 대상 브라우저 HWND를 고정하고, 해당 창까지 연결되는
   부모/소유 창 관계를 확인한 UIA 요소에서 `Save image as`, `이미지를 다른 이름으로 저장`,
   Edge 한국어 `다른 이름으로 사진 저장(V)` 중 하나를 유일하게 식별해 Invoke합니다.
   가상 요소의 부모 경로는 신뢰한 HWND에서 새로 얻은 UIA 루트와 동일해야 합니다.
   메뉴 순서·고정 좌표·키보드 단축키로 대체하지 않습니다.
5. 전경의 실제 HWND가 대상 창의 소유 관계 안에 있는 `#32770` 저장 창인지 확인합니다.
   UIA 최상위 창 열거에 빠질 수 있으므로 확인한 HWND로 직접 연결합니다. 파일명 Edit(`1001`)와
   저장 Button(`1`)을 확인하고 기본 이름을 기록한 뒤 `_staging/native-image.png` 경로를 입력합니다.
   파일명은 `FileNameControlHost` ComboBox의 직접 자식 Edit로 한정합니다. 이미 전경인
   저장 창 안에서 필요한 경우에만 해당 Edit를 포커스하고 `EM_SETSEL`·`EM_REPLACESEL`로 경로를 입력해
   Windows 편집 알림을 전달합니다. 각 메시지 전에 실제 HWND·PID·부모·소유 관계를 확인하며
   메시지당 2초 제한이 있습니다. 정확한 경로를 다시 읽은 뒤 저장 버튼을 Invoke합니다.
   저장 버튼으로 포커스를 옮기거나 창 복원·전경 활성화·전역 키 입력을 수행하지 않습니다.
6. 네이티브 HWND의 종료/숨김 확인에 더해 Windows 배타적 파일 열기, **시험 원본과 SHA-256 동일성**,
   Pillow 검증/디코딩을 확인합니다. 크기 안정화 하나로 성공 처리하지 않습니다.
7. 성공 시 전용 브라우저를 닫고 `report.json`을 남깁니다. 실제 게시글의 최종
   이동/DB 커밋/metadata.json 생성은 이 시험의 범위에 포함하지 않습니다.

PNG의 알려진 해시를 완료·대응 확인 신호로 사용할 수 있는 것은 **이 합성 시험에
한정**됩니다. 실제 게시글에서는 원본을 따로 받지 않으며, 이 방식을 그대로 일반
다운로드 완료 판정으로 사용하지 않습니다. 브라우저 자체의 백그라운드 연결까지
완전 차단한다고 주장하지 않습니다. 시험 페이지와 이미지는 로컬 파일입니다.

## 결과와 실패 처리

정상 결과는 종료 코드 0, `status: probe_passed`, 검증된 형식/크기/SHA-256입니다.
보고서에는 Windows/브라우저 버전, 지역 형식 로캘(`regional_locale`), 사용자의 선호
Windows UI 언어(`windows_ui_language`), 시스템 DPI, 모니터 수, 원격 세션 여부와
실제 저장 창 제안 이름이 기록됩니다. 브라우저 UI 언어는 별도로 검증하지 않았으므로
`browser_ui_language`는 null입니다. 실제 인수 시험에서 확인해 기록하세요.
시스템 DPI 값은 Python 프로세스의 DPI 인식 설정에 따라
가상화될 수 있어 모니터별 배율의 증거로 사용하지 않습니다.

실패 시 전용 브라우저를 자동 조작하거나 반복 저장하지 않고 `manual_review` 또는
`cancelled_manual_review` 보고서를 남깁니다. 외부 예외의 전체 텍스트는 저장하지
않습니다. 기본 이름을 읽기 전에 실패한 경우 그 값은 null입니다.
결과 TXT에는 `Probe summary`로 중단 단계·오류 유형·브라우저 버전·환경 정보와 실패 당시
전경 HWND/PID/클래스 및 대상 창 소속 여부를 함께 기록합니다. 다른 창의 제목이나 내용을
읽지 않으며, 진단 실패가 원래 오류를 덮지 않도록 처리합니다.

미해결 상태는 사용자 LocalAppData의
`ImageMonitor/native-save-session-<Windows세션ID>.json`에 보존됩니다.
보고서의 `shared_pending_state`가 실제 경로이며, `run_directory`로 이전 시험을 찾을 수
있습니다. 같은 세션에서는 `--work-root`를 바꿔도 새 저장을 차단합니다.
보고서와 `_staging`을 확인하고 **시험에서 생성한 브라우저를 직접 닫은 뒤** 실행하세요.

```powershell
uv run --locked --extra windows image-monitor native-recover --confirm-browser-closed
```

이 명령은 같은 전역 mutex 안에서 등록된 브라우저 PID/생성 시각 및 전용 프로필의
사용 여부를 확인합니다. 브라우저가 살아 있거나 상태·프로세스를 확인할 수 없으면
차단을 유지합니다. 브라우저 시작 직후 프로세스 정보 기록 전에 종료된 경우도
프로필 사용 검사를 수행합니다. 복구는 상태 표시만 지우며 결과 파일과 프로필을
삭제하지 않습니다. 상태 파일을 직접 지우거나 LocalAppData를 변경해 우회하지 마세요.
상태 파일이 손상된 경우에는 자동 초기화하지 않고 수동 조사를 요구합니다.

이전 버전의 작업 루트에 `native-probe.pending`이 남았다면 해당 브라우저와 파일을
먼저 수동 확인하고 브라우저 종료 후 그 이전 표시 파일만 제거하세요. 새 버전은
세션 공통 상태를 사용하며, 이전 버전이 남긴 다른 작업 루트까지 자동 검색하지 않습니다.

확인해야 할 조합은 정상 저장, 한글 파일 경로, 포커스 변경, 화면 잠금, Ctrl+C,
같은 세션 중복 실행, 다중 모니터/배율, RDP, 메뉴 미식별 및 저장 창 미식별입니다.
사용자 환경의 인수 시험과 장애 복구 검증을 마친 뒤 자동 감시 저장을 연결합니다.
