# 본문 분석과 관찰 결과 대기열

`post-demo --db <새 DB 경로>`는 합성 게시글을 분석하고 SQLite에 저장한 뒤 새 연결로
다시 읽습니다. 브라우저나 이미지 저장 작업자를 시작하지 않습니다.
본문 순서와 첨부 순서가 다른 경우, 같은 이미지 반복, 본문에 없는 첨부 파일,
대응 근거가 없는 이미지를 포함합니다. 기존 DB는 덮어쓰지 않습니다.

## 본문과 파일명 처리

본문은 유일한 `.write_div`에서만 읽습니다. 없는 본문이나 중복된 본문을 페이지 전체 이미지
수집으로 대체하지 않습니다. 댓글·광고·프로필·추천 영역과 동영상의 이미지, 본문 디시콘은
제외 사유를 보존합니다. 크기만으로 이미지를 제외하지 않습니다.
스크롤 후 `complete`, 자연 크기와 `decode()`를 확인하며 로딩 실패는 별도 미해결 이미지로
남깁니다. 미해결 이미지가 있으면 저장 대기열 등록을 허용하지 않습니다.
관찰 마지막에도 본문 이미지 노드·순서·개수가 처음과 같은지 확인합니다.

제목·작성자·작성 시각은 유일한 `.gallview_head`에서 읽습니다. IP는 화면에 보이는 `.ip`의
부분 표시값만 사용하고 `data-ip` 속성으로 대체하거나 숨겨진 나머지를 추정하지 않습니다.

첨부 이름은 명시적인 DOM 참조나 검증된 공통 식별자가 유일하게 대응할 때만 확정합니다.
순서·개수·동일한 파일명은 대응 근거가 아닙니다. 중복·충돌·잘린 이름을 구분하며,
확정하지 못한 이름은 null로 기록합니다. 이름 대응 실패만으로 정상 본문 이미지를 버리지 않습니다.
`original_filename_source`는 대응이 확정된 경우에만 `attachment_list_dom`입니다.
실제 저장 창의 제안 이름과 최종 저장명은 분석 단계에서 null로 남깁니다.

## 실사이트에서 확인된 식별자와 작업 키

사용자 v7·v8 관찰에서 일반 갤러리 `comic_new6`의 예제 글 `7036949`를 확인했습니다.
본문 일반 이미지 4개가 로딩됐고 공개 첨부 목록 4개의 이름과 모두 대응됐으며,
본문 디시콘 1개를 제외하고 미해결 로딩은 없었습니다. 수정한 `.gallview_head` 선택자로
제목·작성자·공개 부분 IP·작성 시각도 읽혔습니다. 개인 식별 표시값과 원문 URL 토큰은
이 문서나 저장소에 넣지 않습니다. 상세 근거와 검증 경계는 [관측 기록](live-dom-observations.md)에 있습니다.

관찰된 대응 규칙은 다음 두 HTTPS 엔드포인트의 공통 `no`입니다.

- 본문: `dcimg3.dcinside.co.kr/viewimage.php`, 쿼리 키는 `id`, `no`.
- 첨부: `image.dcinside.com/download.php`, 쿼리 키는 `no`, `f_no`.

엔드포인트와 전체 쿼리 키 구성을 검사하고, 중복·누락·빈 값·잘못된 인코딩을 거부합니다.
본문과 첨부의 `no`만 네임스페이스가 있는 해시로 대응합니다. `id`, `f_no`, `data-fileno`를
파일 동일성으로 비교하거나 첨부 링크에 별도 요청을 보내지 않습니다.
네임스페이스 해시는 식별자의 노출을 줄이는 표기이며 이미지 바이트의 SHA-256이 아닙니다.

실사이트 검증 상태가 허용된 이미지에는 이 리소스 식별자를 작업 키로 사용합니다.
같은 `no`의 URL 변형은 하나의 작업으로 묶고 모든 본문 출현 순서·표시 URL·대응 근거를 보존합니다.
v7과 v8의 관찰에서도 네 이미지의 표시 URL 해시와 `no` 식별자 해시가 유지됐습니다.
확인되지 않은 외부 리소스와 합성 fixture는 정확한 표시 URL 해시를 계속 사용합니다.
그 경우 URL이 바뀌면 새 작업이 될 수 있다는 경고를 남기며 식별자를 만들어내지 않습니다.

## 실사이트 등록 허용 범위

현재 `site_verified`와 `queue_eligible: true`를 허용하는 실사이트 대상은
`normal / comic_new6 / 7036949` 한 개입니다. 본문과 헤더가 각각 한 개, 헤더의 제목·작성자·날짜도
각각 한 개여야 합니다. 제목·작성자가 비어 있지 않고 작성 시각이 유효하며 미해결 이미지도 없어야 합니다.
파서의 등록 가능 여부는 관찰 결과에서 계산하며 `site_verified`는 호출자가 전달하는 검증 옵션이 아닙니다.

다른 게시글·갤러리는 `unverified`로 유지합니다. 같은 엔드포인트의 첨부 이름 후보가 대응되더라도
그 사실만으로 게시글 레이아웃 검증이나 저장 대기열 등록을 허용하지 않습니다.
일반·마이너·미니 URL 형식을 검사하는 것과 각 종류의 실제 DOM을 검증하는 것은 구분합니다.

리소스 작업 키가 같아도 저장할 화면 요소는 다시 검증합니다. 네이티브 선택 단계는 본문 소속과
준비한 정확한 `currentSrc`, 예상 헤더·게시글 정체성을 유지해야 합니다. 관찰에서 확인된
식별자가 있다는 이유로 다른 이미지나 다른 위치의 요소를 선택하지 않습니다.

사용자 v10에서는 이 예제 한 글의 기존 WEBP 한 장을 보존하고 나머지 세 장을 저장·검증·확정해
총 네 장의 완료와 입력 전 재개를 확인했습니다. 별도 후보 저장은 전역 `site_verified`를
확대하지 않고 완료된 상세 관찰에 묶인 `CandidateSavePermit`과 현재 본문 재검사를 사용합니다.
후보는 기준점 이후 작성 시각·로딩된 본문 이미지 1~2개·미해결 이미지 0개 등 허가 조건을
충족해야 하며, 일반 `enqueue_snapshot`과 별도 경로로 이미지 작업을 만듭니다.

사용자 v15에서는 이 경로로 고정 후보의 JPEG·PNG 두 장을 저장·검증·확정했으나 마지막
브라우저 종료 확인에 실패했습니다. v16에서 기존 파일 재검증·보존과 이미 종료된 브라우저 확인·
미해결 표시 해제를 마쳤습니다. v19에서는 `목록 감시`의 완료 상세 관찰 한 개에 묶인 JPEG 한 장의
저장·검증·확정과 정상 종료·보류 해제를 확인했습니다. v21에서는 기존 완료 한 건을 재검증해
배치 원장에 등록·건너뛰고 새 후보 한 건의 JPEG 한 장을 저장·검증·확정해 정상 종료했습니다.
v21은 새 목록·상세를 수집하지 않으며 새 네이티브 시도는 실행당 최대 두 번이고 게시글마다
사용자의 `저장 시작`과 전경 유지가 필요합니다. 이 한정 인수는 다른 글·갤러리의 본문 프로필이나
전체 후보의 연속 자동 저장을 검증한 결과가 아닙니다. 자세한 근거는 [검증 기록](validation.md)에 있습니다.

## SQLite 연결

`enqueue_snapshot`은 등록 가능한 관찰 결과만 `persist_post_snapshot`에 전달합니다.
합성 검증 결과는 명시적인 합성 모드가 필요하며, 미검증 실사이트 결과는 등록하지 않습니다.
관찰 결과·게시글·감시 범위·이미지 작업·작업 대응 관계를 한 트랜잭션으로 저장합니다.
감시 범위는 호출자가 제공한 값이며 검색 목록에서 해당 글을 찾았다는 증거가 아닙니다.
목록 체크포인트를 갱신하지 않습니다.

기존 작업 ID·파일 슬롯·최초 날짜 경로와 재시도 상태는 유지합니다. 이전 관찰 결과는 수정하지
않으며 본문 순서가 바뀐 새 관찰 결과와 별도로 조회할 수 있습니다. 활성 작업의 URL은 바꾸지 않습니다.
대기열 등록 API와 `post-demo` 자체는 실제 저장이나 정기 스케줄러를 시작하지 않습니다.

DB v2에서 관찰 결과와 작업 대응 테이블, v3에서 파일 확정 저널, v4에서 검색 목록 관찰·후보를
추가했으며 현재 v5는 후보 상세 시도 기록도 보존합니다. 알려진 v1/v2/v3/v4 스키마가 정확히
일치할 때만 단일 트랜잭션으로 추가 마이그레이션합니다. 알 수 없는 객체가 있는 DB는 수정하지
않고 거부하며 읽기 전용 조회는 기존 버전을 마이그레이션하지 않습니다. 별도의 배치 저장 원장은
스키마 1이며 이 DB v5와 구분합니다. 선점 시 고정한 관찰 ID와 파일 확정·복구 절차는
[대기열 안내](queue.md)를 참고하세요.

## 읽기 전용 사이트 검사

클라우드 탐색은 연결 단계에서 실패했습니다. 이후 실사이트 근거는 사용자 Windows의
v7·v8 읽기 전용 관찰 결과에서 확보했습니다.

`site-inspect`는 설치된 브라우저의 별도 임시 컨텍스트로 예제 게시글 한 개를 읽습니다.
화면을 띄우지 않고 다운로드를 거부하며, 첨부 링크 클릭·추가 첨부 요청·응답 바이트 추출·
네이티브 저장을 실행하지 않습니다. HTTP 차단이나 오류에서 우회·반복 요청을 하지 않습니다.
본문·첨부 구조와 후보·제외·로딩 오류·메타데이터, 계산된 검증 상태를 검사 보고서에 남깁니다.
공유 TXT는 URL의 민감한 값과 로컬 보고서 경로를 정리하며 개인 프로필·쿠키·인증 헤더는 수집하지 않습니다.

사용자 작업은 ZIP의 `image-monitor` 폴더 안에 하나만 넣은 TXT 안내에 정리합니다.
`RUN_SITE_INSPECTION.cmd`는 결과 TXT를 자동으로 엽니다. 이 읽기 전용 검사의 성공은
관찰 결과가 생성됐다는 뜻이며 이미지 저장 성공이나 정기 감시 실행을 의미하지 않습니다.
